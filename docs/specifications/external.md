# novnow 仕様書 — 配布形態（外部提供物）

## 20. 配布形態

本書は、novnow を利用者の手元へ届ける**提供物の形**を定める。何ができるか（機能）は §1〜§19 が定め、本書は「どの形で、どの選択肢に分けて、どう名付け、どこへ置くか」だけを定める。

### 20.1 配布形態の一覧と共通原則

#### 20.1.1 一覧

配布形態は次の 5 種とする（MUST）。形態をこれ以上に増やさない。

| 形態 | 提供するもの | 選択肢の数 | 主な利用者 |
|---|---|---|---|
| ブラウザ版 | ブラウザで開くアプリ一式（PWA） | 1 | インストールしたくない人 |
| デスクトップ版 | 実行ファイル（OS 別・画面の有無別） | 10 | 手元のフォルダで原稿を管理する人 |
| Python ライブラリ版 | Python のホイール | 5 | Python から操作を自動化する人 |
| VSCode 拡張版 | エディタ拡張（設定と LSP 接続のみ） | 1 | VSCode で原稿を書く人 |
| GitHub Actions 版 | 複合アクション | 1 | 点検や書き出しを自動化する人 |

- ブラウザ版は公開済みであり、本書は再定義しない（§20.1.3 だけを適用する）。
- デスクトップ版の 10 通りは、画面の有無 2 通り × 対象環境 5 通りである（§20.2）。つまるところ、5 つの対象環境のそれぞれに「窓あり」と「窓なし」があるだけである。
- Python ライブラリ版の 5 通りは、対象環境 5 通りだけである（§20.3）。
- VSCode 拡張版と GitHub Actions 版は選択肢を持たない（§20.4・§20.5）。

#### 20.1.2 共通原則

- **版の一致（MUST）**: 5 形態は同じ版番号を名乗る。ある版の成果物は、すべて同一のソースの状態から作る。形態ごとに版を進めない。
- **実行時に配布元へ接続しない（MUST）**: novnow は更新の確認・利用統計の送信・遠隔の設定取得を行わない。通信が起きるのは、利用者が明示した取得（VSCode 拡張版のバイナリ取得、GitHub Actions 版のバイナリ取得）と、利用者が指定した外部 LLM・URL 取得だけである。
- **照合値の公開（MUST）**: 実行ファイル・ホイール・拡張機能の各成果物について、SHA-256 の照合値を同じ版の公開物へ置く。取得側は照合してから使う。
- **書き込み先を増やさない（MUST）**: 配布物は利用者が展開先を決める。novnow 自身は配布物の配置先・設定・OS の関連付けを書き換えない。したがって**インストーラを提供しない**（§20.2.5）。規則 10（プロジェクト外に書かない）は、すべての形態で等しく効く。
- **自動更新をしない（MUST）**: 新しい版は利用者が取得する。アプリは自分自身を置き換えない。
- **署名**: 実行ファイルと拡張機能には、可能な範囲で配布元の署名を付ける。署名が無い成果物を配る場合は、OS の警告の避け方を利用者向けの手引きに書く（MUST）。

#### 20.1.3 ブラウザ版

- 公開 URL から開くだけで使える（MUST）。インストールを要求しない。
- PWA としてホーム画面へ追加でき、初回の読み込み後はオフラインでも起動できる。
- 配布物はサイトの公開物そのものであり、版番号は画面の情報に表示する。

### 20.2 デスクトップ版

#### 20.2.1 選択肢

「画面の有無」と「対象環境」の 2 つの軸の組み合わせで **10 通り**（MUST）。軸を増やさない。

| 軸 | 値 | 意味 |
|---|---|---|
| 画面 | GUI あり | 窓を出す。CLI としても使える |
| 画面 | GUI なし | 窓を出さない。CLI・LSP・MCP 専用 |
| 対象環境 | 5 通り | 下表のとおり |

| 対象環境 | 実行ファイルの形式 | アーカイブ |
|---|---|---|
| Linux x86_64 | ELF | `.tar.gz` |
| Linux aarch64 | ELF | `.tar.gz` |
| macOS x86_64 | Mach-O（GUI あり版は `.app` を含む） | `.tar.gz` |
| macOS arm64 | Mach-O（GUI あり版は `.app` を含む） | `.tar.gz` |
| Windows x86_64 | PE | `.zip` |

#### 20.2.2 配布物の名前

```
novnow-<版>-<対象環境>-<gui|nogui><拡張子>
```

- 例: `novnow-0.1.0-x86_64-unknown-linux-gnu-gui.tar.gz`
- 対象環境の表記は Rust のターゲット三重項と同じ綴りとする（MUST）。`x86_64-unknown-linux-gnu` / `aarch64-unknown-linux-gnu` / `x86_64-apple-darwin` / `aarch64-apple-darwin` / `x86_64-pc-windows-msvc`。
- アーカイブには、実行ファイル（Windows は `novnow.exe`）・`LICENSE`・起動方法を書いた短いテキストを含める（MUST）。GUI あり版の macOS は `.app` バンドルを含める。
- 同じ版の 10 個の成果物と、その照合値をまとめた 1 個のファイルを公開する（MUST）。

#### 20.2.3 同梱物

同梱物とは、同梱フォント・既定プロンプト・サンプル作品・ライセンス表示を指す。

- 同梱物は**すべて実行ファイルに埋め込む**（MUST）。配布物の中に同梱物のファイルを別に置かない。同梱物が変われば実行ファイルも変わる（版と同梱物が 1 対 1 で対応する）。
- 展開先に置くのは実行ファイル 1 個（macOS の GUI あり版は `.app` 1 個）とする（MUST）。同梱物のフォルダ・設定ファイル・データファイルを要求しない。
- 同梱物を**プロジェクトの中へ書き写さない**（MUST）。同梱物はアプリの資源であり、作品のファイルではない。
- **配布物の作りを分ける軸を置かない**（MUST）。同梱物を外に置く版（いわゆるポータブル配布・共有ライブラリ版）を提供しない。
- 同じ機械で何個でも起動できる（MUST）。2 つ目を止める仕組み・ロックファイルを設けない。
- プロジェクトの外へ書くのは、パス履歴のファイル 1 個だけである（§13.1・§13.2）。配布物の作りによって、この範囲を広げない（MUST）。

ここまでの MUST は、**同梱物を外に置く版（ポータブル配布）**と、**同時に起動できる数を 1 つに限る版**を、どちらも選択肢にしないという意味である。novnow は履歴ファイル以外をプロジェクトの外に置かないので、どちらの版を作っても利用者から見た違いが小さく、選ぶ手間と検証の重複だけを増やすためである。

#### 20.2.4 GUI あり / GUI なし

- **GUI なし**の成果物は、引数なしで起動しても窓を出さない。`--gui` は使い方の誤りとして終了コード 2 を返す（§14.2.5 と同じ扱い）。
- **GUI なし**でも、`new` / `check` / `export` / `import` / `migrate` / `mcp` / `lsp` / `api` と `--version` / `--help` は使える（MUST）。
- **GUI あり**の成果物は、窓を出す。同時に CLI としても使える（§14.3 の判定に従う）。
- Windows の GUI あり版は、窓付きの実行形式で作り、新しいコンソールを開かない（MUST）。
- 2 つの成果物は、同じ版・同じ対象環境であれば保存形式と診断結果が完全に一致する（MUST）。画面の有無で機能差を設けない。

#### 20.2.5 取得と起動

- 利用者はアーカイブを展開し、実行ファイルを直接起動する。**インストーラは提供しない**（MUST）。レジストリ・アプリケーションフォルダ・PATH を書き換えない。
- どの成果物を選ぶかは、画面の有無 1 つの質問と、パソコンの種類で決まるように案内する（MUST。既定の推奨は GUI あり）。
- 展開先のフォルダを削除すれば元に戻る（MUST）。ほかに消すものを要求しない（パス履歴を消してよいと案内する）。
- macOS の GUI あり版は `.app` を開いて起動でき、`open -a novnow --args <ディレクトリ>` でもプロジェクトを開ける（MUST）。
- Linux の GUI あり版は、デスクトップ環境のファイルマネージャから実行ファイルへディレクトリを渡して開ける（MUST）。
- アンインストールは、展開したフォルダを削除することである。加えて、パス履歴のファイル（§13.2）を削除してよい。

### 20.3 Python ライブラリ版

#### 20.3.1 成果物

- ビルド済みホイールを 5 通り提供する（MUST）。対象環境はデスクトップ版と同じ 5 通り。
- ホイールの名前は Python の包装規約（PEP 427）に従う。実装のタグは `cp39-abi3` とし、1 つのホイールで CPython 3.9 以降のすべての版を賄う（MUST）。
- ソース配布を提供しない（MUST）。利用者に Rust のツールチェーンを要求しない。
- パッケージ名と import 名は `novnow` とする（MUST）。版は本体と同じで、`novnow.__version__` で読める。

#### 20.3.2 できること

- Python プロセスの中で、GUI と同じ正規操作（§19.7）を呼べる。セッションを複数持てる。
- GUI は持たない。窓を開く操作は提供しない。
- GUI を持たないので、画面の部品を要求しない。同梱物は wheel の中に含める。
- ファイルへの書き込みは、規則 10 と §13 に従う。

#### 20.3.3 取得

- 公開先は Python のパッケージレジストリ（PyPI）とする（MUST）。`pip install novnow` で導入できる。
- 版の指定が無い場合は最新の安定版を導入する。利用者は `novnow==<版>` で固定できる（MUST）。
- ネットワークに出られない環境のために、ホイールを直接指定して導入できる（MUST）。

### 20.4 VSCode 拡張版

#### 20.4.1 原則

- 拡張機能の配布物に novnow の実行ファイルを含めない（MUST）。含めるのはエディタ向けのメタデータと接続のためのコードだけである。
- 拡張機能は novnow の機能を自前で実装しない。点検・書き出し・診断は、必ず novnow の LSP または CLI を呼んで得る（MUST）。
- 拡張機能がプロジェクトのファイルを直接書き換えない（MUST）。書き込みは novnow の関門を通す。
- 拡張機能の版は本体と同じ番号にする（MUST）。

#### 20.4.2 実行ファイルの探索

次の順で探し、最初に見つかったものを使う（MUST。順序を変えない）。

1. 利用者の設定 `novnow.executablePath` が指すパス
2. `PATH` 上の `novnow`
3. 拡張機能が以前に取得して保存した実行ファイル
4. 取得（§20.4.3）

#### 20.4.3 自動取得

- 1〜3 で見つからない場合、拡張機能は対象環境に合う**GUI なし**の実行ファイルを自動で取得する（MUST）。版は拡張機能と同じ版とする。
- 取得先は同じ版の公式の公開物だけとし、SHA-256 の照合値と一致しなければ破棄する（MUST）。
- 保存先は拡張機能の保存領域とする（MUST）。プロジェクトの中や OS の一時領域に置かない。
- 取得の進み具合と結果を利用者に通知する（MUST）。失敗した場合は、手動での導入先を案内する。
- 自動取得は設定 `novnow.autoDownload` で無効にできる（MUST）。無効のときは取得せず、案内だけを出す。
- 取得に失敗しても、拡張機能は起動を続ける（MUST）。ただし novnow に依存する機能は無効化し、その旨を表示する。
- 通信は VSCode のプロキシ設定に従う（MUST）。認証情報を要求しない。

#### 20.4.4 提供する機能

- novnow プロジェクトのフォルダを開くと、LSP のサーバ（§19.4）へ接続する（MUST）。
- 次の操作をコマンドとして提供する（MUST）: プロジェクトの点検、テキストの書き出し、新規プロジェクトの作成、言語サーバの再起動。
- 診断・補完・定義移動・参照検索・整形・折りたたみは、LSP が返す内容をそのまま見せる（MUST）。拡張機能が独自の診断を足さない。
- 原稿の文字コードは UTF-8 として扱い、保存時に BOM と改行を変えない（MUST）。

#### 20.4.5 配布

- 公開先は VSCode の拡張機能の市場とする（MUST）。識別子は `sonneko.novnow` とする。
- 同じ版の `.vsix` を公式の公開物へも添付する（MUST）。市場を使えない環境では、このファイルから導入できる。
- 市場からの削除は行わない。不具合は新しい版で直す（MUST）。

### 20.5 GitHub Actions 版

#### 20.5.1 形

- 複合アクションとして公開する（MUST）。Docker アクションと JavaScript アクションは使わない。
- リポジトリ直下の `action.yml` を定義とし、利用者は `uses: sonneko/novnow@v1` の形で呼ぶ。
- アクションは対象環境を自動で判定し、対応する**GUI なし**の実行ファイルを取得して実行する（MUST）。

#### 20.5.2 入力と出力

| 入力 | 既定 | 意味 |
|---|---|---|
| `path` | `.` | 対象のプロジェクトのディレクトリ |
| `command` | `check` | 実行するサブコマンド（点検・書き出しなど） |
| `args` | 空 | サブコマンドへ渡す追加の引数 |
| `version` | 空 | 使う版。空ならアクションの版と同じ版 |
| `target` | 空 | 対象環境。空なら実行環境から自動で判定する |

| 出力 | 意味 |
|---|---|
| `exit-code` | novnow の終了コード |
| `findings` | 点検で出た診断の件数（点検以外では空） |
| `export-path` | 書き出したファイルのパス（書き出し以外では空） |

- 入力を省略した場合でも、点検が通るプロジェクトでは成功する（MUST）。
- `args` は引用符の解釈をせず、空白で区切った引数として渡す（MUST）。値をそのままシェルへ渡さない。

#### 20.5.3 実行と失敗

- 取得した実行ファイルの SHA-256 を照合する（MUST）。一致しなければジョブを失敗させる。
- novnow の終了コードを、そのままジョブの成否へ伝える（MUST）。点検で E の診断が出た場合は失敗し、W と I だけなら成功する。
- 取得した実行ファイルは、版と対象環境を鍵にしてキャッシュしてよい（MUST ではない）。キャッシュを使う場合も照合は毎回行う。
- 通信は取得のときだけ行う（MUST）。リポジトリの内容を外部へ送らない。認証情報を要求しない。
- 対応する実行環境は Linux・macOS・Windows の標準のランナーとする（MUST）。§20.2.1 の 5 つの対象環境のうち、ランナーに合うものを選ぶ。

#### 20.5.4 配布

- 版に対応する固定のタグと、主要版を指す可動のタグ（`v1`）の両方を公開する（MUST）。利用者は再現性のために完全な版を指定できる。
- アクションの版は本体と同じ番号にする（MUST）。

### 20.6 公開・版・廃止

#### 20.6.1 公開の単位

- 1 つの版は、5 形態すべての成果物が揃って初めて公開完了とする（MUST）。揃うまでは、欠けている形態を「未提供」と表示する。
- 実行ファイルとホイールと拡張機能は、版ごとの公開物へまとめて置く（MUST）。成果物の一覧と SHA-256 の照合値を同じ場所へ置く。
- 公開の順序は、実行ファイル → Python → VSCode → GitHub Actions のタグとする（MUST）。前の段階が失敗したら、後の段階へ進まない。

#### 20.6.2 版番号

- 版番号はセマンティックバージョニングに従う（MUST）。`0.x` の間は、マイナー版の更新で互換性が壊れることがある。
- 試験的な版（プレリリース）は、版番号に `-rc.<番号>` などを付けて区別する（MUST）。安定版と同じ場所に混ぜない。

#### 20.6.3 廃止と取り下げ

- 公開済みの版を取り下げない（MUST）。重大な不具合は新しい版で直し、古い版の公開物は残す。
- ただし、Python のパッケージレジストリでは、壊れた版を「取り下げ（yank）」として印を付けてよい。削除はしない。
- 主要版のタグ（`v1`）は、互換性を壊す版を出すときにだけ新しい主要版へ移す（MUST）。
- 公開を止める場合は、同じ版の全形態を同時に「未提供」へ戻す（MUST）。形態ごとに残さない。
