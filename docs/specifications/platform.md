# novnow 仕様書 — ストレージと起動仕様

## 13. ストレージ

### 13.1 規則 10 — プロジェクト外に出してよい情報

> 「プロジェクトディレクトリ外に存在して良い情報は、プロジェクトディレクトリパスの履歴のみ。これは厳密に守る必要がある。」

#### 13.1.1 規範

novnow が **書き込んでよい場所は次の 2 つだけ**（MUST）。例外は下の明示エクスポートと、配布物の取得専用領域だけである。

1. 現在開いているプロジェクトルート配下
2. パス履歴ファイル **1 個**（§13.2）。Web ではその等価物（§13.3.4）

**特例 — 利用者が明示的に導入・有効化した配布物の取得専用領域**:
VSCode 拡張の保存領域と GitHub Actions の実行ファイルキャッシュに限り、取得した実行ファイル・照合値と版の検証情報・短命な展開ファイルを保存してよい。展開中のファイルは完了・失敗時に削除する。原稿・作品の設定・ログをこの例外で保存してはならない。これは配布物の導入だけの許可であり、本体の通常保存や書き出しの境界を広げない（MUST）。

**特例 — ユーザーが明示的に指定したエクスポートの書き出し先**:
ユーザーが **書き出しを明示的に指示し、そのとき書き出し先のパスを明示的に指定した** ときに限り、**指定されたそのパス** には
プロジェクトの外でも書き込んでよい。対象は次の 2 つだけ。

| 書き出し | 書き出し先の指定 | 書けるファイル |
|---|---|---|
| Zip エクスポート（§13.5。デスクトップ） | 保存ダイアログ | 名前が `.zip` か `.novnow` で終わるもの |
| テキストエクスポート（§17.2） | デスクトップの「名前を付けて保存」の保存ダイアログ、または `novnow export --out <パス>`（§14.1） | 名前が `.txt` か `.md` で終わるもの |

- 書けるのは、指定された **ファイル 1 個** への **その 1 回の書き込み** だけ。許可はそこで消える
  （パスを覚えない。履歴にも書かない。§13.1.3）。
- 一時ファイルを作らずに直接書く。親ディレクトリは作らない（ダイアログで選べるのは既存のディレクトリだけ。
  `--out` の親ディレクトリが無ければ書き込みは失敗する）。
- 名前が表の拡張子（大文字小文字は問わない）で終わらないパス（シンボリックリンクなら行き先で判定する）と、
  履歴ファイルは指定できない（E060）。Zip の書き出しに `.txt` を指定する、のように種類に合わない拡張子も同じ。
- 既定の書き出し先（`exports/…`）・自動保存・設定・ログなど、ユーザーがパスを指定しない書き込みに特例は無い。
  Web はダウンロードなので関係しない。

これ以外への書き込みは、一時ファイルであっても禁止する。具体的に禁止されるもの:

- 設定ファイル（テーマ・言語・ウィンドウサイズ・ペイン比）→ すべて `.novnow/ui.json`（プロジェクト内）
- キャッシュ（解析結果・フォントキャッシュ・サムネイル）→ `.novnow/cache/`（プロジェクト内）
- ログ・クラッシュレポート・テレメトリ → `agents/log/`（プロジェクト内）/ テレメトリは **そもそも実装しない**
- プロンプトのグローバル共有 → 禁止
- MCP サーバ設定のグローバル共有 → 禁止（`agents/mcp.json` のみ）
- 最近使ったファイル・検索履歴・undo 履歴 → プロセス内メモリのみ（終了で消える）
- OS の一時ディレクトリ（`/tmp` 等）への中間ファイル → 禁止（原子的保存の一時ファイルも **プロジェクト内の同一ディレクトリ** に作る、§8.3）

#### 13.1.2 強制の仕組み（MUST）

- すべてのファイル書き込みは単一の境界検査を通過しなければならない。
- §13.1.1 の特例（ユーザーが明示したエクスポート先）は、保存ダイアログまたは `novnow export --out` で明示されたパスとエクスポート種別（Zip / テキスト）の組に対して 1 回限り有効とし、通常の保存経路からは利用できない（MUST）。
- 判定は **シンボリックリンク解決後の絶対パス** で行い、`..` を含む脱出を拒否する。
- 違反時は書き込みを即座に中止し、診断 **E060** を表示する（MUST）。

#### 13.1.3 読み取りについて

読み取りは「ユーザーが明示的に選んだパス」（フォルダ選択ダイアログ、Zip インポート）に限り、プロジェクト外でも許可する。
ただし **読み取ったパス自体を履歴以外のどこにも保存しない**。
プロジェクトの中にあっても、行き先がプロジェクトの外のシンボリックリンクは読まない（ファイルのリンクは一覧に出さず、名前で
読んでも無いものとする。ディレクトリのリンクは辿らない。プロンプトがプロジェクト外から読み込まれないこともこれで担保する）。

### 13.2 デスクトップ: パス履歴ファイル

#### 13.2.1 場所（固定）

| OS | パス |
|---|---|
| Linux / BSD | `$XDG_STATE_HOME/novnow/recent.json`（未設定時 `~/.local/state/novnow/recent.json`） |
| macOS | `~/Library/Application Support/novnow/recent.json` |
| Windows | `%APPDATA%\novnow\recent.json` |

環境変数 `NOVNOW_RECENT_FILE` が設定されていればそれを使う（テスト・ポータブル運用のため）。

#### 13.2.2 形式（これ以外のキーを足してはならない。MUST）

```json
{
  "schema_version": 1,
  "items": [
    { "path": "/home/user/novels/hoshikuzu", "opened_at": "2026-10-09T12:00:00+09:00" }
  ]
}
```

- `path` は絶対パス。`opened_at` は **履歴の順序を保つためだけ** に存在する（順序は履歴の本質であるため許容する）。
- 上限 **32 件**。超えたら古い順に捨てる。
- タイトル・サムネイル・文字数・最後に開いた節など、**プロジェクトの内容に関する情報は一切書かない**（MUST）。
- 存在しないパスは起動時の一覧表示で灰色にし、選択すると「履歴から削除」を促す。
- ファイルが壊れていたら黙って空の履歴として扱い、上書きする。
- 同じ `path` は 1 件にまとめる（開くたびに先頭へ移す）。
- 書き込みは一時ファイルを使わず **直接上書き** する（§13.1.1 は一時ファイルであってもプロジェクト外への書き込みを禁じる）。親ディレクトリ（`novnow/`）の作成は履歴ファイルの書き込みの一部として許す。
- `opened_at` は RFC 3339。順序のためだけの値なので UTC（`Z`）で書いてよい。

### 13.3 Web: IndexedDB

#### 13.3.1 なぜ LocalStorage をやめるか

LocalStorage は同期 API・文字列のみ・容量 5MB 前後という制約があり、長編小説 1 本（数 MB）+ 複数プロジェクトに耐えない。
v0.1.0 では **IndexedDB のみ**を使い、LocalStorage は移行のためにだけ読む（移行後に消す）。

#### 13.3.2 スキーマ

DB 名 `novnow` / バージョン `1`。

| ストア | keyPath | インデックス | 値 |
|---|---|---|---|
| `projects` | `id`（文字列 UUIDv4 または `sample`） | `by_updated`（`updated_at`） | `{ id, name, created_at, updated_at, schema_version, origin }` |
| `files` | `[project_id, path]` | `by_project`（`project_id`） | `{ project_id, path, text, updated_at }` |
| `app` | `key` | — | `{ key, value }`。**許可キーは `recent_projects` のみ**（§13.3.4） |

- `origin`: `"sample" | "new" | "import"`。
- `path` はプロジェクトルートからの相対パス（`contents/01-04.cnov`）。先頭スラッシュ禁止。
- 1 ファイル = 1 レコード。バイナリ資料は v0.1.0 では非対応（テキストのみ）。

#### 13.3.3 操作のトランザクション境界

| 操作 | トランザクション |
|---|---|
| ファイル保存 | `files` に `readwrite` で 1 回 `put` + `projects.updated_at` 更新（同一トランザクション） |
| プロジェクト作成 | `projects` + `files`（雛形一式）を 1 トランザクション |
| プロジェクト削除 | `by_project` で全ファイル削除 + `projects` から削除を 1 トランザクション |
| エクスポート | 読み取り専用トランザクションで全件取得 |

#### 13.3.4 `app` ストア（規則 10 の Web 版）

```json
{ "key": "recent_projects", "value": { "schema_version": 1, "items": [ { "id": "…", "opened_at": "…" } ] } }
```
Web には「プロジェクトディレクトリパス」が存在しないため、その等価物として **プロジェクト ID の履歴** のみを許可する。
`app` ストアに他のキーを書くことは禁止（MUST、テストで検証）。テーマ・言語などは `files` 内の `.novnow/ui.json` に置く（= プロジェクト内）。

#### 13.3.5 サンプルプロジェクトの初期投入

- 起動時に `projects` が空なら、**`sample` という名前のプロジェクトを 1 つだけ** 作成する（`id = "sample"`, `origin = "sample"`）。
- 中身は novnow バイナリに埋め込んだ v0.1.0 形式のサンプル小説（付録 C）。
- 投入後も **必ずプロジェクト選択モーダルを出す**。一覧には `sample` 1 件だけが並ぶ（指示 2 の明文）。自動で開いてはならない（MUST）。

#### 13.3.6 容量・エラー

- 起動時に `navigator.storage.persist()` を要求する（拒否されても続行）。
- 保存前に `navigator.storage.estimate()` で残容量を確認し、残り 10MB 未満なら W062。
- `QuotaExceededError` は `SaveFailed`（§8.2）として扱い、「Zip でエクスポートしてから不要プロジェクトを削除」する導線をモーダルで出す。
- プライベートブラウジング等で IndexedDB が使えない場合は **LocalStorage へフォールバックしない**（MUST）。
  起動を中止し、全画面メッセージ（i18n 済み）で状況と回避策（通常ウィンドウで開く / デスクトップ版を使う）を示す。

#### 13.3.6 PWA 化とオフライン動作〔状態: 実装完了〕

- ブラウザ版は PWA（Progressive Web App）として構成し、ブラウザからインストール可能かつネットワーク未接続のオフライン環境でも起動・執筆・保存が完結するようにする。

### 13.4 プロジェクト選択モーダル（Web）

ページを開いた瞬間（フォント読み込み完了前でも）に表示する。

```
┌──────────────────────────────────────────────┐
│  [検索欄 autofocus]                           │
│                                               │
│   sample                 2026-10-09   124 KB  │  ← 選択行は accent 背景
│   hoshikuzu-no-tokei     2026-10-08   2.1 MB  │
│                                               │
│   [＋]  [⇪]                                   │  ← 新規 / Zip 読み込み（アイコンのみ）
└──────────────────────────────────────────────┘
```

- タイトル文言は `project.pick.title`（これは「内容から役割が分からない」ケースなのでラベルを残す）。
- キーボード: `↑/↓` 選択、`Enter` 開く、`/` 検索欄へ、`Ctrl+N` 新規、`Ctrl+I` インポート、`F2` リネーム、`Delete` 削除（確認モーダル、名前の入力一致を要求）。
  ブラウザがページに渡さないキー（Chrome の `Ctrl+N` など）は、同じ操作のボタン（新規・Zip 読み込み）で代える。
- Web 版は別タブでの変更を自動検知しないため、モーダル内に「別のタブでの変更は検知されません。1 つのタブでお使いください」（`web.note.single_tab`）を明示する。
- **プロジェクトを選ぶまで背後の UI を描画しない**（MUST）。`Esc` では閉じない。
- 2 回目以降は `Ctrl+O` でいつでも開ける。開いている編集内容は先に保存される（§8.2 の即時トリガー）。

#### 13.4.1 同名プロジェクト作成の禁止と初回起動ウェルカム案内〔状態: 実装完了〕

- **同名プロジェクトの禁止**: Web 版では既存のプロジェクトと同じタイトルのプロジェクトを新規作成・改名できないようにする。
- **初回起動時のウェルカム案内**: プロジェクト履歴に何も存在しない初回起動時には、アプリについての簡潔な説明とドキュメントサイトの存在を知らせるウェルカムメッセージを表示する。この案内は初回以降もコマンドパレット上からいつでも呼び出せる。

#### 13.4.2 入口ページの初期言語

- Web 版の入口ページは、アプリ本体が読み込まれるまでの静的な表示も含め、ブラウザ（OS）のロケールで初期表示する（§12.4）。読み込み完了前の画面が、利用者の言語とは違う言語で固定されて見えてはならない。
- プロジェクト選択画面（Web・デスクトップとも）に言語切替ボタンは置かない。言語は §12.4 の決定順序に従い、変更は作品を開いた後に行う。

### 13.5 Zip インポート / エクスポート

- エクスポート: プロジェクト全ファイルを Deflate で Zip 化し、`<project-name>.zip` としてダウンロード（Web）/ **保存ダイアログでユーザーが指定したパスに書き出す**（デスクトップ。ダイアログの初期値は `exports/<project-name>.zip`。プロジェクトの外を指定してもよい＝ §13.1.1 の特例での「`exports/` 固定・ダイアログなし」を改めた）。
  `.novnow/` は **含めない**（ローカル状態のため）。`exports/` は含める（書き出し先がプロジェクト内なら、その Zip 自身は除く）。
  名前がドットで始まるもの（`.git/`・`.DS_Store`・原子的保存の一時ファイル等）は含めない。ただし `novnow new` が作る `.gitignore` と `.gitkeep`（§14.5）は含める。`.git/` は読みもしない（§14.2.1）。
- インポート: Zip 内に単一のルートディレクトリがあれば剥がす。`__MACOSX` とドットファイル（`.gitignore` / `.gitkeep` を除く）は無視。
  絶対パスや `..` を含む名前は取り込まず、一覧で示す（プロジェクト外への書き込みになるため、§13.1）。
  取り込み後に §4.3 の妥当性検査を行い、不備があれば「不備のまま取り込む / 取り消す」を選ばせる。
- Web ではインポート先として新しいプロジェクトレコードを作る（既存に上書きしない。MUST）。Web はテキストのみ（§13.3.2）なので、UTF-8 として読めないエントリは取り込まずに一覧で示す。
- デスクトップでは、ユーザーが選んだディレクトリを新しいプロジェクトルートとして書き込む。既存のファイルは上書きしない（§14.5 の `new` と同じ）。
- プロジェクト一式を入れた Zip のファイル名の拡張子が `.novnow` のものも、`.zip` と同じ規則でインポート／エクスポートできる。実体は通常の Zip であり、独自形式ではない（`.novnow` はプロジェクト全体のパッケージを表す拡張子として予約する）。`.novnow/`（ローカル状態の隠しディレクトリ）と `.novnow` ファイルは別のものである。

---

#### 13.5.3 デスクトップでの Zip 導入と Web⇔デスクトップ移行ヘルプ〔状態: 実装完了〕

- デスクトップ版でも CLI（`novnow import <zip> <dir>`）および GUI から Zip ファイルを取り込んでプロジェクトを展開できるようにする。
- Web 版からデスクトップ版への移行、およびデスクトップ版から Web 版への移行について、Zip を使った手順を案内するヘルプを備える。

## 14. 起動仕様

### 14.1 CLI 文法

```
novnow <dir>                    既存プロジェクトを開く（フラグなし位置引数）
novnow new [dir]                dir（既定 "."）に新規プロジェクトを作る
novnow check <dir>              妥当性検査のみ行い、診断を出して終了（CI 用）
novnow export <dir> [options]   アノテーション除去エクスポート（§17）
novnow mcp <dir>                MCP サーバとして起動（§15.8.3）
novnow migrate <入力…> <dir> [--preview]  既存本文を新しい作品へ移行（§14.6）
novnow --gui                    引数があっても GUI 起動を強制
novnow --help | -h
novnow --version | -V
```

- **サブコマンド解決規則**: 第 1 位置引数が `new` / `check` / `export` / `mcp` / `import` / `migrate`、または §19 の `lsp` / `api` / 正規操作のドメイン名と完全一致したときにコマンドとして解釈する。既存コマンド語を優先し、他はプロジェクトディレクトリとして解釈する。
- 予約語と同名のディレクトリは `novnow ./new` / `novnow ./api` / `novnow ./lsp` / `novnow ./project` のように `./` を付けて開く。
- `export` のオプション、`migrate` の末尾 `--preview`、§19 の `--json` / `--lang` / 操作別引数を受け付ける。既存サブコマンドの名前・引数・出力・終了コードの凍結は、新しいドメイン動詞の追加と区別する（§19.6）。

#### 14.1.1 `novnow import <zip> <dir>` の追加〔状態: 実装完了〕

- サブコマンドとして `novnow import <zip> <dir>` を追加し、Zip アーカイブ `<zip>` をディレクトリ `<dir>` へ展開してプロジェクトとして導入できるようにする。

### 14.2 起動時のスキャンとエラー出力

`novnow <dir>` は、GUI を出す前に次を行う。

1. `<dir>` の存在・ディレクトリであること・読み取り権限を確認。
2. §4.2 の必須パスを **すべて** 検査（最初の 1 件で止めず、不足を全部集める）。
3. `project.toml` の `schema_version` を検査（§4.3）。
4. 1 件でも問題があれば **stderr に出力して終了。GUI は一切出さない**（MUST、指示 2 の明文）。

#### 14.2.1 定数

```rust
/// プロジェクト構造の解説ページ
pub const PROJECT_STRUCTURE_DOC_URL: &str =
    "https://sonneko.github.io/novnow/guide/project_structure.html";

/// Git の解説ページ
pub const GIT_GUIDE_DOC_URL: &str =
    "https://sonneko.github.io/novnow/guide/git.html";

/// CI/CD・自動公開の解説ページ
pub const CICD_GUIDE_DOC_URL: &str =
    "https://sonneko.github.io/novnow/guide/publish.html";
```
これらの URL はハードコードせず、この定数群のみを参照する（MUST）。
**3 つの URL はすべて公開サイトに実在しなければならない（MUST）。** 実在は CI が検査する（§18.5）。

**解説ページへの導線（v0.1.0 追加仕様 14、MUST）**

novnow 本体は Git も CI/CD も **実装しない**。ファイルベースであることの帰結として
「Git を使えば版管理できる」「GitHub Actions を使えば自動公開できる」というだけであり、
IDE がそれを肩代わりすると、プロジェクトディレクトリ外への書き込み（規則 10）や
バージョン管理の二重実装（U-7）に必ず繋がるためである。

したがって提供するのは **解説ページへのリンクのみ** とする。

| 導線 | 置き場所 | 文言 |
|---|---|---|
| Git の解説 | ヘルプメニュー / `novnow new` 完了時の案内 / `review` の下部 | `原稿のバックアップと履歴（Git）について` |
| CI/CD の解説 | ヘルプメニュー / エクスポート完了ダイアログ | `公開を自動化する（GitHub Actions）について` |

- リンクは **外部ブラウザで開く**（MUST）。アプリ内ブラウザを持たない。
- Web 版では新規タブで開く。
- **リンク以外のことをしない**（MUST）。Git の有無を検出しない、`git init` を促さない、
  コミット状況を表示しない、`.git/` を読まない。

#### 14.2.2 出力（ja）

```
novnow: このディレクトリは novnow プロジェクトではありません
```

```
novnow: this directory is not a novnow project
```

- 言語の決定は §12.4（`NOVNOW_LANG` → OS のロケール → 既定 ja）。CLI は §12.4 の 1（`.novnow/ui.json`）を読まない。OS のロケールは `LC_ALL` → `LC_MESSAGES` → `LANG` の順の環境変数（Windows で無ければユーザーの既定ロケール）。`NOVNOW_LANG` は `ja` / `en` で始まる値だけを受け、他の値は無視して次へ進む。
- 色付けは出力先が TTY のときのみ（`NO_COLOR` 環境変数を尊重）。

- 「このディレクトリに新規作成する場合」は、対象がカレントディレクトリなら `novnow new`、そうでなければ `novnow new <対象>`（空白や記号を含むパスは引用符で囲む）。「対象」はシンボリックリンク解決後の絶対パス。
- 対象が見つからないときは見出しを「ディレクトリが見つかりません」にして、構造の解説と `novnow new <対象>` を出す（終了コード 3）。ディレクトリでないときは見出しと対象だけ（3）。読めないとき（権限など）は 4。`schema_version` が新しすぎるときは「novnow を新しい版に更新してください」を出す（3）。

#### 14.2.5 終了コード

| コード | 意味 |
|---|---|
| 0 | 正常終了 |
| 2 | 使い方の誤り（引数不足・未知サブコマンド） |
| 3 | プロジェクトが不完全 / スキーマが新しすぎる |
| 4 | I/O エラー（権限・不正 UTF-8） |
| 5 | `check` が E 診断を検出（CI 用） |

- 対象が見つからない・ディレクトリでないときも 3（「novnow プロジェクトではない」の一種として扱う。§14.2.3）。
- 作者が §4.5.2 の設定で `"error"` として扱う診断も、コード 5 の対象に数える。`"off"` の診断は `check` にも出さない。
- まだ実装されていないサブコマンドと、GUI を含まないビルドで GUI を求められたときは 2（新しい番号は作らない）。
- `check` の診断は標準出力に 1 行 1 件で `パス:行:列: [場所] コード 文言`（行と列は 1 始まり、列は文字数。位置を持たない診断は `パス: [場所] コード 文言`）。並びはパス → 位置 → コードで、最後に件数を 1 行出す。W と I だけなら 0。

### 14.3 GUI 直接起動の判定

```rust
enum Launch { Cli(Subcommand), OpenProject(PathBuf), Gui }

fn decide() -> Launch {
    if args.contains("--gui")            { return Launch::Gui; }
    if let Some(sub) = parse_subcommand(){ return Launch::Cli(sub); }
    if let Some(dir) = first_positional(){ return Launch::OpenProject(dir); }
    if stdin_is_terminal() || stdout_is_terminal() { print_usage(); exit(2); }
    Launch::Gui          // 引数なし & 端末に繋がっていない = GUI から起動された
}
```

OS 別の要件（MUST）:

| OS | 要件 |
|---|---|
| Windows | リリースビルドは `#![windows_subsystem = "windows"]`。起動直後に `AttachConsole(ATTACH_PARENT_PROCESS)` を試み、成功した場合のみ stdout/stderr を親コンソールへ接続して CLI として振る舞う。**新しいコンソールウィンドウを決して作らない**（`AllocConsole` 禁止） |
| macOS | `.app` バンドルから起動されると引数なし・非 TTY になるため GUI。`open -a novnow --args ./dir` も `OpenProject` として機能すること |
| Linux | `.desktop` からの起動は非 TTY のため GUI。`Exec=novnow %f` でファイルマネージャからディレクトリを渡せること |

ターミナルから `novnow` を引数なしで実行した場合は **GUI を出さず** 使い方を表示して終了（コード 2）。GUI が欲しい場合は `novnow --gui`。

- `--gui` / `--help`（`-h`）/ `--version`（`-V`）はどの位置にあっても効き、この順で優先する。`-` で始まる知らない引数と余分な位置引数は使い方の誤り（2）。`-` だけはディレクトリ名として扱う。
- **Windows の注意**: GUI サブシステムの実行ファイルは、`cmd.exe` から起動すると終了を待たれない（出力がプロンプトの後に出て、`%ERRORLEVEL%` も取れない）。CI などで終了コードを使うときは `start /wait novnow check .`、PowerShell なら `Start-Process -Wait -PassThru` を使う。

### 14.4 GUI 起動時のプロジェクト選択モーダル（デスクトップ）

```
┌──────────────────────────────────────────────┐
```

- `↑/↓` + `Enter`、`Ctrl+O` でネイティブのフォルダ選択（エクスプローラ / Finder / ポータル）を開く。

  「ここに新規作成する」ボタンを出す。**ここでも勝手に作らない**（明示操作が必要）。

#### 14.4.1 `Ctrl+O` で一覧へ戻る 2 段構成・日付表示・履歴のみの削除〔状態: 実装完了〕

- **`Ctrl+O` の 2 段構成**: デスクトップ版でも `Ctrl+O` は「現在のプロジェクトを保存してからプロジェクト選択画面（履歴一覧）へ戻る」動作に統一し、一覧画面内の「フォルダを開く」からディレクトリを選ぶ 2 段構成とする。
- **日付の表示**: デスクトップのプロジェクト選択画面の各行に最終利用日付を表示する。
- **履歴削除の明示提供**: デスクトップのプロジェクト選択画面に、「ディスク上の原稿データ自体は消さず、フォルダを開いた履歴のみを一覧から消す」ことをユーザーに明示した上で履歴削除機能（ボタンおよび `Delete` キー）を提供する。

### 14.5 `novnow new` の生成物

```
<dir>/

  characters.md         サンプル 1 名（モード 2 つ・役割語 2 本つき）
  words.md              サンプル 1 語
  ideas.md              書き方のコメント 1 行だけ（見出しを置くとアイデア 1 件になるため、§5.7）
  contents/01-01.cnov   @01-01-01 と 1 節のサンプル
  plots/all.cnov        @01 ブロック 1 つ（summary 入り）
  plots/01.cnov         @01-01 ブロック 1 つ
  plots/01-01.cnov      @01-01-01 と 1 節（mode: つき）
  materials/index.json  {"schema_version":1,"next_id":1,"items":[]}
  materials/docs/.gitkeep

  agents/mcp.json       {"schema_version":1,"servers":{}}
  agents/{tasks,results,threads,proposals,log}/.gitkeep
  .gitignore            .novnow/ と exports/ を無視
```

- 生成先が空でないディレクトリの場合: 上記のうち **存在しないファイルだけ** を作る。既存ファイルは絶対に上書きしない（MUST）。
- 競合が 1 件でもあれば、作成したファイルの一覧と「上書きしなかったファイル」の一覧を標準出力に出す。
- 生成先が `schema_version` が新しすぎるプロジェクトなら、**何も書かずに**エラーを出して終了する（コード 3）。生成先がファイルなら 4。

- 履歴には書かない（積むのは GUI がプロジェクトを開けたとき、§14.4）。

### 14.6 既存本文テキストからの移行支援

既存の小説本文テキストから新しい作品へ移行する。

- CLI は `novnow migrate <入力…> <dir> [--preview]`。入力は 1 個以上のテキストファイルまたはフォルダ（混在できる）であり、引数の並び順に処理する。最後の引数が移行先ディレクトリである。フォルダを指定した場合は、直下にある拡張子 `.txt` / `.md` のファイルだけを自然順に読み、サブフォルダは辿らない。`--preview` は末尾に指定し、生成ファイル一覧と変換後の本文（分割の候補を含む、§14.6.2）を標準出力へ表示する。ディレクトリ・履歴・ファイルを一切作成しない。
- デスクトップの作品選択画面から入力テキストを選び、プレビューを確認して新規の移行先を選択できる。確定後に作品を開く。Web のテキスト移行は対象外とする。
- 入力にできるのはプレーンテキストだけである。`.docx` などのバイナリ文書は受け付けない。
- 入力元は変更せず、そのパスを作品に保存しない。移行先は存在しないディレクトリのみ。親ディレクトリは既存のものを指定する。既存のファイル・ディレクトリ・シンボリックリンクへの取り込みは拒否する。
- 入力エラーは出力前に拒否する。書き込み途中の I/O エラーでは不完全な新規ディレクトリが残る場合があり、失敗を通知する。既存作品とのマージや上書きはしない。
- 題名は移行先ディレクトリ名とする。プロットの構造だけを用意し、サンプル本文・人物・用語は混入させない。話者推定はしない。

#### 14.6.1 文字コードの扱い（ファイル取り込みと貼り付け）

- ファイル取り込み（CLI / デスクトップ）では、文字コードをバイト列から判定する。正しい UTF-8 を優先し（先頭 BOM は除く）、UTF-8 として読めない場合は Shift_JIS として変換する。Shift_JIS 以外の符号化（EUC-JP など）は対象にしない。どちらでも読めない場合、空白だけの入力、NUL を含む入力は拒否する。判定が曖昧な場合はプレビューで文字コードを切り替えられる。
- GUI の入力欄への貼り付けは通常は Unicode の文字列のまま扱う。ただし、UTF-8 の文字列を Shift_JIS で読み違えた文字化けらしい文字列のときは、直した候補をプレビューして選ばせる。選ばなかった場合と候補を作れない場合は、元の文字列のまま貼り付ける。この扱いは複数行の入力欄を対象とし、デスクトップと Web の双方に適用する。
- 修復候補を出す条件は次のすべてを満たすときだけである（自動では置き換えない）。
  - 4 文字以上で、ASCII だけではない。
  - 元の文字列に文字化けの指紋がある。指紋は「文字化けで頻出する固定の 17 字（`縺` `繧` `繝` `縲` `吶` `峨` `譖` `翫` `菴` `薙` `譁` `帙` `隱` `溘` `榊` `蜷` `荳`）のいずれかを含む」または「半角カタカナが 3 文字以上」のどちらか。
  - 元の文字列を Shift_JIS へ符号化し直せ、UTF-8 として読み直した結果が元と異なる（符号化できない文字が 1 つでもあれば、その文字列は Shift_JIS の読み違いでは作れないので候補にしない）。
  - 読み直した結果の欠損（置換文字）が、全体の文字数の半分以下である。
  - 読み直した結果にかな（ひらがな・カタカナ）を含む。
- 編集画面での自動の節分割は、現行どおり明示的な区切りだけとし、§14.6.2 の候補生成は移行のときだけ行う。

#### 14.6.2 章・話・場面・節への分割（候補提示型）

- 分割は候補の提示だけを行い、自動では確定しない。デスクトップではプレビューで章・話・場面・節のツリーと件数を示し、各候補を他の段または境界なしへ変更でき、生成は候補を確定した後だけ行う。CLI では候補を編集できず、生成した候補のとおりに生成する（`--preview` で候補を確認できる）。
- 複数ファイルは自然順に並べ、1 ファイルを 1 話、1 フォルダを 1 章として候補化する。単一ファイルは第 1 章・第 1 話から始める。
- 見出し行では章・話の境界候補を作る。対象は単独の短い行だけで、「第○章」「第○話」（○ は漢数字・算用数字。括弧や空白、末尾のタイトルを付けてもよい）と、序章・終章・プロローグ・エピローグ・幕間・閑話・番外編を拾う。序章・終章・プロローグ・エピローグは章の境界候補、幕間・閑話・番外編は話の境界候補とする。見出しの残りは章・話のタイトルとして使い、本文には残さない。番号が飛んだり重なったりしても、構造番号は出現順に振り直す。
- 区切り行（`＊＊＊` のように記号だけの行）と、空行が 2 つ以上続く箇所では、場面の境界候補を作る。空行 1 つだけの段落区切りでは、節の境界候補を作る。
- novnow の記号はエスケープして本文として保持する。改行・行末空白は通常の保存規則で正規化する。本文内の空行は、境界として使わなかった分を保持する（エクスポート時は通常どおり連続空行が圧縮される）。ルビ記法はルビ保持設定で出力する。
