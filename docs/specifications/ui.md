# novnow 仕様書 — 画面・ワークスペース・テーマ・国際化

## 9. 画面仕様（共通シェル）

### 9.1 全体レイアウト

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ① ヘッダ（高さ 28px・ラベル無し）                                          │
│   [ワークスペースインジケータ] [パンくず 01›04›02›03]      [言語][テーマ]  │
├───────────────────────────────────────────┬──────────────────────────────┤
│ ② メインカラム（既定 62%、最小 480px）     │ ③ 参照ペイン（既定 38%、     │
│  ┌──────────────────────────────────────┐ │   最小 320px / 最大 560px）  │
│  │ 文脈ビュー（前後の節・読み取り専用）  │ │                              │
│  │ 既定 55% の高さ                       │ │  §9.5                        │
│  ├──────────────────────────────────────┤ │                              │
│  │ 節エディタ（編集対象の節のみ）        │ │                              │
│  │ 既定 45% の高さ                       │ │                              │
│  └──────────────────────────────────────┘ │                              │
├───────────────────────────────────────────┴──────────────────────────────┤
│ ④ ステータスバー（高さ 22px）                      ... [保存インジケータ] │
└──────────────────────────────────────────────────────────────────────────┘
```

- v0 にあったファイルツリー（左上）は **廃止**。その分の横幅を文脈ビューに回す。
- 分割比は `Ctrl+Alt+Shift+←/→`（メイン/参照の比）と `Ctrl+Alt+↑/↓`（文脈ビュー/節エディタの比）で 5% 刻み変更。`.novnow/ui.json` に保存。
  
- ウィンドウ幅 < 900px では参照ペインを折り畳み、`Ctrl+3` でオーバーレイ表示に切り替える。

#### 9.1.4 ヘッダ右端の常設ボタン・点検アイコン変化・操作要素の視覚規約〔状態: 実装完了〕

- **ヘッダ右端の常設ボタン**: 上端アイコンバーの右側に、テーマ切替・言語切替と並べて **`Ctrl+P` ボタン**（統一パレットを開く）と **`?` ボタン**（ショートカット選択パレットを開く）を常設する。
- **`review` アイコンのエラー・警告表示**: プロジェクト内にエラー（`E`）または警告（`W`）が存在するとき、上端アイコンバーの `review`（点検）ワークスペースアイコンにエラー色・警告色のバッジおよび強調変化を付け、異常が出ていることを視覚的に示す。
- **視覚的アクションボタンの併設**: キーボードショートカットでしか使えない機能をなくし、主要操作にはショートカット表記付きの視覚的ボタンを設置する（従来の「`Ctrl+Shift+N` で新しい資料を作れます」のようなガイドラベルはそのまま押せるボタンにする）。
- **押せる要素の統一表現**: 押せるボタン・リンク・アクション要素にはすべて共通して**薄い黒（ダーク時は薄い前景色）の下線**を付け、ホバー時の背景色変化とポインタカーソル変化を伴わせる。
- **押せないラベルの非選択化**: 押せない静的なラベルや見出しをダブルクリックしても、テキスト選択（薄い青の選択ハイライト）が入らないようにする。

#### 9.1.5 ヘッダの省略規則とプロジェクト名・パンくずのボタン

- ヘッダの要素は、左から画面切替アイコン列・プロジェクト名・パンくず・切替直後の画面名（1 秒）・右端の常設ボタン（ヘルプ・パレット・テーマ・言語）の順に並ぶ。幅が足りないときは、画面名の一時表示 → プロジェクト名 → パンくずの順に省略し、画面切替アイコンと右端の常設ボタンは常に残す。プロジェクト名は末尾を省略し、ホバーで全文を表示する。
- プロジェクト名はボタンであり、押すと `Ctrl+O` と同じ規則（現在の変更を保存してからプロジェクト選択画面へ戻る。保存に失敗している間は戻らず、その旨を知らせる）でプロジェクト選択画面へ戻る。
- ヘッダのパンくずはボタンであり、押すと `@` だけを入力した状態でコマンドパレットを開く。節エディタのミニヘッダー（§9.4.2）とステータスバー（§9.6）のパンくずは表示専用のままである。
- どちらのボタンも押せる要素の統一表現（下線・ホバー背景・ポインタ、§9.1.4）に従う。パンくずを持たない画面ではパンくずボタンを出さない。

### 9.2 ラベル撤廃規則

#### 9.2.1 規則

文字ラベルを置いてよいのは次の 3 つだけ（MUST）。

1. 内容を見ても役割が分からない場合（例: 参照ペイン内の情報種別見出し）
2. 破壊的操作（削除・却下・上書き）の確認
3. 診断・エラー・ヘルプの文言

それ以外は **アイコン・配置・色・フォーカスリング** で表現する。

#### 9.2.2 撤廃一覧（v0 → v0.1.0）

| v0 の表示 | v0.1.0 |
|---|---|
| ペイン見出し「ファイル」 | ペインごと廃止 |
| ペイン見出し「エディタ」 | 撤廃（下半分が編集領域であることは自明） |
| ペイン見出し「情報」 | 撤廃 |
| 「プレビュー（節スクロール: Alt+↑ / Alt+↓）」 | 撤廃（操作はヘルプ `?` と パレットで案内） |
| 「節 01-04-02-03」「(確定: Enter)」「対象行: 12」 | パンくず 1 つに統合（`01›04›02›03`） |
| メニューバーの「エクスポート (Zip)」「インポート (Zip)」「再読込 (F5)」「ショートカット」 | すべてコマンドパレットへ |
| 「フォーカス: 2 エディタ」 | 撤廃（フォーカスリングで示す） |
| ステータスバーの「… 行 … 文字 (空白除外: …) 原稿用紙換算: 約 … 枚 … 保存済み」 | 数値 + 単位記号に圧縮（§9.6） |
| 情報パネルの「現在の節」「対応プロット」「登場人物」「用語」「関連資料」 | **見出しは残すが、枠（`Frame::group`）を廃止** し、11px の弱色見出しにする |
| 「ホバー: ファイル名」 | 撤廃（ホバー自体を使わない） |

#### 9.2.3 フォーカス表現

- フォーカス中のペインは外周 2px の `accent` 枠。非フォーカスは枠なし。
- 文字ラベルでペイン名を書かない。`Ctrl+1/2/3` の対応は `?`（ヘルプオーバーレイ）でのみ説明する。

#### 9.2.4 編集面の左線

複数行のテキスト編集面には、左端に幅 3px の縦線を常時出す。普段は薄い色（`accent.faint`、§11.1）で「ここは編集できる場所である」ことを示し、フォーカス中は濃い青（`accent`）にする二段表示とする。対象は、節エディタ、話プロット・構成・配役・アイデア・資料本文の各エディタ、資料フォームの要約・条件欄、MCP 設定のコード欄、タスク作成の例欄である。1 行入力は対象にしない。

線の色の意味は、青 = 編集面とフォーカス、橙・緑・灰 = 状態（提案モードの警告線、節リストの状態色など）で分ける。同じ左端で両方が重なる場合は、警告・状態の表示を優先する。

### 9.3 文脈ビュー（メインカラム上段）

#### 9.3.1 内容

現在の節を中心に、**前 3 節・後 3 節**（既定、`ui.json` の `context_sections: 1..9`）を読み取り専用で表示する。

- 1 行の最大幅: 全角 **44 字**（既定）。これを超える幅があっても文字列は折り返す（指示 3「前後の節の表示幅を広げる」に対応し、v0 の狭いツリー併置をやめた分を使い切る）。
- 本文フォント 15px / 行間 1.9 / 段落間 8px。
- 節の境界には `border` 色の 1px 横線を引き、**8px の余白と節番号の薄い表示（`01-04-02-02` の 4 階層形式、`fg.faint`、10px、右寄せ）** で示す。
- 構文ハイライトは本文と同じ（§11.2）。役割語の緑下線もここで見える。
- スクロールは常に「現在の節が画面の上から 38% の位置」に来るよう自動追従する。

#### 9.3.2 編集中プレースホルダ

現在編集中の節の位置には **本文を一切表示せず**、次のブロックのみを置く。

```
┌────────────────────────────────────────────┐
│   ✎   01-04-02-03        412字   ●        │   ← 高さ 56px、背景 bg.inset、
└────────────────────────────────────────────┘      左端に 3px の accent 縦線
```

- 構成要素（これ以外を置かない）: 編集中アイコン（`✎` 相当のベクタ図形）/ SceneId / 現在の文字数 / 保存状態ドット。
- 文字数は 200ms ごとに更新。目標字数（`length`）がある場合は `412 / 500` と分母を添える。
- **節の本文テキストは絶対に描画しない**。

#### 9.3.3 折りたたみ

文脈ビューと構成ツリー（§10.3.1）で、**章 → 話 → 場面** の単位で表示を畳める。

| 操作 | 動作 |
|---|---|
| `Ctrl+Shift+[` | カーソル位置の 1 階層上を畳む（節 → 場面 → 話 → 章 と段階的に上へ） |
| `Ctrl+Shift+]` | 展開する |
| `Ctrl+K Ctrl+0` | すべて畳む（章だけが見える状態） |
| `Ctrl+K Ctrl+J` | すべて展開 |

- 畳まれた単位は **1 行** になる: `▸ 01-04 図書室の密談 ····· 5,842字 / 8節`。
- 表示するのは「見出し ▸ タイトル ▸ 文字数 ▸ 節数」の 4 要素のみ（MUST）。`summary` は出さない（情報密度を上げすぎないため）。
- **現在の節を含む単位は畳めない**（MUST）。畳もうとしたらその 1 つ上を畳む。
- 状態は `.novnow/ui.json` の `folded` に保存され、再起動後も復元される。
- 検索（§9.7.4）のヒットがある単位は、畳まれていても **自動で展開** する。
- 読者モード・エクスポートには影響しない（MUST）。

#### 9.3.4 節境界の横線・完全形節番号・フォーカス縦線・空状態ガイド・可視範囲レイアウト〔状態: 実装完了〕

- **節境目の横線**: 文脈ビューに並ぶ各節の境界に明確な横線を引き、節ごとの区切りを分かりやすくする。
- **節番号表記の統一**: 文脈ビューの節番号表示は、章番号を省略した `B-C-D` 形式ではなく、常に 4 階層すべてを含む **`A-B-C-D`（`@AA-BB-CC-DD`）**で統一表示する。
- **編集中プレースホルダとフォーカス縦線の対表示**: 文脈ビュー内の「現在編集中の節」のプレースホルダ左端にも **3px の縦線**を表示し、節エディタ側のペインフォーカス縦線と対で見せる。
- **未保存ドットの拡大**: 節ごとの未保存状態を示すオレンジの点を視認しやすい大きさ（直径 8〜10px 相当）にする。
- **本文 0 文字時の 3 行ガイド**: 本文が 0 文字のときは、文脈ビュー領域に 3 行の操作ガイド（`Alt+数字=画面 / Alt+矢印=節移動 / Ctrl+P=一覧`）を薄字（`fg.faint`）で表示する。
- **可視範囲のみのレイアウト**: 文脈ビューはスクロール領域の可視範囲に入る節・行のみをレイアウトおよび描画する。

#### 9.3.5 節の削除ボタン

文脈ビューの各節には、その節を指定して削除するボタンを置く。削除の意味と確認の規則は §8.1.2 に従う。節エディタのミニヘッダー（§9.4.2）には削除ボタンを置かない。

### 9.4 節エディタ（メインカラム下段）

#### 9.4.1 基本

- 編集対象: 現在の節のテキスト全体（複数行）。
- 行番号: **節内のローカル行番号**（1 始まり）を左に表示。ファイル全体の行番号は出さない（節が単位であるため）。
- `Enter` は改行。`Ctrl+Enter` はカーソルのバイト位置で節を 2 つに分割する（§8.1.1）。節の末尾では「確定して次の節へ」と同じ結果になり、次が無ければ新規節を作る。
- `Ctrl+;` は「この節の直後に新しい節を作って移動」。
- ソフトラップ有り。横スクロールは発生させない。
- 入力補完（§9.7.3）はこのペインでのみ動作する。

#### 9.4.2 ミニヘッダー

上端の 1 行（高さ 18px）。左から順に、**これ以外を置かない**。

```
01›04›02›03                      ▓▓▓▓▓░░░░░░░░░░ 34%      'リリア B+C
└ パンくず                        └ 台詞比率バー            └ 有効モード
```

| 要素 | 仕様 |
|---|---|
| パンくず | `01›04›02›03`。クリック不可（移動はキーボード） |
| **台詞比率バー** | 幅 64px・高さ 4px の横棒。塗り部分が台詞の割合。右に `34%` を 10px で添える |
| 有効モード | `'リリア B+C`。10px、色はキャラの `color` |

**台詞比率の算出（決定論、MUST）**

1. 対象は **現在の節** のみ（本文全体ではない）。
2. 台詞文字数 = `「…」` および `『…』` の **内側** の文字数の合計。鉤括弧そのものは数えない。
3. 地の文字数 = 節の全文字数 − 台詞文字数 − アノテーション（§5.0.7 の 9 種）の文字数。
4. 空白・改行は両方から除外する。
5. 比率 = 台詞 ÷（台詞 + 地の文）。分母 0 のときはバーを描かない。
6. 更新は打鍵から 200ms デバウンス。

**色（MUST）**: バーの色は常に `fg.faint` の単色。
`dialogue_ratio_target` から外れても **赤くしない**（警告は §10.9 の文体タブに限る）。
ここは「今どうなっているか」を知る窓であって、「正しさ」を告げる場所ではない。

ワークスペース（§10.2）のヘッダには同じバーを **話全体** について出す。

#### 9.4.3 句切れ提案レイヤー

読点を打ち忘れた長文に対し、**打てそうな位置を控えめに示す**。

| 項目 | 仕様 |
|---|---|
| 既定 | **オフ**（`.novnow/ui.json` の `suggest_comma: false`）。`Ctrl+Alt+,` でトグル |
| 発火条件 | 1 文（`。！？` までの区切り）に読点が 0 個、かつ `writing.long_sentence_chars`（既定 120 字）超 |
| 表示 | 候補位置の文字間に **1px・高さ 10px の縦線**（`fg.faint` の 40% 不透明度）。文字は一切挿入しない（MUST） |
| 適用 | `Alt+→` / `Alt+←` で候補間を移動、`Alt+,` でその位置に `、` を挿入 |
| 診断との関係 | 発火した文には W081 が付く（既定で無効、§7.2） |

**候補位置の決定（決定論・形態素解析なし、MUST）**

次の文字列が **その直後** に現れた位置を候補とする。優先度の高い順に並べ、上位 3 件だけを表示する。

| 優先 | 手がかり | 例 |
|---|---|---|
| 1 | 接続助詞 `が` `けれど` `けれども` `ので` `のに` `から` `ば` `と` `て` `ても` `たら` `なら` | 「〜だった**が**、」 |
| 2 | 読点の直前に来やすい副詞句 `ときに` `ために` `ように` `ながら` `つつ` | 「〜しながら、」 |
| 3 | 主題の助詞 `は` `も` が文頭から 10 字以内に現れた直後 | 「少年**は**、」 |
| 4 | 列挙の `と` `や` が 3 回以上連続した各直後 | — |

**除外規則**: 次の位置は候補にしない。

- `「…」` の内側（台詞のリズムは作者の領分、MUST）
- 直前または直後 6 字以内に既に `、` がある
- 行末から 4 字以内
- `'参照` や `｜ルビ《…》` の途中

**思想上の注意（MUST）**: この機能は **提案に留まり、自動では決して挿入しない**。
「正しい日本語」を IDE が決めることはしない。既定がオフなのもそのためである。

#### 9.4.4 繰り返し・接続詞の検出（W087 / W088 の算法）

形態素解析を使わない範囲で決定論に行う。

| 検査 | 算法 |
|---|---|
| W087 同語反復 | 段落内で、**辞書（`'` のトライ）に登録された語** と、2 字以上の漢字連続・3 字以上のカタカナ連続を数える。同一表記が 3 回以上で発火。助詞・助動詞は対象外（辞書にも漢字列にも該当しないため自然に除外される） |
| W088 接続詞連続 | 文頭が固定リストに一致する文が 3 連続で発火。リスト（固定）: `しかし` `だが` `でも` `そして` `それから` `だから` `つまり` `また` `ところが` `しかも` `けれど` `それでも` `そのため` `なぜなら` |

#### 9.4.5 枠内余白・カーソルと行番号の整列・フォーカス表現の分離・`Tab` フォーカス制御〔状態: 実装完了〕

- **枠線内への収まり**: 節エディタの枠線の内側に適切な余白（パディング）を設け、本文テキストや下線が枠の外側にはみ出さないようにする。
- **カーソル寸法と行番号の位置合わせ**: キャレット（カーソル）の高さを文字サイズに対して自然な寸法に揃え、行番号の垂直位置を本文各行のベースライン・行高と正確に一致させる。0 文字の節（空の行）でも同じベースライン基準でそろえ、通常の行とずれないようにする。
- **ペインフォーカスと編集中枠の分離**: ペインのフォーカス表示は**左端 3px の縦線**、編集中の節そのものの領域表示は**常時 1px の枠線**として形を分け、`Ctrl+3` 等で参照ペインへフォーカスが移っても「どの節が編集中か」が失われないようにする。
- **エディタのフォーカスロックと `Tab` 巡回**: 節エディタ本体は 1 つのまとまったフォーカス対象としてロックし、入力欄の外では `Tab` / `Shift+Tab` でヘッダのボタンや画面内の操作部品を順番に回れるようにする（フォーカス中の部品には明確なフォーカス枠を表示する）。

### 9.5 参照ペイン

#### 9.5.1 体裁

- 枠線付きカードによる囲み表示を **禁止** する（MUST）。
- 区切りは枠線ではなく余白（セクション間 12px）と、見出しの字送り。
- 見出し: 11px / `fg.faint` / 太字無し / 下線無し。
- 本文: 13px / `fg.primary` / 行間 1.6。
- リンク（資料 URL 等）は下線のみ、色は `accent`。
- スクロールバーは hover 時のみ可視（2px）。

#### 9.5.2 表示順（固定）

1. **今の節のプロット**（話プロットの当該節テキスト。無ければ場面テキスト）
2. **上位プロット**（章プロットの `summary` 1 行 → 全体プロットの `summary` 1 行。計 2 行だけ）
3. **配役**: 有効モードの情報のみ（§6.4.6）
   ```
   リリア  B 冷静な観察者
   性格    呆れながらも見捨てない。損得より筋を通す。
   感情    好奇心が警戒心を上回りつつある。
   役割    主人公の暴走を止める者。
   口調    「*なのよ」「*あげるわよ」
   ```
4. **用語**: この節に出現する用語の `term` と `definition`（1 行目のみ、続きは `Ctrl+Shift+W` で全文）
5. **五感**: `senses:` の宣言（§5.4.4）。宣言が無ければ **この見出しごと出さない**
6. **空間**: `space:` の内容（§5.3.6）。4 行を超える場合は折りたたみ、`Ctrl+Shift+Space` で全文
7. **資料**: 明示参照（`'M...`）→ 本文の引用注釈（`^M...`、§5.2.4）→ 条件一致候補（§16.4）の順。各行 `M0137 タイトル` + `summary`
8. **挿絵**: この節の `! ` 行と `illustration:`（§5.2.5）。無ければ見出しごと出さない
9. **診断**: この節に関するもののみ。`E` → `W` の順、各 1 行

優先順位は v0 を踏襲し、**カーソル行 > 同一節 > 同一場面 > 同一話** とする。

**節の出現規則（MUST）**: 5・6・8 は内容が無ければ **見出しごと表示しない**。
空の見出しが並ぶとペインの情報密度が落ち、P3（ノイズを増やさない）に反するため。
1〜4・7・9 は従来どおり、内容が無ければ「—」も書かずに省略する。

#### 9.5.3 空間設計メモの表示

- `space-mode: ascii` のときは **等幅フォント・折り返しなし**（MUST）。
  参照ペインの幅に収まらない場合は横スクロールを許す（このセクションに限り、§9.5.1 の「横スクロール無し」の例外）。
- `space-mode: text` のときは通常の本文フォントで折り返す。
- 上位階層から継承した `space` には、見出しの右に継承元を薄く添える（`空間 · 01-04 より`）。

#### 9.5.4 更新タイミング

カーソル移動から **80ms デバウンス**（v0 の 100ms より短縮）。更新待ちの間もスピナーを出さず、前の内容を表示したままにする（ちらつき防止、MUST）。

#### 9.5.4 セクション境界線・要約の「続き...」・診断アコーディオン・形態素自動回復〔状態: 実装完了〕

- **セクション境界の横線**: 上位プロット・配役・用語・資料・診断などの各セクションの境界に薄めの横線を入れて区切りを明確にする。
- **要約切り詰め時の「`続き...`」表示**: 資料やプロットの要約が行数・文字数上限で途中で切れる場合は、末尾に「`続き...`」の 1 行を表示し、クリックまたは `Enter` で全文画面へ移動できるようにする。
- **診断の 4 件以上アコーディオン集約**: 同じ種類の診断が **4 個以上**ある場合は 1 行にまとめて表示し、クリックまたは `Enter` で開閉できるアコーディオンにする。
- **診断からの形態素単位の辞書・キャラ登録**: 未解決参照などの診断項目から、形態素解析で区切った 1 形態素をその場のボタンで辞書（`words.md`）またはキャラ一覧（`characters.md`）へ即座に追加して自動回復できるようにする。

#### 9.5.5 行からの移動

参照ペインの各行は、ダブルクリック、または `Ctrl+3` でフォーカスして `↑` / `↓` で選び `Enter` を押すことで、対応する場所へ移動できる。シングルクリックでは移動しない。飛び先はセクションごとに次のとおりとする（§9.5.2 の番号に対応）。

| セクション | 飛び先・動作 |
|---|---|
| 1 今の節のプロット | 話プロットの当該節 |
| 2 上位プロット | 章プロット／全体プロットの当該ブロック |
| 3 配役 | 配役画面の当該キャラ |
| 4 用語 | 定義行へは飛ばず、`Ctrl+Shift+W` と同じ全文表示を開く |
| 5 五感・6 空間・8 挿絵 | 話プロットの当該フィールド |
| 7 資料（明示参照） | 資料画面の当該資料を開く |
| 7 資料（条件一致の候補） | 従来どおり話プロットへ `material:` として追加する |
| 9 診断 | 該当箇所の節（点検画面の `Enter` と同じ） |

明示参照の「開く」と候補の「追加」は、見た目（下線の有無など、§9.9）で区別できるようにする。

#### 9.6.1 既定表示

左から順に（区切りは `·`、ラベル語は使わない）:


|---|---|---|
| パンくず | SceneId | 共通 |

| 診断件数 | `⚑` + E と W の合計。0 件なら非表示。クリック/`Ctrl+Shift+E` でレビューへ | — |
| 保存インジケータ | §8.4 | ツールチップのみ |

#### 9.6.2 執筆セッション情報

```
+1,240字  42分
```

| 項目 | 定義（MUST） |
|---|---|
| セッションの開始 | プロジェクトを開いた瞬間、または **30 分以上の無操作のあとの最初の打鍵** |
| セッションの終了 | プロジェクトを閉じる、または 30 分の無操作 |
| 増加文字数 | 開始時点の全本文文字数（空白除外）との **差**。削ればマイナスになり、`-320字` と表示する |
| 経過時間 | セッション開始からの実時間。**無操作の 30 分は含めない**（途切れたら次のセッション） |
| 範囲 | プロジェクト全体。節や話ではない |
| 本文の定義 | `contents/` のアノテーション除去後（§5.0.7）。プロット・あらすじ・提案は含めない |

**毎分の速度は既定では出さない**（MUST）。速度の常時表示は焦りを生み、
「執筆に集中させる」という本ツールの目的に反する。速度を見たい場合は §9.6.3 の統計モードを使う。

#### 9.6.3 統計モード（v0.1.0 追加仕様 20・25）

`Ctrl+Alt+S` でステータスバーの中央部が **統計表示に切り替わる**（トグル、`ui.json.status_stats_mode` に保存）。

```
01›04›02›03  ·  本日 3,800字  ·  18.2字/分  ·  7日平均 2,410字  ·  連続 12日  ·  ⚑2  ·  [保存]
```

| 要素 | 定義 |
|---|---|
| 本日 | `.novnow/stats.json` の当日 `chars` |
| 速度 | 現セッションの 増加文字数 ÷ 経過分。60 秒未満のときは `—` |
| 7 日平均 | 直近 7 日の `chars` の平均（0 字の日も分母に含める） |
| 連続 | `chars > 0` の日が連続している日数 |

**切り替えても消してはならない要素**: パンくず・診断件数・保存インジケータ（MUST）。
統計は文字数表示と置き換わる。

詳細な集計（時間帯分布・キャラ別台詞量・節長分布）は §10.9.5 の統計タブで見る。

#### 9.6.3 修飾キー押下中のショートカット補完・起動通知の左下トースト化・幅に応じた省略優先順〔状態: 実装完了〕

- **修飾キー押下中のリアルタイム補完**: ユーザーが `Cmd`（または `Ctrl` / `Alt`）を押している間、および `Cmd+Shift` 等を押し続けている間、その後に続けて押せるショートカット候補（例: `Cmd+Shift+X` 等）の補完ガイドをステータスバーに表示する。
- **起動時フォント通知のモードレストースト化**: 「日本語フォントが見つからないため、同梱のフォントを使います」のような一時通知はステータスバーを占領せず、画面左下のモードレストーストとして起動後数秒間のみ表示して自動的に消す。
- **幅に応じた表示省略の優先順**: ウィンドウ幅が足りないときに落とす順序を「**セッション情報 → 原稿用紙枚数 → 文字数**」と定め、**保存状態のマークを最高優先度**として常に残す。入りきらない項目は `…` にまとめ、`…` のホバーで詳細を表示する。出すか落とすかの判定は固定の幅しきい値ではなく、各要素の実測の描画幅で行う（空きがあるのに `…` になる状態を作らない）。保存インジケータの右端の予約幅は従来どおり確保する。

### 9.7 ナビゲーション

#### 9.7.1 コマンドパレット `Ctrl+P`

単一の入力欄で、先頭文字によってモードが変わる（固定）。

| 先頭 | 対象 | 例 |
|---|---|---|
| （なし） | ファイル・場面・節のあいまい検索 | `0104` → `contents/01-04.cnov`, `@01-04-02` |
| `>` | コマンド | `>export`, `>theme`, `>format` |
| `@` | SceneId ジャンプ | `@01-04-02-03` |
| `'` | 辞書（キャラ・用語） | `'リリア` → 定義へ / 使用箇所一覧 |
| `M` or `#` | 資料検索（§16.3） | `M0137`, `#取材 甲子園` |
| `?` | ヘルプ（キーボード一覧） | — |

- 候補は最大 50 件。`↑/↓` 移動、`Enter` 決定、`Shift+Enter` は「別の意味で開く」（例: 用語なら定義ファイルを開く）。
- あいまい一致のスコアリング（決定論、固定）:
  `+10` 連続一致 / `+6` 語境界一致 / `+3` 先頭一致 / `-1` スキップ文字。同点は ID 昇順で安定ソート。
- 畳まれた単位（§9.3.3）の中にある候補も、通常どおり検索対象になる。決定すると自動展開して移動する。

#### 9.7.2 直接ジャンプ

`Ctrl+G` で SceneId 入力（`0104` のように区切り無しでも受理し、桁数から補完）。

#### 9.7.3 入力補完

- `'` を入力した瞬間に候補ポップアップ（キャラ → 用語 → 資料の順、各最大 8 件）。
- `:`（キャラ参照の直後）でモード候補。`range` 外のモードは灰色で下に並べ、選ぶと E004 と同時にクイックフィックスを提示。
- `@`（行頭）で近傍 SceneId 候補、（行末）でキャラ候補。
- `Ctrl+Space` で明示起動。`Esc` で閉じる。`Tab` / `Enter` で確定。
- 候補の並び順は「現在の節に登場 > 同じ話に登場 > 直近使用 > 五十音（`reading` 優先）」（決定論）。

#### 9.7.4 全体検索と正規表現検索

プロジェクト内の検索は 2 系統に分ける（固定）。

**全体検索（`Ctrl+Shift+F` の重ね物）** は、本文（`contents/`）の文字どおり検索である。

| 項目 | 仕様 |
|---|---|
| 対象 | `contents/` の本文 |
| 結果表示 | ファイル → SceneId 順。各行に前後 20 字の文脈を添え、一致した範囲は §11.3 の検索一致の背景塗りで示す。畳まれた単位も結果に出す |

**正規表現検索** は、本文執筆（`write`）の全文検索タブで行う。

| 項目 | 仕様 |
|---|---|
| トグル | 検索欄右端の `.*` ボタン、または `Alt+R` |
| 文法 | 先読み・後読み・後方参照のない正規表現 |
| 大小文字 | 既定で区別する。`Alt+C` で無視に切替 |
| 置換 | `$1` `${name}` でキャプチャ参照。`\n` は改行 |
| **タイムアウト** | **1 秒**（MUST）。超えたら中断し、W094 の通知「検索が複雑すぎます」を出して部分結果を表示する |
| サイズ上限 | コンパイル後の正規表現のサイズ上限 1MB。超えたら構文エラー扱い |
| 構文エラー | 検索欄の下に 1 行で理由を出す。検索は実行しない |
| 対象 | `contents/` `plots/` `*.md`。`.novnow/` と `exports/` は **常に除外**（MUST） |
| 結果表示 | ファイル → SceneId 順。各行に前後 20 字の文脈。畳まれた単位も結果に出す |
| 置換の安全性 | 置換は **プレビュー必須**（MUST）。「{n} ファイル {m} 箇所」を確認してから実行。実行は 1 つの undo 単位 |

画面表示では、一致範囲は前後の文脈と区別して描く（太字等の記法を文字列に埋め込んで表示することはしない）。結果を資料として保存する形は §16.3.1 に従う。

**非目標**: 正規表現での **構造検索**（「リリアの台詞だけ」等）はここでは扱わない。
それはフィルタ（§10.9）の役目である。両者を混ぜると検索欄が複雑になりすぎる。

#### 9.7.3 パレットの配置・幅固定・ガイド・広さ優先 `@` 移動・`>` 全コマンド化・`?` 選択・Tab 補完〔状態: 実装完了〕

- **表示位置と最前面レイヤ（z-index）**: パレットは画面水平方向の中央・上端（VS Code と同じ位置）に配置し、節エディタの枠線を含むすべての背面要素より前面（最上位レイヤ）に描画する。
- **横幅固定と長文省略**: パレットの横幅は固定とし、選択肢のテキストが長い場合は末尾を `...` で省略（または短く整形）してパレット自体の幅や位置がズレないようにする。
- **閉じる手段と外側クリック**: 選択肢の中に「**パレットを閉じる**」を用意する。またパレットを開いている間にパレット外をクリックしたときは、背面の要素は押された判定にしないままパレットだけを閉じる。
- **未入力時ガイドと 0 件表示**: 未入力のパレットの下部に「`>` コマンド / `@` 節 / `'` 辞書 / `M`（`#`）資料 / `?` ショートカット」のルール説明ガイドを表示する。また資料や一致項目が 0 件のときは空白にせず「一致する項目がありません（ない）」と明示表示する。
- **`>` コマンドの階層化と全ショートカット網羅**:
  - `>` を押した初期状態ではエージェント関連の設定が大量に並んで他を埋めないよう、エージェント関連は `>agent ` の親項目にまとめる。
  - すべてのキーボードショートカット操作を `>` パレット経由でも実行できるようにし、さらに `agents/mcp.json` の編集モーダルや初回ウェルカム案内も `>` から呼び出せるようにする。
- **`?` によるショートカット選択実行**: パレットの `?` は単なる一覧表示ではなく、ショートカットを検索・選択してそのまま実行できるモードとする。
- **`@` による広さ優先の階層移動**: `@` を用いた移動では、最初から `@01-01-01-01, @01-01-01-02, ...` と深さ優先で並べるのではなく、まず `@01-* 〈第1章タイトル〉, @02-* 〈第2章タイトル〉, ...` を提示し、選択または入力に応じて話（`@01-01-* 〈話タイトル〉`）→ 場面（`@01-01-01-* 〈場面タイトル〉`）→ 節（`@01-01-01-01`）へと広さ優先で段階的に掘り下げる。
- **個別単位での `Tab` 補完**: パレット入力中に `Tab` キーを押すことで、個別のトークン単位（例: `">ag"` → `">agent "`、`"@01"` → `"@01-"`）で入力を補完できる。

#### 9.7.5 重ね物（モーダルと軽い重ね物）の共通規則

画面の上に重なる表示は、背面の操作を遮る**モーダル**と、遮らない**軽い重ね物**（検索/置換バー・入力補完・情報ポップアップ・クイックフィックス）に分ける。閉じ方と配置は全画面で次のとおり統一する（MUST）。

- **閉じ方**: モーダルは `Esc` またはモーダルの外側のクリックで閉じる。破壊的操作の確認モーダルでは、外側クリックは「キャンセル」と同じ意味とする。次の 2 つは外側クリックでも `Esc` でも閉じない（閉じると警告の意味が消えるため）: 保存失敗の通知、未保存の変更があるときの終了ガード。外側クリックが背面の要素を操作することは決してない。
- **軽い重ね物**: 外側クリックでは重ね物を閉じるだけとし、そのクリックを背面のボタンやエディタへの操作として通さない。
- **配置**: モーダルは画面中央に置く。コマンドパレットなどのパレット系は従来どおり画面上部に置く。
- **閉じる案内の共通フッタ**: 外側クリックと `Esc` で閉じられるモーダルには、末尾に「Esc / 外側クリックで閉じる」の案内を共通で出す（§9.2.1 の例外 3「ヘルプの文言」に当たる）。閉じられないモーダルには出さない。
- **入力の下書き**: 閉じたとき、改名・新規資料のタイトル・行幅設定・ジャンプ先のような短い 1 項目の入力は破棄する。項目の多いフォーム（MCP 設定・タスク作成・エクスポート設定・却下／差し戻しコメント・アイデア即時入力）の入力は、アプリを閉じるまでの間だけ保持し、次に開いたとき復元する。却下／差し戻しコメントは、同じ提案・同じ向きで開いた場合だけ復元する。下書きをファイルへ保存することはない。

#### 9.7.6 最近使った項目

- コマンドパレットの `>`（コマンド）と `@`（節移動）では、最近実行した項目をモードごとに直近 10 件まで覚える。同じ項目を再び実行したら先頭へ移す。
- 履歴は、パレットを開いた直後の**入力が空のときだけ**候補の先頭に出す。文字を入力した後は §9.7.1 の固定スコアと ID 順に戻り、履歴は順位に影響しない（検索中の決定論を保つ）。
- 履歴はアプリを閉じるまでのメモリ内にだけ持ち、ファイルへは書かない。ヘッドレスの候補生成には持ち込まない。

#### 9.7.7 候補一覧のスクロール

- 候補一覧を持つ重ね物（コマンドパレット・全体検索・資料検索・使用箇所一覧・昇格先選択）では、キーで選択を移したとき、選択行が見える位置までだけ一覧をスクロールさせる（最小移動。選択行を中央へ寄せたりはしない）。
- 一覧のスクロールバーは重ね物の枠の右端に寄せて置き、普段は細く目立たせず、ホバーまたはスクロール操作のときに見える形にする。

#### 9.8.4 衝突の確認

`Ctrl+1..3`（ペイン）と `Alt+1..9`（ワークスペース）と `Ctrl+Shift+1..9`（節維持切替）は衝突しない。
agent ワークスペースの `1`〜`4`（委譲レベル変更、§15.7.6）と `Ctrl+Shift+X`（総停止、§15.7.4）も、
修飾キーの有無でこれらと区別できるため衝突しない（MUST）。

**`Alt+←` / `Alt+→` の二重割当（解決規則、MUST）**: 既定は「前/次の場面へ」（§9.8.2）。
句切れ提案レイヤー（§9.4.3）が **有効** かつ **現在の節に候補が 1 件以上ある** ときのみ、候補移動が優先される。
候補が尽きた状態でさらに押すと、場面移動に戻る。レイヤーが無効なら常に場面移動。

IME 変換中（composing）はすべてのショートカットを無効化する（MUST、実装規約は §9.8.5）。`Alt` 系は macOS では `Option` が文字入力に使われるため、macOS では `Ctrl+Alt` に読み替える（MUST）。
`Ctrl+K Ctrl+0` は **2 ストローク**（`Ctrl+K` を押してから 2 秒以内に `Ctrl+0`）。2 秒を過ぎたら破棄する。
`Ctrl+0`（文字サイズ既定）とは、直前に `Ctrl+K` があったかどうかだけで区別する。

#### 9.8.5 IME 変換状態とフェイルセーフ規則（MUST）

1. **変換開始・更新・確定の追跡**: IME の変換開始（CompositionStart）および変換更新（CompositionUpdate）で「変換中」状態に入り、変換確定またはキャンセル（CompositionEnd）で「変換中」状態を解除する。
2. **変換中のキーイベント抑止（MUST）**: 「変換中」状態の間は、すべてのキーボードショートカット（§9.8.1〜§9.8.3）、`Enter` による節確定（§9.4）、および `Esc` によるモーダル閉じ（§9.6）を抑止する。変換候補の選択・確定・取消に使われるキーがエディタやシェルの操作として誤発火してはならない。
3. **フェイルセーフ解除（MUST）**: OS やブラウザによっては変換取消時に終了イベントが届かない場合があるため、以下のいずれかで「変換中」状態を自動的に解除する。
   - ウィンドウがフォーカスを失ったとき。
   - 最後の変換イベントから **2 秒** が経過し、かつその間にテキスト入力もキー入力も発生していないとき。
4. **変換候補ウィンドウの位置（MUST）**: 編集領域にフォーカスがある間、常に現在のキャレット矩形を OS / ブラウザの IME へ通知し、変換候補ウィンドウがキャレット直下に表示されるようにする。

#### 9.8.6 キー割当の統一とブラウザ・OS 非衝突化〔状態: 実装完了〕

- **ブラウザ・OS 予約キーとの非衝突化**: ブラウザや OS に奪われやすいショートカットには競合しない代替キーおよび画面上のボタン・パレット実行経路を用意する。 Web で `Ctrl+Shift+I`（開発者ツール）、`Ctrl+Shift+N`（シークレットウィンドウ）、`Ctrl+Shift+T`（タブ復元）、`Ctrl+Shift+W`（ウィンドウを閉じる）が優先される環境では、それぞれ `Ctrl+Alt+Shift+I/N/T/W` を代替キーとして使える。
- **一覧移動と確定移動の統一**: 全ワークスペースで「**一覧・タイムラインの選択移動は素の `↑` / `↓`、編集を確定して前後へ移動は `Alt+↑` / `Alt+↓`**」に統一する。素の `↑` / `↓` はエディタにフォーカスがあるときだけエディタが受け取り、それ以外のときはどの画面でも一覧・タイムラインに効かせる。
- **`Ctrl+3` と `Tab` の役割統一**: `Ctrl+3` は全画面共通で「参照ペインへフォーカス」の 1 つの意味に統一し、資料ワークスペース内の審査・メタデータフォーム等へのフォーカス移動は `Tab` / `Shift+Tab` に移す。
- **`Ctrl+O` の挙動統一**: デスクトップ版と Web 版の双方で、`Ctrl+O` は「現在の変更を保存してからプロジェクト選択画面（一覧・履歴）へ戻る」に統一し、一覧画面から「フォルダを開く」で選択する 2 段構成にする。

#### 9.8.7 キー案内のクリック実行

- ヘルプ（`?`）のキー一覧と、各画面の末尾に出るキー案内は、項目ごとに押せるボタンとして並べる。押すとそのキー操作をそのまま実行する。対象はこの 2 か所の案内だけであり、ホバーのツールチップやステータスバーの補完表示（§9.6）は押せるようにしない。
- 破壊的・確認付きの操作を案内から実行するときも、通常の確認経路をそのまま通る。ヘルプの中の項目を押したときは、ヘルプを閉じてから実行する。
- 案内の文言は項目単位に持ち、実際のキー割当（本節）と食い違わないことを機械的に検証できる形にする。

### 9.9 アクセシビリティ

- すべてのインタラクティブ要素は `Tab` 順に並び、OS の支援技術（アクセシビリティツリー）へ公開する（SHOULD）。
- アイコンのみの要素にはアクセシブル名（i18n 済み）を必ず付ける（MUST）。文字ラベルを消すことと、支援技術への情報提供は両立させる。

- 最小コントラスト比 4.5:1（本文）/ 3:1（12px 以上の補助テキストと図形）。

### 9.10 ガイドモード（はじめての手引き）

はじめて `novnow` を開いた人が、最初の 1 本を書き終えて書き出すまでを、アプリの中で案内するモード。

**自動で出る条件（MUST）**: 次のどちらかに当てはまるときだけ、ガイドモードを自動でオンにする。

| 版 | 条件 |
|---|---|
| Web 版 | 保存済みプロジェクトが 0 件である |
| デスクトップ版 | プロジェクト履歴が 0 件である |

- 一度でも閉じた（「あとで」または最後まで進んだ）ら、自動では出さない（MUST）。閉じたことは
  `.novnow/ui.json` の `guide_done` に保存する（MUST）。
- 自動で出るのは「保存済みプロジェクト 0 件」のときだけなので、プロジェクトを 1 件作れば以後は出ない。
  プロジェクトを 1 件も作らずに閉じた場合は保存先がまだ無く、次の起動でもう一度出る（MUST の例外）。

**手順（MUST）**: 公開サイトの「はじめての手引き」と同じ段階・同じ順序で示す。各段階は
「すること（1 文）」「操作（キーまたはボタン）」「次へ進む条件」を持つ。

| 段階 | すること | 次へ進む条件 |
|---|---|---|
| 1 | 作品を作る | 作品が 1 件できる |
| 2 | 画面の 3 つの領域を知る | 「次へ」を押す |
| 3 | 1 節目を書く | 節が 1 つ以上できる |
| 4 | `;` で 2 節目を作る | 節が 2 つ以上になる |
| 5 | 人物を登録して `'` で呼ぶ | `'` の参照が 1 つ以上できる |
| 6 | 話プロットを書く | 話プロットが空でなくなる |
| 7 | 読み返す（`Alt+7`） | 読者モードを開く |
| 8 | 書き出す | エクスポートが完了する |
| 9 | Zip で保管する | Zip の書き出しが完了する、または「あとで」 |

- 段階は**実際の操作**で進む（MUST）。「次へ」を押しただけでは進まない（2 と 9 を除く）。
- 先に操作を済ませてしまった段階は、条件を満たした時点で飛ばす（MUST）。

**見せ方（MUST / SHOULD）**

- 対象の部品の近くに、**矢印と吹き出し**を出す（MUST）。吹き出しの文は 1 段階 40 文字以内。
- 画面全体を暗くして操作を止めない（MUST）。対象だけを枠と矢印で指し、**入力を奪わない**
  （ガイド中も本文を書ける）。
- 吹き出しの位置は対象の矩形から決め、画面の端や他の吹き出しと重なるときは上下左右へ逃げる（SHOULD）。
- 「次へ」「戻る」「あとで閉じる」はキーボードだけで操作できる（MUST、§9.9）。`Alt+Enter`（次へ）・
  `Alt+Backspace`（戻る）・`Esc`（閉じる）を割り当てる。**`Enter` と `Backspace` そのものは横取りしない**
  （本文の改行と削除を奪わないため）。

**文言（MUST）**

- 日本語と英語の両方を用意する（§12）。
- 公開サイトの手引きと同一の文面を保つ（両者に差異があってはならない）。

**終了後**

- 最後の段階を終えたら、読み終えたことを伝え、ヘルプへの導線と「読者モードで読み返す」を出す（SHOULD）。

## 10. ワークスペース

ワークスペース = 用途別に最適化された画面構成。`Alt+1..9` で切替。切替時も **現在の SceneId は維持** する（MUST）。これにより「同じ場所を違う視点で見る」が成立する。

| # | ID | 名称(ja/en) | 主目的 |
|---|---|---|---|
| 1 | `write` | 本文 / Write | 本文執筆 |
| 2 | `plot-episode` | 話プロット / Episode | 話プロット（B 形式） |
| 3 | `plot-outline` | 構成 / Outline | 全体・章プロット（A 形式） |
| 4 | `idea` | アイデア / Ideas | 発想・保管・昇格 |
| 5 | `material` | 資料 / Materials | 収集・審査・参照 |
| 6 | `cast` | 配役 / Cast | キャラ・モード・役割語 |
| 7 | `reader` | 読者 / Reader | 読み返し（縦書き・注釈なし）※**追加仕様 27** |
| 8 | `agent` | エージェント / Agents | AI の管制 |
| 9 | `review` | 点検 / Review | 診断・進捗・伏線 |

### 10.0 切替の挙動

ワークスペースは「同じ場所を違う視点で見る」ための装置であり、**切替は思考を途切れさせてはならない**。

| 項目 | 規則（MUST） |
|---|---|
| `Alt+1..9` | ワークスペースを切り替える。**SceneId は維持**。各ワークスペースが最後に居たスクロール位置・フォーカス位置を復元する |
| `Ctrl+Shift+1..9` | **節位置を強制的に持ち越す**。切替先が最後に居た場所ではなく、**今いる節の対応物** に着地する |
| 切替の所要時間 | **16ms 以内**（1 フレーム）に描画が完了すること。ローディング表示・フェード・スライドを **出してはならない** |
| 事前計算 | 切替先の状態は常にメモリ上に保持する。ワークスペースの破棄・再構築をしない |
| 未保存 | 切替は保存のトリガーになる（§8.2 の「節位置変更」と同じ扱い）。確認ダイアログは出さない |
| `Alt+Tab` 相当 | `Ctrl+Tab` は **ファイル** の循環であってワークスペースではない。ワークスペースの「直前に戻る」は `Alt+0` |

**`Ctrl+Shift+1..9` での着地点（「対応物」の定義、固定表）**

| 現在 → 切替先 | 着地点 |
|---|---|
| `write` → `plot-episode` | 同じ SceneId の節ブロック。無ければ同じ場面の見出し |
| `write` → `plot-outline` | その節が属する **話** のブロック |
| `plot-episode` → `write` | 同じ SceneId の節。本文が無ければ空の節を作らず、その位置にカーソルだけ置く |
| `plot-outline` → `write` | その章/話の **最初の未完（`state != fixed`）の節**。無ければ最初の節 |
| 任意 → `cast` | 現在の節の `mode:` に出てくる **先頭のキャラ** |
| 任意 → `material` | 現在の節が参照している **先頭の資料**。無ければ条件一致候補の先頭 |
| 任意 → `reader` | 現在の節の先頭（読者モードのスクロール位置に変換） |
| 任意 → `review` | 現在の節に関する診断。無ければ診断一覧の先頭 |
| 任意 → `idea` / `agent` | 一覧の先頭（SceneId に対応物が無いため） |

**参照ペインの瞬時切替**

- `Ctrl+\` で参照ペインを隠す / 出す。隠したときメインカラムが即座に全幅になる（アニメーション無し、MUST）。
- `Ctrl+Shift+\` で左右を入れ替える。`.novnow/ui.json.reference_pane_side` に保存。
- 隠した状態でも参照情報の計算は **止めない**（出した瞬間に正しい内容が出ている必要があるため）。

#### 10.0.1 切替時の画面名 1 秒表示〔状態: 実装完了〕

#### 10.3.3 ストックタブ

|---|---|

| 原子性 | 上記をまとめて 1 操作として行う（§5.1.2、MUST）。途中失敗は全巻き戻し |

#### 10.3.4 分量タブ

話ごと・章ごとの長さの偏りを、**偏差値（T スコア）** で示す。

```
章 01   4話   28,400字   平均 7,100字
  01-01   6,200字   T 47  ▓▓▓▓▓▓▓░░░
  01-04   5,842字   T 45  ▓▓▓▓▓▓░░░░
  01-05   7,000字   T 52  ▓▓▓▓▓▓▓▓░░
  01-06  11,358字   T 68  ▓▓▓▓▓▓▓▓▓▓  ⚠ 長い
```

| 項目 | 定義（MUST） |
|---|---|
| 母集団 | **既定は「同一章の話」**。切替で「プロジェクト全体の話」「同一話の節」も選べる |
| 値 | 各単位の本文文字数（空白・アノテーション除外） |
| T スコア | `T = 50 + 10 × (x − 平均) / 標準偏差`（母集団標準偏差）。小数第 0 位に四捨五入 |
| 標準偏差 0 | 全単位が同じ長さのときは全員 `T 50` とする（0 除算回避、MUST） |
| 母集団サイズ | **3 未満のときは計算しない**（`—` と表示）。2 件の偏差値に意味が無いため |
| 閾値 | `T < 35` または `T > 65` で `⚠`。これが W091 |
| 未執筆 | 文字数 0 の単位は母集団から **除外**（書いていないだけで「短い」とは言わない、MUST） |

**思想上の注意**: 偏差値は「揃えるべき」という主張ではない。山場が長いのは当然である。
したがって `⚠` は **赤ではなく橙** とし、文言も「長い / 短い」であって「エラー」ではない。
`review` の診断一覧に出すのは既定で無効（§7.2）。

| 7 日 / 30 日平均 | 移動平均 |

**(b) キャラ別（追加仕様 25）**

| 指標 | 算法（MUST） |
|---|---|
| 台詞文字数 | 話者注釈で特定できた台詞の、鉤括弧内の文字数合計 |

| 話者不明 | 特定できなかった台詞は `（不明）` として 1 行で出す。**除外しない**（MUST。数字の総和が合うことが信頼の条件） |

**(c) 節長（追加仕様 25）**

| 指標 | 定義 |
|---|---|
| 分布 | 100 字刻みのヒストグラム |

**(d) 進捗の予測を出さない（MUST）**

「この調子だと完成は◯月◯日」のような予測・締切・目標達成率は **表示しない**。

統計は「過去に何をしたか」だけを示す。

## 12. 国際化

### 12.1 対象言語

`ja`（日本語）と `en`（English）の 2 言語を **同等にサポート**（MUST）。どちらかが「翻訳の劣化版」になってはならない。

### 12.2 ドメイン処理と表示文言の分離（MUST）

- ドメイン処理はユーザー向けの表示文言を直接持たず、診断コードと構造化引数のみを生成する。
- 表示文言への展開はすべて選択中の言語（`ja` / `en`）の文言カタログによって行う。
- CLI のメッセージも同じ文言カタログを使用する（§14.2）。
- **字句データは表示文言に含まない**: ファイル形式の語彙・記号（§5.0.2 のシジル文字 `「」`、§5.0.6 のフィールドキー日本語別名など）は UI 言語に依存せず（§12.6「UI 言語が `en` でも受理する」）、どの言語設定でも同一に解釈する。

### 12.3 カタログ

- 形式: 日本語（`ja`）と英語（`en`）の 2 つの文言カタログで管理する。
- キー命名: `<領域>.<対象>.<語>`。例: `status.unsaved`, `palette.hint.command`, `diag.E004`, `cli.error.incomplete`.
- プレースホルダ: `{0}`, `{1}`（位置引数のみ。名前付きは使わない）。
- **整合条件（MUST）**: 2 つのカタログのキー集合および各キーのプレースホルダ番号集合は完全に一致しなければならない。
- 欠落時のフォールバック: `en` → キー文字列そのもの、の順にフォールバックする。

#### 12.3.1 日本語テンプレート直後の助詞空白規則〔状態: 実装完了〕

- 日本語（`ja`）の文言では、`{0}はこの版ではまだ使えません` のように、プレースホルダ `{0}` 等の直後に助詞（「は」「が」「を」「に」「へ」「で」「と」「の」「も」等）が続くときは半角空白を入れない。この規則は自動テストで検査する。

### 12.4 言語の決定順序

1. `.novnow/ui.json` の `language`（`ja` / `en`）
2. `NOVNOW_LANG` 環境変数（CLI でも GUI でも有効）
3. OS / ブラウザのロケール（`ja*` → ja、それ以外 → en）
4. 既定 `ja`

切替は `Ctrl+Alt+L` と パレット `>language`。切替は **即時反映**、再起動不要（MUST）。

### 12.5 言語切替 UI

ヘッダ右端に 2 文字の記号ボタン（`あ` / `A`）。文字ラベル（「言語」「Language」）は置かない。
アクセシブル名には i18n 済みの「言語を切り替える / Switch language」を設定する。

### 12.6 翻訳しないもの

- プロジェクトの中身（本文・プロット・キャラ・資料・アイデア・プロンプト）は **決して自動翻訳しない**（MUST）。
- ファイル名・フィールドキーの正準形（ASCII）は言語に依存しない。
- 日本語別名フィールドキー（§5.0.6）は、UI 言語が `en` でも受理する。
