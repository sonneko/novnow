用語集

novnow の言葉は、仕様書とそろえています。ここでは言い換えずに、意味を足して説明します。

各項目の終わりのリンクから、仕様書のその節へ移れます。

書き物の単位

節

このアプリのいちばん小さい書き物の単位。1 つの場面の中の 1 区切りで、ふつうは数行〜十数行。

本文では、行全体が ; の行で区切られます。「1 節だけを見て書く」ことが、このアプリの中心の考え方です。

→ 仕様: 本文の構文 §5.2

場面

節をいくつかまとめた単位。@01-04-02 のように 3 つ組で表します。同じ場所・同じ時間の出来事です。

話

場面をまとめた単位。本文では 1 ファイル（01-04.cnov なら 1 章 4 話）。プロットは話ごとに 1 ファイルです。

章

話をまとめた単位。作品全体は「章 → 話 → 場面 → 節」の 4 段です。

→ 仕様: 構造 ID §4.1

プロット

これから書く内容のメモ。「作品全体の流れ」「章の流れ」「話の流れ」の 3 段があり、 本文の節と結びついて右の欄に出ます。

→ 仕様: プロット §5.3〜§5.4

人物と口調

モード

同じ人物の別の顔（普段の口調、怒ったとき、任務中のとき、など）に付けた名前。 場面ごとに「この場面ではこのモード」と指定できます。

→ 仕様: モード解決 §6.4

役割語

その人物らしい語尾や言い回し（「〜だぞ」「〜かしら」など）。台詞の口調が合っているかを その場で確かめられるようにするための決まりです。

→ 仕様: 役割語パターン §6.5

辞書参照（'）

'名前 と書いて、登録済みの人物・用語・資料を指すこと。

指された言葉は色が変わり、右の欄にその説明が出ます。登録が無いときは E001 が出ます（辞書にない参照）。

→ 仕様: 最短一致と正規化 §6.2

画面

ワークスペース

用途ごとの画面のこと。Alt+1〜Alt+9 で切り替えます。切り替えてもいまいる節は変わりません。

→ 仕様: ワークスペース §10

参照ペイン

本文画面の右側。いま書いている節に関わるプロット・人物・用語・資料・注意書きが自動で並びます。

→ 仕様: 参照ペイン §9.5

文脈ビュー

本文画面の上側。前後の節を読むための場所で、編集はできません。

→ 仕様: 文脈ビュー §9.3

読者モード（Alt+7）

記号を消して、縦書きで読み返す画面。ルビやしおりもここで扱います。

→ 仕様: 読者モード §17.3

注意と手助け

診断

書いた内容の気になるところを、その場で教えてくれる仕組み。全部で 85 種類あり、 それぞれに E001 のようなコード（識別子）が付いています。赤い波線は「直したほうがよい」、 黄色は「確認してほしい」、青は「知らせておく」の意味です。

→ 仕様: 診断カタログ §7

クイックフィックス

波線の上で Ctrl+. を押すと出る「その場で直す」選択肢。

→ 仕様: コードアクション §9.4

点検（Alt+9）

作品全体をまとめて調べる画面。エラーの一覧、進み具合、伏線の置き忘れなどを確認します。

→ 仕様: 点検 §10.9

AI と外部連携

エージェント

AI に手伝ってもらう仕組み。7 つの役割（本文・プロット・アイデア・調査・文体・論理・統合）があります。

→ 仕様: エージェント §15

委譲レベル

AI にどこまで任せるかの 4 段階。off（頼まない）/ propose（案を出すだけ）/ apply（承認したら反映）/ autonomous（任せる）。既定は提案までで、勝手に本文は変わりません。

→ 仕様: 委譲レベル §15.1

提案

AI が出した変更案。本文に反映する前に、どこがどう変わるかを差分で確認できます。

→ 仕様: 変更提案 §8.7

保存と持ち出し

エクスポート

記号（@ や '）を取り除いて、ふつうの文章として書き出すこと。.txt と .md が選べます。

→ 仕様: エクスポート §17

Zip 書き出し / 読み込み

作品まるごとを 1 つのファイルにまとめること。ブラウザ版のバックアップはこれを使います。

→ 仕様: Zip §13.5

IndexedDB

ブラウザ版が作品を保存する場所。ブラウザの中にあり、外のフォルダは使いません。

→ 仕様: Web の保存 §13.3
