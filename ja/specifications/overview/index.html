novnow 仕様書 — 概要・原則・処理モデル

1. 設計原則

README に現れる作者の思想を、実装判断に使える規則へ落としたもの。迷ったらこの章に戻る。

P1. 1 節が世界の単位である

IDE のあらゆる機能（表示・保存・診断・AI タスク・エクスポート範囲・検索結果）は 節（SceneId の第 4 階層） を既定の単位とする。 節より大きい単位を扱う機能は、必ず「節の集合」として実装する。

P2. ワーキングメモリを IDE が肩代わりする

人間が覚えていなくてよいものは画面に出す。出すものは「今の節に必要なもの」だけに絞る。 → モードの性格は 有効なモードだけ 表示する（他モードは隠す）。用語は 今の節に出現するもの を先頭に置く。

P3. キーボードで完結する

マウス操作は常に代替キーボード操作を持つ（MUST）。 逆に、キーボードだけで到達できない機能を作ってはならない。

P4. 決定論

同じ入力からは常に同じ表示・同じ診断・同じコンテキストが得られる。 曖昧検索のスコアリング、辞書一致、コンテキスト切り詰めは、すべて順序まで決定論的に定義する（§6.2, §16.3, §15.4）。

診断や分かち書きに使う部品は、実行時に乱数を必要としないものに限る（「確率・統計モデル」とは実行時に乱数を必要とするものを指す）。学習済みの部品を使う場合でも、中身を人間が把握できる規模の小さな固定モデルだけを許容し、全員へ同じ学習結果を配布する。実行中に学習して人ごとに変わる部品は持たない。

P5. AI に何を任せるかは人間が決め、その範囲で AI は自律に動く

README の明文に従う。LLM による自律作業は 一切否定しない。執筆計画の管理だけを AI に任せることも、 本文やプロットは自分で書いてアイデアだけを AI に量産させることも、小説ひとつ丸ごとを AI に作らせることも、 全く任せない ことも、すべてできる。この思想の核心は 「LLM に何を任せ、何を人間がするか」をユーザーが指定できること であり、 人間の創作性は「AI を使わないこと」で担保するのではなく、任せる範囲を自分で決め、その結果に責任を持てること で担保する。 「あなたは、あなたのするべきことをするだけ」である。

したがって:

  • 委譲レベル（delegation） — 役割ごとに「どこまで AI を自律させるか」をユーザーが設定する（MUST、§15.1.1）。 既定は安全側（提案のみ・人間が採否）だが、ユーザーはいつでも全委譲（直接書込・連鎖・自律実行）に切り替えられる（MUST）。
  • novnow が ユーザーの設定なしに 委譲範囲を広げることはない（MUST）。範囲の変更はすべて監査ログ（§5.10.5）に残る。
  • 自律させた場合でも、上限（タスク数・連鎖数・文字数）と停止手段は必ず人間が握る（MUST、§15.1.1 A8、§15.7.4）。 創作性の担保は禁止ではなく、「止められること・戻せること・いつでも見られること」 で行う。

P6. プロジェクトは自己完結する

プロジェクトディレクトリをコピーすれば、プロンプトも資料も設定も丸ごと移動する。 プロジェクト外に出てよい情報は プロジェクトディレクトリパスの履歴のみ（§13.1）。 例外は、ユーザーが書き出し先を明示したエクスポートと、配布物の取得専用領域に限定する（§13.1.1）。

P7. ドメインは UI を知らない

小説管理のドメインロジックは特定の画面フレームワークやストレージ実装に依存しない純粋な規則として定義する（§3）。

3. アーキテクチャと処理モデル

3.1 層と責務の分離

novnow は「ドメイン規則」「入出力境界」「環境固有の入出力」「ユーザーインターフェース」の 4 つの責務を厳格に分離する。 小説管理のドメイン規則は画面表示やストレージの種別（デスクトップのファイルシステム / Web のブラウザ内ストレージ）に依存せず、同一の入力に対して常に同一の解析結果・診断・コンテキスト・エクスポート出力を返す（MUST）。

3.2 ドメイン純粋性と外部隔離規則

ドメイン処理は次の外部要素に一切依存してはならない（MUST）。

  • 画面フレームワーク・ダイアログ・クリップボード
  • ファイルシステム・ネットワーク・サブプロセスなどの直接入出力
  • ブラウザ API・OS 固有 API
  • スレッド・非同期ランタイム
  • グローバルな現在時刻・乱数

文字の正規化（NFKC）やパターン照合はすべて純粋な決定論的変換として定義し、実行環境や OS ロケールによって結果が変化してはならない（MUST）。

打鍵入力
