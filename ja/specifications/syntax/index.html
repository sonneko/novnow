5. ファイル形式（構文仕様）

5.0 共通字句規則

すべての novnow テキスト形式（contents/*.cnov, plots/*.cnov, *.md）に共通。

5.0.1 行指向の原則（MUST）

複数行にまたがるトークンは存在しない。 1 行は常に単独で字句解析できる。 これはインクリメンタル再解析（編集行のみ再解析）と LSP 化の前提であり、v0.1.0 でも維持する。

行頭シジルの優先順位（固定）: @ → ; → # → ! → // → フィールド行 → 通常テキスト。 # と ! は 直後に半角または全角の空白が必要（#1 位 や !? を誤認しないため、MUST）。

:// は行内コメントにしない（MUST）: 行内の // の直前が : のときは、URL の scheme 区切り（https://example.com、フィールド値の source:https://…）なのでコメントの始めにしない。 直前が : でなければ、その // から行末までがコメント。回避にはエスケープ \/（§5.0.3）も使える。 この判定は行内で完結する（§5.0.1）。

5.0.3 エスケープ

\@ \' \; \/ \「 \」 \\ \# \! \^ のみ有効。それ以外の \x は \x の 2 文字としてそのまま扱う（診断なし）。 エクスポート時にエスケープは解除される（§17.1）。

5.0.4 改行・符号化・正規化

  • 読み込み: UTF-8。BOM があれば剥がして読み、保存時は付けない（MUST）。改行 LF / CRLF / CR を受理し、内部表現は LF。
  • 保存: project.toml の newline に従う。既定 LF、BOM なし。
  • 行末の半角/全角空白は保存時に削除（MUST）。ただし行頭のインデントは保持する。
  • ファイル末尾は必ず改行 1 個で終える（MUST）。ただし空の文書は空のまま保存する（改行 1 個を強制すると「空の 1 行」が増え、読み込み → 保存の往復で文書が変わってしまうため。MUST の例外）。 改行だけの文書も空として扱う。
  • Unicode 正規化は行わない（作家の入力を変えないため）。ただし 辞書照合時のみ NFKC 相当の比較を行う（§6.1.3）。

5.0.5 フィールド行

field_line   = ws? field_key ws? (":" | "：") field_value ;
field_value  = ws value | ws | ε ;   (* ε は行末。手順 4・5 の場合は ws 無しでもよい *)
field_key    = ascii_key | ja_alias ;
ascii_key    = /[a-z][a-z0-9-]{0,23}/ ;

判定は行内で完結する（§5.0.1）。次の手順で決める。

  1. 行頭のインデントが 2 文字以上の空白（半角・全角）または 1 文字以上のタブなら継続行であり、フィールド行ではない（下の「継続行」参照）。
  2. 最初のコロン（半角 : または全角 ：）の直前までを key 候補とし、末尾の空白を除く。 コロンが無ければフィールド行ではない。コロンが複数あれば最初のもので切る（値にコロンが残ってよい）。
  3. key 候補が field_key（ascii_key の形、または §5.0.6 の表にある日本語別名）でなければ フィールド行ではない。§5.0.6 の表に無い日本語（注：これは本文 のような散文）はここで通常テキストになる。
  4. コロンが全角 ： なら、直後の空白を問わずフィールド行（日本語の自然な書き方 要約：あらすじ を受けるため）。
  5. コロンが半角 : のとき:
    • 直後に空白（半角・全角・タブ）があるか、行末ならフィールド行。
    • 直後に空白がなくても、key が §5.0.6 の表にあるキー（正準形または別名）ならフィールド行 （summary:一行 mode:B source:https://example.com を救う）。
    • それ以外は通常テキスト。
  6. 値は前後の空白を除いて保持する。key: / key： だけの行は空の値のフィールド行 （§5.0.4 が行末の空白を削除する MUST と両立させるため、ws は行末でも満たされると読む）。
  7. §5.0.6 の表に無い ascii_key でフィールド行になったものは W011（未知のキー）とし、値は改変せず保持する。

URL 判定は除外リストを持たない（MUST）: 手順 5 が「表に無い ascii キーは空白なしではフィールド行に しない」ため、http://example.com・https://…・mailto:foo@example.com・doi:10.1000/xyz・ isbn:978-…・tel:090-…・file:///tmp/x・C:\Users\x・10:30 は自動的に本文のまま残る （http doi 10 などは §5.0.6 の表に無いので手順 3・5 で落ちる）。逆に、表にあるキーの値に URL を 書くのは正当（source:https://example.com）なので、値の中身は検査しない。

不変条件（MUST）: §5.0.6 の ascii_key は URL scheme および本文中に書かれがちな接頭辞と 衝突してはならない（http https ftp file mailto data tel urn ssh git svn s3 news doi isbn arxiv pmid javascript about blob 等）。表に scheme と同名のキーを足してはならず、キー表と URI スキーム列挙の非交差を維持する（MUST）。

  • ascii_key が正準形。日本語別名は §5.0.6 の表にある語のみ受理し、保存時に正準形へ正規化しない（作家の表記を保つ）。
  • 値は 1 行。複数行が必要な場合は継続行として 2 文字以上の空白（半角・全角）または 1 文字以上のタブによるインデント を用いる。 継続行の先頭インデント（先頭がタブなら 1 文字、それ以外の空白なら 2 文字）は値から剥がす。
summary: 一行目
  二行目（継続行）

5.0.7 コメントと「アノテーション」の定義

エクスポート（§17）で除去される「アノテーション」とは、次の 9 種を指す（固定）。

  1. 構造見出し行（@A-B-C[-D] ...）
  2. 行末話者注釈（@キャラ名[:モード]）
  3. 参照シジル ' と修飾子（:モード / :タイトル）。表示名そのものは残す
  4. 節区切り ;
  5. 行コメント //...、行内コメント /* ... */
  6. 行頭コメント行 # ...（§5.0.8）
  7. 行末の資料引用注釈 ^M0137（§5.2.4）
  8. 挿絵メモ行 ! ...（§5.2.5）
  9. フィールド行（A/B 形式のみ。本文には現れない）

5.0.8 # 行コメント

hash_comment = ws? , "#" , (" " | "　") , any* , eol ;
  • .cnov（A / B / C 形式）でのみ有効。.md ファイル（characters.md 等）では # は従来どおり見出しであり、コメントにならない（MUST）。
  • 行頭のみ。行の途中の # はただの文字。
  • 複数行コメントは存在しない（1 行 1 コメント、MUST）。
  • // との使い分けは利用者の自由。novnow はどちらも同じ comment トークンとして扱い、相互変換もしない。
  • 用途の想定: 執筆中の自分宛てメモ（「ここは後で直す。リリアの心情が不自然」）。
# ここは後で直す。リリアの心情が不自然。
「……付き合ってあげるわよ」@リリア:B

5.0.9 文書として認識する範囲

novnow が文書として読み、解析し、書き戻すのは、置き場所と拡張子の組が仕様の定義に一致するファイルだけである。

  • contents/<章>-<話>.cnov は本文（C 形式）、plots/all.cnov と plots/<章>.cnov はアウトライン（A 形式）、plots/<章>-<話>.cnov は話プロット（B 形式）。形式は拡張子単体では決まらず、置き場所とファイル名の形との組で決まる。
  • 名前がこの形に一致しないファイルは文書として認識しない。contents/ にあっても拡張子が .cnov でないファイルや、章・話の番号の形に合わない .cnov がそうである。認識しないファイルは解析も書き戻しもせず、§4.3 のとおり未知のファイルとして触れない。
  • .cnov は A / B / C の 3 形式で使う novnow 専用の拡張子であり、中身は通常の UTF-8 テキストである。

5.1 SceneId と範囲式

scene_id      = num , "-" , num , "-" , num , [ "-" , num ] ;
partial_id    = num , [ "-" , num , [ "-" , num , [ "-" , num ] ] ] ;
num           = /\d{1,4}/ ;                   (* 表示は project.toml の桁数でゼロ詰め *)
range_expr    = range_term , { "," , ws , range_term } ;
range_term    = ( "@" partial_id , ws? , ".." , ws? , [ "@" partial_id ] )
              | ( ".." , ws? , "@" partial_id )
              | ( "@" partial_id ) ;

意味論:

  • @01-04-02-03 は節、@01-04-02 は場面全体（section = 0 を「場面全体」の意味で用いる。v0 と同じ）。
  • @01-04 .. @02-01 は 閉区間。比較は (chapter, episode, scene, section) の辞書式順序。 左辺の省略階層は最小値（0）、右辺の省略階層は最大値（9999）に展開される。 例: @01 .. @02 ⇒ 01-00-00-00 .. 02-9999-9999-9999。
  • @03-01 .. は上端開放、.. @01-03 は下端開放。
  • カンマ区切りで複数区間の和集合。
  • 境界検査: 区間の左端 > 右端 のときは E016。

表示（SceneId::display）: section == 0 のときは 3 階層表示、それ以外は 4 階層。いずれも project.toml の structure.*_digits でゼロ詰め。

5.1.1 階層ごとの役割（再掲）

A 章 / B 話 / C 場面 / D 節。

5.1.2 予約番号 00（v0.1.0 追加仕様 17・22）

00 は階層ごとに固有の意味を持つ。番号としては正当な値であり、パースを拒否しない（MUST）。

位置 意味 ファイル 備考
A = 00 未配属ストック章 contents/00-01.cnov, plots/00.cnov, plots/00-01.cnov 章番号を決めていない話の仮置き場。UI 表示名は「未分類ストック」。structure.allow_chapter_zero = false にすると E022 で拒否
B = 00 章あらすじ contents/01-00.cnov, plots/01.cnov 内の @01-00 ブロック 読者向けの短いあらすじ。blurb: フィールドを持つ（§5.3.2）
C = 00 予約（未使用） — v0.1.0 では書いてはならない（E022）
D = 00 場面全体 — 既存仕様（見出しで D を省略した状態）
  • 予約番号を拒否する診断は E022。
  • @00-01-02-03 は正当な SceneId（ストック章の 1 話 2 場面 3 節）。
  • @01-00 は正当な PartialSceneId（1 章のあらすじ）。@01-00-01-01 のように下位を付けることもできる（あらすじを節に分けて書く場合）。
  • 範囲式での扱いは通常の番号と同じ（@00 .. @01 は「ストック章と 1 章」を意味する）。
  • ソート順は数値順のため、ストック章（00）は常に先頭、章あらすじ（B=00）は章の先頭に来る。

ストックから正式な章への移動（§10.3.3）は、ファイル名のリネームと本文・プロット内の SceneId 一括置換を 1 つの操作として原子的に 行う（途中失敗時は全て巻き戻す、MUST）。

5.2 本文形式（C 形式）— contents/AA-BB.cnov

5.2.1 文法

content_file  = { line } ;
line          = scene_header | section_break | comment_line | illust_line | blank | text_line ;

scene_header  = ws? , "@" , scene_id , [ ws , title_text ] , [ comment ] , eol ;
section_break = ws? , ";" , [ comment ] , eol ;
comment_line  = ws? , ( "//" | "#" ws1 ) , any* , eol ;
illust_line   = ws? , "!" , ws1 , any* , eol ;
blank         = ws? , eol ;
text_line     = inline+ , [ citation* ] , [ speaker_annot ] , [ comment ] , eol ;

inline        = dialogue | ref | ruby | escaped | plain ;
dialogue      = "「" , inline* , "」" | "『" , inline* , "』" ;
ref           = "'" , ( ref_name | "{" , ref_name , "}" ) , [ ":" , modifier ] ;
ruby          = "｜" , base , "《" , reading , "》" | kanji_run , "《" , reading , "》" ;
citation      = ws* , "^" , material_id ;                            (* 行末側 *)
speaker_annot = ws* , "@" , char_name , [ ":" , mode_expr ] , ws* ;   (* 行末のみ *)
mode_expr     = mode_id , [ "+" , mode_id ] ;
ws1           = " " | "　" ;

char_name（話者注釈、' 参照、address: の相手）は、空白（半角空白・全角空白・タブ）と : を含まない 1 文字以上とする。 : を含む @… は、: の後ろが mode_expr として読めない限り話者注釈にならない（W002）。

5.2.2 節の確定規則（MUST）

  • 場面見出し @A-B-C の直後から最初の ; までが節 D=1。以降 ; ごとに D が 1 ずつ増える。
  • 見出しに D が明示されている（@01-04-02-03）場合、その見出し直後の節番号を D から開始する（部分ファイル・差し込み用）。
  • 節の末尾の空行は節の内容に含めない。
  • ; が連続した場合、空の節が生成される（診断 W012「空の節」）。
  • ファイル先頭の場面見出しより前の行はどの節にも属さない。見出しより前の ; も節を作らない。
  • ファイル末尾で、最後の ; の後ろに本文（空行以外）が無ければ節を作らない（; や改行で終わるファイルに空の節を足さない。W012 も出さない）。

5.2.4 資料引用注釈 ^

本文の行が、どの資料に基づいて書かれたかを示す。

citation = "^" , ( "M" | "S" ) , /\d{4,}/ ;
規則 内容
位置 行末側。speaker_annot より 前。複数並べられる（^M0137 ^M0021）
連続性 行末（行末コメントの手前）から遡って、空白区切りで並ぶものだけが注釈。注釈の後ろに本文が続くものは注釈ではない（^M0137 の話 の ^M0137 は注釈）
桁数 4 桁以上（M0137。9999 を超えると桁が増える、§5.8.2）
打ち消し 直前の \ が奇数個なら注釈にしない。行内コメント /* … */ の中も注釈にしない
範囲 除去・文字数の対象は ^ から ID の末尾まで。直前の空白も注釈の一部として扱う
スコープ その 1 行。段落や節には掛からない

5.3.5 作中日時式 when:

現実の暦ではなく 作中世界の時間 を書くためのフィールド。異世界の独自暦を許すため、 novnow は暦を解釈しない。解釈するのは「順序」だけである（MUST）。

when_value   = timepoint , [ ws? , ".." , ws? , timepoint ] , [ ws , free_text ] ;
timepoint    = ordinal_key , [ ws , clock ] ;
ordinal_key  = /[-+]?\d+(\.\d+)?/ , [ unit_label ]      (* 例: 0, 12, 405.5, -3 *)
             | "?" ;                                     (* 時系列不明 *)
unit_label   = /[^\s:]{1,12}/ ;                          (* 日 / 年 / 刻 / Day など *)
clock        = /\d{1,2}:\d{2}/ ;
規則 内容
正本 ordinal_key の数値だけが順序を決める。unit_label と free_text は人間向けの表示
単位 プロジェクト全体で 1 つの単位系を暗黙に使う。novnow は単位名を検査しない（日 と 年 が混在しても無視）
時刻 clock は ordinal_key 内の副順序。12 08:30 は 12 09:00 より前
範囲 12 .. 14 は「12 から 14 にかけて」。順序比較には 開始値 を使う
不明 ? はタイムラインで「順序未定」の帯に置く。矛盾検出の対象外
継承 下位階層が when を持たないとき、上位の when を継承する（章 → 話 → 場面 → 節）
相対 先頭が + のとき、直前の同階層ブロックの値への加算（+1 = 翌日）。- も同様 
when: 405.0 春分  09:15        … 405 日目の 9 時 15 分、表示は「405 春分 09:15」
when: +1 翌朝                   … 直前のブロック +1
when: 12 .. 14 三日間の合宿
when: ? 回想（時期不明）

時系列矛盾の検出: 本文の節順（SceneId 昇順）に対し when が巻き戻る箇所を W080 で通知する（§7.2）。 ただし 回想は正当な技法 なので、次のいずれかがあれば警告しない（MUST）。

  • when の free_text に 回想 / 過去 / flashback のいずれかを含む
  • 同ブロックに note: 回想 がある
  • when: ?

5.5 characters.md

5.5.1 設計方針

  • 人間が直接書く情報は MD（読み書きしやすい）。機械が採番・管理する情報は JSON（materials/index.json のみ）。
  • 曖昧さのない MD とするため、意味を持つのは次の 4 種類の行だけに限定する:
    1. # 見出し（H1 = キャラ、H2 = セクション、H3 = モード）
    2. フィールド行 key: value（§5.0.5）
    3. 箇条書き - ...
    4. 鉤括弧行 「...」（役割語パターン、§5.5.5） それ以外の行は、直前のフィールド／セクションに属する自由記述（note 相当）として保持される。
  • MD ビューアで読めること（GitHub 上で読めること）を MUST とする。

5.5.2 文法

characters_md = [ file_preamble ] , { character } ;
character     = "# " , char_name , eol , { field_line | section } ;
section       = "## " , section_key , eol , section_body ;
section_key   = "modes" | "attributes" | "tone" | "relations" | "notes"
              | "モード" | "口調" | "関係" | "メモ" ;   (* §5.0.6 の別名のうち対応する 4 語 *)
section_body  = { field_line | bullet | pattern_line | free_line | blank | comment_line } ;
mode_def      = "### " , mode_id , [ ws , mode_label ] , eol , { field_line | pattern_line | free_line } ;
mode_id       = /[A-Za-z][A-Za-z0-9_]{0,15}/ ;
pattern_line  = ws? , "「" , pattern , "」" , { ws? , "「" , pattern , "」" } , eol ;

section_key の日本語表記は、§5.0.6 の別名のうちセクションとして意味が対応する 4 語（モード 口調 関係 メモ）だけを受ける。 これ以外の ## …（## 性格 など）は見出しとして保持するが、5 種のセクションとしては扱わない（中の行は自由記述として残り、失われない）。

寸法 長辺 256px 以下を推奨。ヘッダから読める寸法の長辺が 256px を超える値は W069。表示は 256×256 に縮小する
ファイルサイズ 1 ファイル 256KB 超は中身を保持せず（§4.1 の assets/ の扱い）、W069
表示箇所 参照ペインの配役見出しの左に 16×16、キャラ一覧（§10.4）に 32×32。本文エディタ内には出さない（MUST）
Web 版 assets/ は IndexedDB に入るため動作する。ただし Zip 入出力（§13.5）に含める
欠損 ファイルが無くてもエラーにしない。アイコン無しで表示し W070
非目標 アイコンの編集・切り抜き・生成はしない（MUST）

W069 の判定（実装の詳細）: 次のいずれかで出す。中身が 0 byte、256KB を超えて保持しなかった、ヘッダから読めた長辺が 256px 超。寸法は PNG / JPEG のヘッダだけで読み、復号はしない。表示では PNG / JPEG と判定できたものだけを復号し、画素数の積が 16,000,000 を超える画像は描かない（メモリ保護）。ファイルがプロジェクトに無ければ W070（§5.5.3 の表）。一覧にあるが中身を読めなかった場合は診断を出さず、アイコン無しで表示する。

設計上の位置づけ: これは「顔を思い出すための備忘」であり、装飾ではない。 P3（ノイズを増やさない）に反しないよう、表示は常に小さく、文字情報より目立ってはならない（MUST）。 icon を 1 件も定義していないプロジェクトでは、アイコン用の余白を取ってはならない。

5.5.4 ## modes

  • ### <mode_id> <表示名> ごとに 1 モード。
  • モード内フィールド: range, personality, emotion, role, note、および役割語パターン行。
  • 同一 mode_id を複数回定義してよい。ただし range が重ならないこと（重なれば E017）。 これにより「章が進むにつれモードの性格が少しずつ変化する」を表現できる。
  • range 省略時は全範囲（@00 ..）。

5.5.5 役割語パターン行

  • 1 行に複数パターンを並べてよい。1 パターン = 「 と 」 に囲まれた文字列。
  • ## tone 直下に置けばキャラ共通、### <mode> 直下に置けばそのモード専用。
  • モード専用パターンがある場合、そのモードが有効な節では モード専用 ∪ キャラ共通 を使う。
  • パターン言語の意味論は §6.5 / 付録 B。
