novnow 仕様書 — 資料収集・エクスポート・性能品質

16. 資料収集機能

16.1 ワークフロー

  収集（人間 or researcher）
        │  materials/inbox/M####.md + index(status=proposed)
        ▼
  審査（人間・material ワークスペース）
        │  タイトル / カテゴリ / conditions / summary を整える
        ▼
  採用  → materials/docs/ へ移動、status=approved
  却下  → status=rejected（ファイルは inbox に残す。ID は回収しない）

これは委譲レベル propose（既定）の流れである。apply / autonomous では researcher の収集物は 自動で採用され、上の審査は事後確認になる（§15.1.1、§16.7）。

16.1.1 新規資料作成操作の全域有効化とボタン化〔状態: 実装完了〕

  • material ワークスペースでの Ctrl+Shift+N（新しい資料）は左一覧にフォーカスがあるときだけでなくワークスペース内のどこにフォーカスがあっても機能し、画面上のボタンからも実行できる。

16.1.2 URL からの本文取得〔廃止〕

  • 素材の source: の URL から本文を取りに行く機能は廃止した（v1 では行わない、ではなく、仕様から外す）。 novnow はネットワークから素材を取得しない。素材の本文は利用者が materials/inbox/ に置くか、 materials.propose の markdown で渡す。source: は出所の記録としてだけ残す（取得には使わない）。
  • 採用（materials.approve）は inbox/ から docs/ への移動と索引の更新だけを行う（§16.2）。
  • 判断の理由: 取得の口（ホワイトリスト・上限・タイムアウト・失敗時の扱い）を仕様に持つ割に、 利用者の手元（ブラウザのコピー、PDF、メモ）から本文を持ち込む経路の方が実際の使い方に合っていた。 依存（HTTP クライアント）とセキュリティ面（SSRF・巨大ファイル）の検討も要らない。

16.2 インデックス（§5.8.2 の運用規則）

  • index.json が 唯一の正本。MD ファイルを手で足しただけでは資料として認識しない（W064 で「未登録の MD がある」と通知し、ワンクリックで登録できる）。 登録は material ワークスペースでその MD を選んで Ctrl+Enter: 新しい ID を振り、H1（無ければファイル名）をタイトルに、docs/ の下なら approved・それ以外は proposed で索引に足し、MD に ID のコメント（<!-- novnow:M0137 -->）を入れる。
  • ID 採番は next_id を用いた単調増加（§5.8.2）。
  • 並べ替え・絞り込みは UI 側の表示順であり、items 配列の順序は 追加順を保つ（差分を読みやすくするため、MUST）。

16.3 検索 UX

Ctrl+M で開くパレット。クエリは次のトークンの組み合わせ（空白区切り、AND）。

トークン 意味 例
素のテキスト タイトル・summary・本文・タグのあいまい一致 甲子園 運営
#カテゴリ カテゴリ完全一致 #取材
@範囲 conditions.scope が交差 @02-03
'参照 conditions.ref が一致 '科学の甲子園
M数字 / S数字 ID 前方一致 M01, S00
!status ステータス !proposed
~日付 saved_at の範囲 ~2026-10
  • 素のテキストは §6.1.3 の正規化と小文字化をしてから部分一致を見る。重みはタイトル 4・タグ 3・summary 2・本文 1（語ごとに 最も重い 1 つ）で、スコアはその和。!status の語が無いときは却下（rejected）を出さない。
  • 既定の並び: スコア降順 → saved_at 降順 → ID 昇順（決定論）。
  • 各行の表示: M0137 科学の甲子園 本戦の運営と実技課題 #取材 2026-10-01。選択行の下に summary と出典を 2 行で展開。
  • Enter: カーソル位置に 'M0137 を挿入。Shift+Enter: 資料 MD を開く。Ctrl+Enter: 新規資料を作成してその ID を挿入。 挿入先はワークスペースで決まる: write はキャレット、plot-episode は選んでいる節の最後に material: 'M0137 の行、idea / plot-outline / cast はエディタのキャレット。material / review では挿入せずに資料を開く。もう一度 Ctrl+M で閉じる。
  • ID を覚えていなくても良いことを保証する: タイトル・カテゴリ・条件・本文のどれからでも辿り着けること（MUST）。

16.3.1 検索結果の資料化

正規表現検索（§9.7.4）の結果 を、そのまま 1 件の資料として凍結保存する。画面では一致範囲を強調して描くが、保存する MD では次に定める固定の形（一致を **…** で囲む）で組み立てる。

目的: 「『あの指輪』が出てくる箇所を全部探した」という 調査の成果 を捨てずに残す。 次に同じことを調べ直さなくて済む。

操作 内容
起動 正規表現検索の結果画面で Ctrl+Shift+S（「この検索結果を資料にする」）
入力 タイトル（既定はクエリ文字列）と、任意の summary
採番 S####（M と連番共有、§5.8.2）
本体 materials/docs/S0042-<slug>.md を生成
index materials/index.json に 1 件追記。category: "検索結果"、status: "approved"、added_by: "human"
通知 なし（資料一覧に新しい行が現れる。I058 は廃止したので診断・トーストは出さない）

生成される MD の形（固定）

# 「指輪」を含む箇所
<!-- novnow:S0042 -->

query: 指輪
regex: false
case_sensitive: true
searched_at: 2026-10-09T21:40:12+09:00
hits: 14

## 結果

- @01-04-02-03 … 銀の**指輪**を外して机に置いた。
- @02-01-01-01 … 母の**指輪**はもう手元に無い。
- @05-03-02-02 … **指輪**の内側に刻まれた文字。
規則 内容（MUST）
凍結 保存した時点の結果をそのまま持つ。本文が変わっても自動更新しない
再実行 資料詳細画面の [再検索] で同じクエリを走らせ、差分を表示 する（新規ヒット / 消えたヒット）。更新するかは人間が決める
引用の長さ 1 ヒットにつき前後 20 字。全文は保存しない（本文の複製を作らないため）
ヒット数上限 500 件。超えたら先頭 500 件を保存し、hits に実数を書いて「500 件まで保存」と註記する
source.kind "search"。{"kind":"search","query":"指輪","regex":false,"searched_at":"…"}
参照 'S0042 として本文・プロットから参照できる。インレイヒントにはタイトルが出る
削除 通常の資料と同じ。ID は回収しない

非目標: 保存した検索を「生きたクエリ」として常時再評価する機能は作らない（MUST）。 常時再評価は、本文を書き換えるたびに全文検索が走ることを意味し、P2（執筆を妨げない）に反する。

16.4 「必要になる条件」と自動提示

conditions の 4 種:

kind 値 一致判定
scope 範囲式 現在の SceneId が範囲に含まれる
ref '名前 現在の節に当該参照が出現する
tag 文字列 現在の節のプロットに同じタグがある
text 自由文 機械判定しない（人間とエージェントが読む）
  • 参照ペインの「資料」欄は 明示参照 を先に、続けて 条件一致した候補 を薄い色で並べる。 候補は「まだ参照していないが、今必要かもしれない資料」であり、Enter でプロットに material: として追記できる。 明示参照は本文の参照と、話プロットの場面見出しの行・節の material:。候補にするのは採用済み（approved）の資料だけで、tag は 話プロット（B 形式）の tags: / タグ: の値と比べる。候補はダブルクリックか Ctrl+3 → Enter で、話プロットのその節の最後に material: の行として足す。
  • researcher のコンテキストには、条件一致した資料も含める（§15.4.1 の 7 materials）。

16.5 プロットからの参照と表示

§6.6 のとおり。要点を再掲する。

  • プロットには 数字 ID を書く。タイトルは インレイヒントで表示される（ファイルには書かれない）。
  • タイトルを明示的に書くこともできる（'M0137:タイトル）。
  • 明示タイトルが ID と食い違えば 赤波線（E006）、クイックフィックスで ID からタイトルを補完・提案する。

16.5.1 要約の「続き…」表示と URL 外部リンク〔状態: 実装完了〕

  • 参照ペインで資料の要約が上限により途中で切れる場合は「続き...」の 1 行を表示する。
  • 資料ビュワーおよび参照表示に URL が含まれる場合は、外部リンクアイコンと薄い黒のアンダーライン＋ホバー時青色を付け、クリックでその URL を開けるようにする。

16.6 資料 MD の編集

  • material ワークスペースの中央ペインで直接編集できる（MD のプレビューは出さない。素の MD を見せる）。
  • 保存は §8 と同じ自動保存。
  • 保存のたびに checksum を更新し、updated_at を書き換える。checksum は sha256: ＋ 本文（UTF-8）の SHA-256 の 16 進。

16.7 エージェントとの連携

  • researcher は novnow.materials.propose 相当の提案を作る。委譲レベル propose では 人間の採用操作なしに approved にはならない（A2）。 apply / autonomous では自動で approved になり、監査ログに auto_applied が残る
  • 出典のない提案は自動的に W065（「出典が無い資料」）を付け、採用ボタンに確認を挟む。W065 の対象は proposed で source が空の 項目で、位置は index.json のその項目の id の値。
  • Web 検索などの外部アクセスは novnow が行わず、MCP サーバ（例: web-research）の責務とする。

17. エクスポート

指示 12 は「アノテーションを除去した出力」と「読者目線でのプレビュー」の 2 つを求めている。 本章は前者（§17.1 / §17.2）を v0.1.0 本体 として定義し、後者（§17.3 読者モード）は v0.1.0 追加仕様 #27 として定義する。

17.1 アノテーション除去パイプライン

エクスポート変換はプロジェクトと範囲・設定のみから出力文字列を決定論的に生成する（MUST）。

処理順（固定）:

# 処理 既定
1 対象節の収集（範囲指定、§17.2） —
2 構造見出し行の除去 除去（insert_headings が真なら章・話のタイトルを見出しテキストとして挿入）
3 コメント（//, /* */）の除去 除去。行がコメントのみなら行ごと削除
3b # 行コメントの除去（§5.0.8） 行ごと削除（MUST）
3c 挿絵メモ行 ! の除去（§5.2.5） 行ごと削除。--keep-illustration-memo 指定時のみ ［挿絵: …］ に変換して残す
4 フィールド行の除去 除去（本文には通常現れない）
5 行末話者注釈 @名前[:モード] の除去 除去。直前の空白も削除
5b 資料引用注釈 ^M0137 の除去（§5.2.4） 除去。直前の空白も削除（MUST）
6 参照の平文化（'名前 → 名前、'{名前} → 名前、:修飾子 除去） 平文化。呼称参照（Address）も表示文字列をそのまま残す
7 資料参照 'M0137[:…] / 'S0042 の除去 行から除去（本文に残っていた場合）
8 エスケープ解除（\@ → @ 等） 解除
9 ルビの処理 keep_ruby: true なら ｜base《ruby》 を保持。false なら base のみ
10 節区切り ; の変換 blank-line（空行 1 行）。他に none / separator（　　＊）を選択可
10b 章あらすじの挿入（§5.3.7） export.include_blurb: true のときのみ、各章の先頭に blurb を 1 段落として挿入し、1 行空ける
11 連続空行の圧縮 2 行以上 → 1 行
12 行頭字下げ indent_first_line: false（真なら段落先頭に全角空白 1 字。ただし 「 で始まる行には入れない）
13 改行コード変換 export.newline（既定 crlf。投稿サイト互換のため）
14 末尾の整形 末尾の空行を削り、改行 1 個で終える

不変条件（MUST）: エクスポート結果に次が残っていてはならない。

  1. @ で始まる行
  2. ; だけの行
  3. ' のシジル
  4. //
  5. # で始まる行
  6. ! で始まる行（--keep-illustration-memo 指定時を除く）
  7. ^M / ^S + 4 桁の文字列

すべてのエクスポート出力はこの不変条件を満たさなければならない（MUST）。

表の読み方:

  • 見出しと区切り（2・10）: 出す節と節のあいだ 1 か所につき、区切りを 1 回入れる。; の行だけでなく、 場面・話・章の境目（見出し行を除いたところ）も同じ 1 回にする。範囲や状態の絞り込みで節が飛んでも 1 回。 insert_headings で見出しを入れたところには区切りを入れない（見出しの前後に空行を 1 行ずつ置く）。 見出しは章が全体プロット、話が章プロットの見出しのタイトルで、タイトルが空なら入れない。場面のタイトルは入れない。
  • コメント（3）: 行内コメント・行末コメントを除いた残りが空白だけになった行は行ごと消す （資料参照だけの行も同じ）。
  • フィールド行（4）: C 形式にフィールド行は無い（§5.0.5。key: value の形の行も本文）ので、本文からは何も消さない。
  • 参照（6・7）: 名前部が資料 ID の形（M0137 / S0042、§5.8.2）なら、解決できなくても修飾子ごと消す。 未解決の参照は ' を消して名前部を残し、: の後ろがモード式（§5.1 mode_expr）ならそれも消す。 直後が区切り文字か行末の '（'『星屑の時計』 の '）も名前を持たないシジルとして消す。英語の短縮形の '（直前が ASCII の英数字）と、エスケープ \' で書いた ' は残す。
  • エスケープ（8）: エスケープで書いた文字は作家が書いたリテラルなので、結果に @ で始まる行や ' が 現れることがある（不変条件はアノテーションについての約束で、リテラルは対象外）。
  • 連続空行（11）: 先頭の空行も削る。
  • 字下げ（12）: 「段落」は本文の 1 行。既に空白（半角・全角）で始まる行には足さない（二重にしない）。 見出し・区切り線・空行には入れない。

17.2 範囲指定と出力

範囲 指定方法
全体 >export → 既定。ストック章（@00）は含まない（§10.3.3、MUST）
章 / 話 / 場面 / 節 SceneId（@01, @01-04, @01-04-02, @01-04-02-03）
複数範囲 範囲式（@01 .. @03, @05）
ストック @00 を明示指定したときのみ
状態で絞る --state fixed（draft を除外して公開分だけ出す）
  • 出力先: デスクトップ/Web とも既定は exports/<title>-<範囲>-<YYYYMMDD-HHMM>.txt（プロジェクト内＝規則 10 適合）。 加えて「名前を付けて保存」（ユーザーの明示操作）とクリップボードコピーを提供する。デスクトップ版の「名前を付けて保存」は保存ダイアログで書き出し先を選ばせ、プロジェクトの外も選べる（§13.1.1 の特例。名前が .txt / .md で終わるファイル 1 個に、その 1 回だけ書く。それ以外の名前は E060 で拒否して書き込まない。Web 版はブラウザのダウンロードでの「プロジェクト内だけ」を改めた）。
  • 形式: .txt（既定）、.md（見出しを # として出力）。
  • CLI: novnow export ./ --range @01-04 --state fixed --out -（- は標準出力）。--out <パス> は指定されたファイル 1 個に書く。プロジェクトの外も指定できる（§13.1.1 の特例。名前は .txt / .md で終わること、親ディレクトリは作らない）。--out を省くと既定の exports/… に書く。
  • 追加オプション:
オプション 既定 動作
--include-blurb export.include_blurb 章あらすじを挿入（§5.3.7）
--blurb-only off あらすじだけ を出力する（投稿サイトの紹介文欄に貼るため）。本文は出さない
--keep-illustration-memo off 挿絵メモを ［挿絵: …］ として残す（§5.2.5）
--include-stock off ストック章を含める

範囲・状態・出力の細部:

  • 範囲の書き方: §5.1 の範囲式に加えて、@ を省いた書き方（01-04、01 .. 03, 05）も受け付ける （シェルによっては @ が特別な意味を持つため）。左端 > 右端の項は誤り（CLI は 2）。
  • 状態（--state s）: draft < review < fixed の順で、実効の状態が s 以上の節だけを出す。 実効の状態は近いものから順に見て最初に書かれていたもの: 話プロット（B 形式）の節の state → 同じ場面の 場面レベル（最初の要点より前）の state → 章プロットの話のブロック → 全体プロットの章のブロック。 どこにも無ければ draft。draft / review / fixed 以外の値は書かれていないものとして扱う。
  • 当てはまる節が無い: 何も書かない。CLI は標準エラーに知らせて 0 で終わる。
  • 既定の名前: <範囲> は全体なら all、項は 01-04 / 01~03（区間）/ ~03・03~（開放端）で、 複数の項は _ でつなぐ。<title> は project.toml の title（空ならディレクトリ名）で、ファイル名に 使えない文字（/ \ : * ? " < > | と制御文字）は _ にする。<YYYYMMDD-HHMM> はローカル時刻だが、 タイムゾーンを得る手段の無いデスクトップ版は UTC（§13.2.2 の opened_at と同じ扱い）。
  • 形式: --out / 保存ダイアログで選んだ名前が .md で終われば .md 形式（insert_headings で入れる 見出しを章 #・話 ## で書く）。それ以外は .txt。
  • CLI のオプション: --range / --state / --out は値を次の引数か --name=value で取る。同じオプションが 2 回あれば後のほう。値が無い・知らないオプション（② の --include-stock などを含む）は 2。 書けたら標準出力に件数（節・字）と書き出し先を出す（--out - のときは本文だけ）。
  • デスクトップの「エクスポート」: コマンドパレットの >export でモーダルを開く。範囲の欄（空欄なら全体）と 状態（Tab で すべて → review 以上 → fixed だけ）を選ぶと、節の数と字数がすぐ出る。Enter で既定の exports/… に保存、Shift+Enter で名前を付けて保存（保存ダイアログ）、Ctrl+Shift+C でクリップボードへ。 3 つのボタンの文字は §9.2.1 の 1（内容から役割が分からない）に当たる。

17.3 読者モード（reader ワークスペース）

縦書き組版計算はフォント実測値（文字ごとの送り幅と縦書きグリフの有無）を入力として受け取り、グリフ幅を固定仮定せずに各文字の座標を決定論的に算出する（MUST）。

17.3.1 要件

  • 縦書き（右上から左下へ、行は右から左へ進む）。
  • アノテーションは §17.1 の変換を通してから表示する（= 読者が読むものと同一）。
  • 原稿に対して読み取り専用。いかなるキー操作でも原稿・プロット・資料・共有設定を変更しない（MUST）。読書位置・表示設定・しおりのローカル状態の保存だけを例外とする。

17.3.2 レイアウト

  • 1 画面 = 1 ページ。既定 18 列 × 42 字（project.toml の reader）。ウィンドウサイズに応じて列数を自動調整（auto 指定時）。

  • 余白: 上下 1 字分、左右 2 字分。
