## 3. アーキテクチャ

<!-- アプリケーションのアーキテクチャを記述する -->

### 3.1 層構造

```
src/
├── core/        # 純粋ドメイン層（I/O を含まない）
├── ports/       # 外部境界 trait（インターフェース）
├── adapters/    # 環境別実装（ファイルシステム、Web API 等）
└── ui/          # ユーザーインターフェース層
```

### 3.2 許可クレート・依存リスト

<!-- 使用を許可する外部依存を列挙する -->

| 層 | 許可クレート | 用途 |
|---|---|---|
| `core/` | （なし＝純粋な言語機能のみ） | ドメインロジック |
| `ports/` | （標準ライブラリのみ） | 抽象インターフェース |
| `adapters/` | （プロジェクトに応じて追加） | 環境実装 |
| `ui/` | （プロジェクトに応じて追加） | GUI 実装 |

### 3.3 将来の拡張点

段階的な機能追加に対応するため、以下の拡張点を設計に組み込む：

1. 未知キーの温存（設定ファイルの後方互換性）
2. 未知フィールド行の温存（パーサの前方互換性）
3. コード予約（将来の診断・イベント ID）
