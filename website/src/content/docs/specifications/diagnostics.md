## 7. 診断カタログ

**現時点で発行しないコード**: 次の 3 件はカタログに定義があるが、現在の実装は発行しない（定義は残す。コードの番号は再利用しない）。

| コード | 発行しない理由 |
|---|---|
| `W041` | プロジェクトの読み取り専用判定が未実装。書き込みの拒否は規則 10 の `E060` として表面化する（§13.1.2） |
| `I051` | ステータスバーの保存状態（§9.6）が代替する |
| `I058` | 資料一覧への反映が代替する |

これら 3 件は「仕様にあって実装が無い」既知の差であり、差分を隠さずにここへ書く（実装したらこの表から消す）。

`W022`（用語の `range` 外の参照・§5.6）、`W025`（資料 MD の H1 と `materials/index.json` の題名のずれ）、`W030`（話プロットと本文の節数の食い違い・§5.4.2）、`W064`（`materials/index.json` に未登録の資料 MD）は発行する（検査は `W022` / `W030` が `diagnose`、`W025` / `W064` が資料の索引の突き合わせ）。

### 7.2 執筆支援系の診断

第 2 次指示で追加された検査。**文章の良し悪し**を言うものはすべて **W（警告）または I（情報）** であり、組み込み既定ではエラーにしない（作者が §4.5.2 で `"error"` と設定した場合は、その設定に従う）。

v0.1.0 の既定で **有効** なのは W080・W082・W084・W092・W095・E064・I054・I055・I056。
W081・W083・W087・W088・W089・W090・W091・W096・W097・W098・W099・W100・W101・W102・W103・W104・W105・W106 は **既定で無効** とし、
文体ワークスペース（§10.9）を開いたときだけ計算・表示する。
理由: これらは「書いている最中に言われたくない」種類の指摘であり、P3（ノイズを増やさない）に抵触するため。
この「既定で無効」は組み込み既定であり、設定で `"warn"` / `"error"` に変えたものは、実行コスト区分の範囲で常時出す。
有効/無効とエラー扱いの正本は `project.toml` の `[features.diagnostics]`（§4.5.2）である。作品を分け合う人同士で揃える設定であるため、`.novnow/ui.json`（個人設定）には書かない。
設定の変更は §10.9 の画面から行える（§10.9.6）。セッション限りの一時的な絞り込みは、表示フィルタ（§10.9.4）で行い、保存しない。

**診断の構造規則（MUST）**: 診断は **コードと引数だけ** で識別し、表示文言は §12 の言語設定に従って解決する。

#### 7.2.2 台詞内の句読点直後の空白（W096）

台詞の中で句読点の後に全角空白を開ける書き方と開けない書き方が作品内で混在しているとき、少数派の箇所を指摘する。寄せ先は作者の既存の文面が作る多数派であり、どちらが正しいかを IDE は決めない。

- 対象は台詞（`「…」`）の内側だけであり、入れ子の台詞（`『…』`）の内側も台詞内として数える。地の文は数えない。
- 記号は `。`・`！`・`？` の 3 つを別々に集計する。各記号について、作品全体で「記号の次に全角空白があって同じ台詞内に文字が続く例」と「全角空白がなく同じ台詞内に文字が続く例」の合計が 5 件以上あり、多数派が少数派より 2 件以上多い場合にだけ、少数派の箇所に W096 を出す。それ以外（同数に近い場合を含む）は診断しない。
- 空白として数えるのは全角空白だけである。半角空白は「空白なし」として扱う。
- 同じ台詞内に次の文字が続かない場合（閉じ括弧の直前 `。」` など）は、集計にも診断にも含めない。
- 文章の言語は表示言語ではなく本文の文字種で決め、日本語主体でない本文ではこの診断を出さない。
- 文言は、作品内で多い側に揃っていないことを対象の記号で示す。ja: `台詞内の句読点「{0}」の後の書き方が、作品内の大勢と揃っていません` / en: `Spacing after "{0}" inside dialogue differs from the majority style in this work`。
- クイックフィックスは、多数派に合わせて全角空白を入れる、または取る 1 操作とする。
- 寄せ先を固定する設定は初版に入れない（多数派への寄せのみ）。
- W096 は執筆支援系の診断であり、組み込み既定では無効とする。有効化は `[features.diagnostics]`（§4.5.2）で行う。実行コストは、編集中は編集中の節のみを対象とし、多数派の集計だけは作品全体から取る。
#### 7.2.3 文末尾の反復（W097）

同じ文末尾で終わる文が 3 文連続した場合（「〜た。」「〜た。」「〜た。」など）、その反復を指摘する。文章の良し悪しを IDE が決めるのではなく（P4）、反復を提示し直すかどうかは作者が定める。

- 対象は地の文（台詞の外側）だけである。`「…」` の内側は数えない（台詞のリズムは作者の領分、MUST。§9.4.3 と同一の原則）。
- 「文」は句点 `。！？` までの区切りとする（§9.4.3 と同一）。改行・段落の区切りは連続を切らない（同一節の読み順で数える）。節の境界は連続を切る。
- 「文末尾」は文を導入済みの `tiniestsegmenter`（§6.2.6）で分詞して得た最後の自立語とする（§9.4.4）。末尾の助詞を固定の除外リスト（1 字の助詞と `から` / `まで`）で取り除き、自立語がもう無い文（例: 助詞だけの文）は文末尾を持たないとし、その文で連続を切って次の文から数え直す。
- 同じ文末尾が 3 文連続したときに、3 文目の位置に W097 を 1 件出す。4 文目以降が同じ文末尾でも同じ連続区間に追加で出さない。
- 文章の言語は表示言語ではなく本文の文字種で決め、日本語主体でない本文ではこの診断を出さない（§7.2.2 と同一）。
- 文言: ja `連続する 3 文の文末尾が同じです` / en `Three consecutive sentences end the same way`。
- クイックフィックスはテキスト編集を返さない（自動置換はしない、MUST。連続する 3 文は診断の範囲とレビュー一覧で示す）。

#### 7.2.10 同一動詞語幹の反復（W104）

同じ動詞の異なる活用形（「考えた。考えて。考えながら。」など）を同じ語として数え、1 個の場面の中で多用された場合に指摘する。

- セグメンタは活用を別のトークンに切る（例: 「走った」→ `走っ` + `た`、「考えて」→ `考え` + `て`）。2 字以上の語トークンの直後の語トークンが固定の活用接尾辞リスト（`た` `て` `だ` `ながら` `られる` `させる` `ない` `たず` `ちゃう` `たい` `よう`、§9.4.4）に属するとき、その語を動詞の語幹として数える。
- 辞書形（接尾辞を伴わない形）と 2 字未満の語（例: 「していた」の `し`）は数えない。`走る` の `走っ` と `走り` のように語幹の表記が割れる場合は、それぞれ別の語として数える（誤検出より取りこぼしを選ぶ、決定論を保つ）。
- 同じ語幹が 1 場面（その場面内の全節）で 5 回以上出現したとき、最後の出現位置に W104 を 1 件出す。4 回以下は診断しない。
- 接尾辞リストは固定・決定論で、規模は小さく保つ（漏れる活用形があっても誤検出はしない、§9.4.4）。
- 文言: ja `同じ動詞が繰り返されています（語幹「{0}」が {1} 回）` / en `The same verb is repeated ({1} forms of "{0}")`。
- クイックフィックスはテキスト編集を返さない（自動置換はしない、MUST。出現箇所と表記は診断の引数とレビュー一覧で示す）。
- W104 は執筆支援系の診断であり、組み込み既定では無効（`[features.diagnostics]` で有効化、§4.5.2）。実行コストは、編集中は編集中の節が含まれる場面のみを対象とする。日本語主体の判定は §7.2.2 と同一（日本語主体でない本文では出さない）。
