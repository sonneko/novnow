## 6. 意味解決エンジン

### 6.1 辞書

#### 6.1.1 名前空間

`'` の後ろで解決される辞書は 1 本のトライに統合する。エントリ種別は次の 5 つ。

| 種別 | 供給元 | キー | 修飾子 `:` の意味 |
|---|---|---|---|
| `Character` | `characters.md` の H1 と `alias` | 表示名・別名 | モード ID（`:B` / `:B+D`） |
| `Address` | `characters.md` の `address:` の値（§5.5.6） | 呼称（「あおいちゃん」等） | （不可。付ければ **E026**） |
| `Word` | `words.md` の H1 と `alias` | 用語・別名 | （不可。付ければ **E026**） |
| `Material` | `materials/index.json` の `id` | `M0137` / `S0042` | 資料タイトル（§6.6） |
| `MaterialTitle` | 同 `title` | タイトル全文 | （不可） |

**衝突規則（固定）**: 同一キーが複数種別に存在する場合の優先順位は
`Character > Address > Word > Material > MaterialTitle`。
衝突したキーには起動時に **W027** を出し、参照ペインに「別種別の同名項目あり」を併記する。

**`Address` エントリの特則（MUST）**

- `Address` は **解決先を持つが、それ自身はキャラではない**。`'あおいちゃん` は「葵あおいへの呼称」として解決され、
  ホバー・参照ペインでは葵あおいの情報を出す。
- `Address` は **呼ぶ側に依存する**。同じ「先輩」が複数キャラの `address:` に現れうるため、
  `'先輩` のように曖昧な場合は **その行の話者**（§6.5.3 の話者決定規則）で絞り込む。
  話者が不明、または話者から見て一意に決まらないときは **W085**（「どの人物への呼称か決められません」）とし、
  クイックフィックスで明示形 `'{葵あおい}` への置換を提案する。
- `Address` は **話者注釈 `@` の解決対象外**（MUST）。`@あおいちゃん` は E012 のままとする
  （話者は常に正式なキャラ名で書く）。
- `Address` は **W084 の呼称検査（§5.5.6）とは独立**。`'` を付けていない素の文字列も検査対象である。

#### 6.1.2 構築とキャッシュ

- トライは `characters.md` / `words.md` / `materials/index.json` のいずれかが変化したときのみ再構築する。
- 再構築は O(総キー長)。目標 5,000 エントリで 10ms 以内（§18）。
- 用語の本文中出現検出（参照ペインの「この節に出てくる用語」）は Aho-Corasick を併用する（v0 を踏襲）。

#### 6.1.3 照合の正規化

比較は次の正規化後に行う（MUST）。元テキストは一切書き換えない。

1. 長音符 `ー`（U+30FC）/ `－`（U+FF0D）/ `—`（U+2014）/ `〜`（U+301C）を `ー` に統一
2. NFKC
3. 英字は小文字化
4. 空白（半角・全角）を除去

**長音の統一は NFKC より先**。
`－`（U+FF0D 全角ハイフン）は NFKC で ASCII の `-`（U+002D）になり、`〜`（U+301C 波ダッシュ）は
NFKC で U+FF5E に変わるため、NFKC を先にすると 1 の長音統一が**永久に発火しない**
。正規化は 1 文字ずつ行い、**正規化後の byte 位置から
元の byte 位置への対応表**を持つ（一致位置を元テキストに戻すため。結合文字は合成されない）。
§6.2.1 の `MAX_KEY_BYTES = 96` は**正規化後**の byte 数で測る。

#### 6.1.4 登場人物の透過的な辞書統合と重複抑止〔状態: 実装完了〕

- `characters.md` に定義された登場人物名および別名（`alias:`）は、`words.md` に重複記載しなくても自動的に統合辞書に登録され、用語と同様に参照解決・補完・ホバー・定義ジャンプの対象となる（`words.md` のファイル自体に勝手に書き込むことはしない）。
- 同一の名前が `characters.md` と `words.md` の双方に存在する場合でも、UI（参照ペイン・パレット・補完候補）に二重表示せず、`characters.md` の登場人物エントリに透過的に統合して扱う。

### 6.2 `'` の最短一致

> 「`@` 及び `'` の後の **最短で何らかの辞書に一致する文字列まで** が範囲」

#### 6.2.1 アルゴリズム（決定論）

```rust
// line: 1 行のテキスト, at: ' のバイト位置
fn resolve_ref(line: &str, at: usize, trie: &Trie) -> RefToken {
    let rest = &line[at + 1..];

    // (a) 明示形 '{...}
    if rest.starts_with('{') {
        return explicit_form(rest);            // } までをキーとする
    }

    // (b) 最短一致: 1 文字ずつ進め、辞書の終端に当たった瞬間に確定
    let mut node = trie.root();
    let mut end: Option<(usize, EntryId)> = None;
    for (i, ch) in rest.char_indices() {
        match node.step(ch) {
            Some(next) => {
                node = next;
                if let Some(id) = node.terminal() {        // ← 最短一致で打ち切り
                    end = Some((i + ch.len_utf8(), id));
                    break;
                }
                if i + ch.len_utf8() >= MAX_KEY_BYTES { break; }   // MAX_KEY_BYTES = 96
            }
            None => break,
        }
    }

    match end {
        Some((len, id)) => {
            let modifier = parse_modifier(&rest[len..]);   // ":" 以降（§6.2.4）
            RefToken::resolved(at, len, id, modifier)
        }
        // (c) 未解決: 区切り文字までを範囲とし、診断 E001 を付ける
        None => RefToken::unresolved(at, scan_to_delimiter(rest)),
    }
}
```

- `MAX_KEY_BYTES = 96`（固定）。これを超える辞書キーは登録時に **E028** で拒否する。
- 未解決時の区切り文字集合（固定）:
  `空白 全角空白 " 「 」 『 』 、 。 ， ． ！ ？ ； ： @ ' ( )  / \n` とタブ。

#### 6.2.2 最短一致の帰結（仕様として受け入れる挙動）

辞書に `リリア` があり `リリアナ` が無いとき、`'リリアナ` は `リリア` + 地の文 `ナ` と解釈される。
辞書に両方があるときは **`リリア`（短い方）** が選ばれる。これは指示どおりの決定である。

ただしこの挙動は作家を驚かせうるため、次の補助を MUST で付ける。

- **W029**: 「より長い辞書項目にも一致しうる」。クイックフィックス = 明示形 `'{リリアナ}` に書き換える。
- 入力補完（§9.7.3）は `'` 入力直後に候補を出すため、通常は曖昧ケースに入らない。

#### 6.2.3 明示形 `'{ ... }`

`'{葵あおい}` のように波括弧で囲むと、その内側全体がキーになる。
閉じ括弧が無い場合は **E002**（行末までを未解決範囲とする）。

#### 6.2.4 修飾子 `:`

```ebnf
modifier = ":" , ( mode_expr | material_title ) ;
mode_expr      = mode_id , [ "+" , mode_id ] ;
material_title = /[^「」『』。、；;\n]+/ ;   (* 空白を許す。下記 *)
```
- 直前の参照が `Character` のとき → モード式。
- `Material` のとき → 資料タイトル（§6.6）。**空白を許す**。
  前後の空白は値に含めない。`:` の後ろが空（`'M0137:`）なら**修飾子として扱わない**
  （`:` は本文の句読点のまま）。
- `Word` / `Address` のとき → **E026**（§6.1.1 の表。`MaterialTitle` も同じく **E026**）。

**`:` の文脈例外（固定表）**

`:` は参照の修飾子であると同時にフィールド行の区切りでもあるため、次の表で曖昧さを消す（MUST）。

| 文脈 | `:` の解釈 | 例 |
|---|---|---|
| フィールド行の最初の `:`（§5.0.5） | **フィールド区切り**。参照修飾子ではない | `mode: 'リリア:B` の 1 つ目 |
| `'参照` の直後の `:` | 修飾子 | `'リリア:B` の 2 つ目 |
| 行末話者注釈 `@名前` の直後の `:` | モード式 | `@リリア:B` |
| **`address:` 行の `=>` より右にある `:`** | **呼称の一部**（モードでも区切りでもない） | `address: '佐倉 => 佐倉先生:担任` → 呼称は `佐倉先生:担任` |
| `address:` 行の `=>` より左にある `:` | 修飾子（`range` 併記時のモード限定） | `address: '葵あおい:D => あおい` |
| `source` / URL 中の `:` | 文字（`:` の直後が空白でないため、§5.0.5） | `https://example.org` |
| 資料タイトル修飾子の中の `:` | タイトルの一部 | `'M0137:取材: 甲子園本戦` |
| 継続行（2 スペース以上のインデント）の `:` | 文字 | — |

`address:` が特別扱いされるのは、呼称そのものが `:` を含みうる自然言語だからである。
`=>` の右側は **行末まで（`#` コメントを除く）すべて値** として読む（MUST）。

#### 6.2.5 `@` の解決

| 文脈 | 解釈 | 失敗時 |
|---|---|---|
| 行頭（空白のみ先行） | 構造見出し。`scene_id`（A 形式は `partial_id`）としてパース | 形が崩れていれば **E002**。ID としては読めるが階層数がそのファイルの許容と違えば **E020**（C・B 形式は 3〜4 階層、A 形式は §5.3.2）。予約番号（§5.1.2）は **E022** |
| 行末（`@名前` が行の最後） | 話者注釈。辞書の `Character` を最短一致 | **E012** |
| 範囲式の中 | `partial_id` | **E002** |
| それ以外の位置 | C 形式では **W002**（エスケープ `\@` を提案）、A/B 形式では自由テキスト | — |

行頭の E002 と E020 の分け方はで確定した。C・B 形式の E020 の `{0}` には許容範囲 `3-4` が入る。

#### 6.2.6 未知の `'` 参照に対する形態素解析境界と自動回復〔状態: 実装完了〕

- `'名前` が辞書に存在せず未解決参照（`E001`）となる場合、句読点まで漫然と赤波線を引くのではなく、形態素解析（漢字・カタカナ・ひらがな・英数字の文字種境界および助詞切り出し）によって先頭の **1 形態素（語幹）**のみを未解決参照の範囲として区切り、その範囲だけに赤波線を引く。
- 参照ペインおよびエディタのクイックフィックスから、その切り出された 1 形態素をワンクリックで「用語（`words.md`）に追加」または「登場人物（`characters.md`）に追加」して診断から自動回復できる。

**文字種の範囲（全機能で共通の固定値）**

日本語かどうかの判定は用途ごとに範囲が違う。**意図して違う**ので、下の表を唯一の定義とし、
範囲を動かすときはこの表を先に直す（MUST）。表に書いていない文字は、その判定の対象にしない。

| 判定 | 使う場面 | 範囲 |
|---|---|---|
| 文字種（形態素境界） | §6.2.6 の 1 形態素切り出し、参照の切れ目 | ひらがな `U+3041`–`U+3096`・`U+309D`–`U+309F` / カタカナ `U+30A1`–`U+30FA`・`U+30FC`–`U+30FE`・半角カナ `U+FF66`–`U+FF9F` / 漢字 `々` `〆`・`U+4E00`–`U+9FFF`・互換漢字 `U+F900`–`U+FAFF` / 英数字 ASCII と全角 `U+FF10`–`U+FF19`・`U+FF21`–`U+FF3A`・`U+FF41`–`U+FF5A` / それ以外は記号。**拡張 A（`U+3400`–`U+4DBF`）は記号**として扱う |
| ルビの親文字 | §5.2.1 の `kanji_run` | CJK 統合漢字 `U+4E00`–`U+9FFF`・拡張 A `U+3400`–`U+4DBF`・互換漢字 `U+F900`–`U+FAFF`。繰返し字 `々`（`U+3005`）・`〻`（`U+303B`）は漢字列に含めるが親文字そのものには数えない。文字種の判定と違い**拡張 A を含む** |

| 診断の「語」 | §9.4.4 の語の抽出 | 文字の性質（英数字・仮名 `U+3041`–`U+30FF`・漢字 `U+3400`–`U+9FFF`・ハングル `U+AC00`–`U+D7AF`）。ラテン文字・〇 付き数字も語になる。標点と空白は語にならない |
| 文字化けの指紋 | §14.6.1（貼り付けの修復候補） | かな `U+3041`–`U+3096`・`U+30A1`–`U+30FA`（**長音符と半角カナを含まない**）／半角カナ `U+FF66`–`U+FF9D`（**濁点・半濁点 `U+FF9E`–`U+FF9F` を含まない**） |

### 6.4 モード解決

#### 6.4.1 モードの定義元

`characters.md` の `## modes` 配下。`(mode_id, range)` の組で一意。

#### 6.4.2 割り当て（プロットが正）

モードの割り当ては **話プロット（B 形式）の `mode:` フィールドで行う**。本文側の話者注釈 `@名前:B` は「その台詞だけの一時上書き」である。

#### 6.4.3 解決順序（上から順に最初に見つかったものを採用、固定）

1. 本文の当該行の話者注釈の修飾子（`@リリア:C`）— その行のみ
2. 話プロットの **当該節** の `mode:`
3. 話プロットの **当該場面**（見出し直下）の `mode:`
4. 話プロットの preamble の `mode:`
5. 章プロット（`plots/AA.cnov`）の当該話ブロックの `cast:` に書かれたモード
6. 全体プロット（`plots/all.cnov`）の当該章ブロックの `cast:` に書かれたモード
7. `characters.md` の `default-mode`
8. モード未決定 → **W006**。参照ペインには「モード未指定」と表示し、全モードの `role` だけを 1 行ずつ畳んで出す

#### 6.4.4 制約

- 1 キャラ 1 節につき **最大 2 モード**（`A+B`）。3 つ以上は **E005**。
- 2 モードが有効なときの参照ペイン表示は、`personality` → `emotion` → `role` の順に **モードごとに並べる**（マージしない）。
- 割り当てたモードの `range` が対象 SceneId を含まなければ **E004**。
  クイックフィックス: (a) `range` を拡張する、(b) 範囲を含む別の同名モード定義を作る、(c) 範囲内の他モードに差し替える。

#### 6.4.5 変種（同一 ID・異 range）の選択

対象 SceneId を含む `range` を持つ定義が一意に決まること。
複数が一致したら **E017**（定義側の range 重複エラー。パース時に検出するので実行時は起きない）。

#### 6.4.6 参照ペインの表示規則（指示 6「モードの性格のみを左に表示する」）

- 有効モードの `personality` / `emotion` / `role` / 役割語パターンのみ表示する。
- **他モードの本文は表示しない**（折り畳みボタンすら置かない。キーボード操作 `Ctrl+Shift+M` で初めて全モード一覧を別ポップアップに出す）。
- キャラ直下の `attributes` は常時表示（モードに依存しない事実のため）。

### 6.5 役割語の照合

#### 6.5.1 パターン言語（RolePattern）

`「` `」` に囲んで書く。**正規表現そのものではなく**、次の 5 種のアトムだけを持つ小言語とする。

| アトム | 意味 | 変換後の正規表現 |
|---|---|---|
| `*` / `〜` | 0 文字以上の任意文字列（改行を含まない） | `[^\n]*?` |
| `…` / `...` / `‥` | 間（1 個以上の省略記号・句点の連続） | `[…‥.。]{1,6}` |
| `(体言)` 等 | 語クラス。`project.toml` の `lexicon.word_classes` で定義 | 定義された正規表現 |
| `?` | 任意の 1 文字 | `[^\n]` |
| それ以外 | リテラル（正規表現メタ文字はエスケープ） | `\Q...\E` 相当 |

既定の語クラス（`project.toml` 未指定時）:

| クラス | 正規表現 |
|---|---|
| `(体言)` | `[\p{Han}\p{Katakana}\p{Hiragana}A-Za-z0-9ー]{1,24}` |
| `(用言)` | `[\p{Han}\p{Hiragana}]{1,16}` |
| `(数)` | `[0-9０-９一二三四五六七八九十百千万]{1,8}` |

`project.toml` の `lexicon.word_classes` に**正規表現として不正な値**を書いた場合は、`project.toml` のその値に **E027** を出し、**そのクラスを使うパターンだけ**を無効にする（他のパターンは生かす。役割語の色が消えるだけで執筆は止まらない、§4.3-4）。不正かどうかは値を**単独で**正規表現としてコンパイルできるかで決める。

#### 6.5.2 アンカー規則（固定）

パターンの先頭・末尾がワイルドカード（`*` / `〜`）かどうかで決まる。

| 形 | 例 | 照合 |
|---|---|---|
| 先頭ワイルドカード・末尾リテラル | `「*だよ！」` | **文末一致**（`$` アンカー） |
| 先頭リテラル・末尾ワイルドカード | `「ちょっ…*」` | **文頭一致**（`^` アンカー） |
| 両端ワイルドカード | `「*ヨシ*」` | 位置自由 |
| ワイルドカード無し | `「です。」` `「ほう…」` | **文末一致**（既定） |
| `=` 前置 | `「=ほう…」` | **完全一致**（発話全体が一致） |

ここで `^` / `$` が指すのは**文**の先頭・末尾である。文は、発話（`「」` / `『』` の内側の文字列）を
文末記号 `。` `！` `？` `!` `?` `…` の**連続の直後**で区切った単位とし、次の 3 点を決めておく。

- 発話の頭（または区切りの直後）にある文末記号の連続は区切りにせず、**次の文の頭に含める**
  （`…あの…その…` は `…あの…` と `その…` の 2 文。`…` で始まる文が空にならない）。
- 文の前後の空白（半角・全角・タブ）は文に含めない（`えっ！　ちょっ…待って` の 2 文目は `ちょっ…待って`）。
- **`=` 前置の完全一致だけは文に分けず、発話全体**と照合する。

したがって `「分かってるよ。でも、これを見てくれ」` に文末固定の `*よ。` は 1 文目の末尾に**一致する**。
文末記号の**後ろにさらに文字が続く**パターン（`*よ。でも*` など）は、その記号で文が切れるため一致しない。
1 つの台詞で複数の文が一致したら、すべての一致に下線を引く（§6.5.4 の和集合）。


#### 6.5.3 照合対象

- C 形式の `dialogue.text`（`「」` / `『』` の内側）のみ。地の文は照合しない（MUST）。
- 入れ子（`「『…』」`）は内側・外側の**両方**を台詞として扱う。種類の違う閉じ括弧（`「…』`）は閉じとして扱わない。
- 閉じ忘れた `「` / `『` の内側は **行末まで** とする（行をまたがない。書きかけの台詞でも役割語が見えるほうが役に立ち、原文は書き換えないので往復は影響を受けない）。同じ規則を、台詞の字数（§9.4.2）・台詞内の句読点直後の空白（§7.2.2）・読点候補の除外（§9.4.3）も用いる。
- 話者は、行末の話者注釈 → 直前の話者注釈の継続 → プロットの `pov` の順に決める。話者不明の台詞は照合しない。
- 適用パターン集合 = （有効モードのパターン）∪（キャラ共通 `## tone` のパターン）。有効モードが 2 つならそれぞれの和。

#### 6.5.4 表示

- 一致した範囲から **`*` / `〜`（`[^\n]*?`）が食った部分を除いた**ところに緑の下線（`syntax.role-language`、§11.3）。語クラス `(体言)`・省略記号 `…`・`?` が食った部分は**下線に含める**（。付録 B.3 の 4 行目が `(体言)！` → `静粛に！` の全体を下線としているためで、B.3 を正とした。§9.1 A-21）。
- 複数パターンが一致したら、一致範囲の和集合に 1 本の下線を引く（二重線にしない）。
- **一致しない場合は何もしない。** 診断も色も出さない（指示 6 の明文、MUST）。
- 例外として、文体チェックワークスペース（§10.9）でだけ「役割語が検出されなかった台詞」を一覧できる（本文編集画面には出さない）。

#### 6.5.5 計算量

1 台詞あたり（適用パターン数 × 文数）回の正規表現検索。パターンはモードごとに `RegexSet` へ事前コンパイルしてキャッシュする。
目標: 1 行 10 パターンで 20µs 以内。

### 6.7 インクリメンタル再解析

- 1 行編集 → その行のみ再字句解析 → **節番号（D）に影響する種別が変わった場合のみ**、その行以降の **節番号（D）の付番** を再計算（O(ファイル行数) だが単純ループ、10 万行で 2ms 以内）。
  付番に影響するのは構造見出し（`@`）と節区切り（`;`）だけで、コメント・フィールド行・継続行・本文行のあいだの種別変化は付番を変えないので再計算しない。
- 行数が変わる編集（改行の挿入・削除、複数行の貼り付け）は、種別が変わらなくても編集位置以降の付番を再計算する（行番号と節番号の対応がずれるため）。編集位置が行数を超えていたら末尾への追加として扱い、パニックしない。
- 参照解決は「編集行」と「参照ペインに出ている行」だけを即時、ファイル全体は 300ms アイドルで再計算。
- 診断は編集行を即時、ファイル全体はアイドル 300ms、プロジェクト全体は明示操作（§10.9）またはアイドル 5 秒。

## 付録 B: 役割語パターン言語と、提示された例の変換表

### B.1 変換規則（§6.5.1 の再掲）

| 記法 | 正規表現 |
|---|---|
| `*` / `〜` | `[^\n]*?` |
| `…` / `...` | `[…‥.。]{1,6}` |
| `(体言)` | `[\p{Han}\p{Katakana}\p{Hiragana}A-Za-z0-9ー]{1,24}` |
| `?` | `[^\n]` |
| その他 | リテラル（メタ文字はエスケープ） |

アンカー: 先頭ワイルドカード → `$` 固定 / 末尾ワイルドカード → `^` 固定 / 両端ワイルドカード → 自由 / ワイルドカード無し → `$` 固定 / `=` 前置 → 完全一致。`^` / `$` は**文**の先頭・末尾、完全一致だけは発話全体（§6.5.2）。

### B.3 変換結果の例（テストの期待値）

| パターン | アンカー | 正規表現 | 一致例（下線部） | 不一致例 |
|---|---|---|---|---|
| `*だよ！` | 文末 | `[^\n]*?だよ！$` | 「もう行く__だよ！__」 | 「本当だよ！？」 |
| `…あの…*` | 文頭 | `^[…‥.。]{1,6}あの[…‥.。]{1,6}[^\n]*?` | 「__…あの…__その…」 | 「えっと、…あの…」 |
| `です。` | 文末 | `です。$` | 「承知しました__です。__」 | 「ですが」 |
| `(体言)！` | 文末 | `[\p{Han}\p{Katakana}\p{Hiragana}A-Za-z0-9ー]{1,24}！$` | 「__静粛に！__」 | 「ねえ、いいでしょ？」 |
| `ちょっ…*` | 文頭 | `^ちょっ[…‥.。]{1,6}[^\n]*?` | 「__ちょっ…__待って」 | 「あ、ちょっ…」 |
| `*ヨシ` | 文末 | `[^\n]*?ヨシ$` | 「指差し確認__ヨシ__」 | 「ヨシと言った」 |
| `オッケーっじゃあ*` | 文頭 | `^オッケーっじゃあ[^\n]*?` | 「__オッケーっじゃあ__始めるぞ」 | 「じゃあオッケー」 |
| `かな` | 文末 | `かな$` | 「行ける__かな__」 | 「かなり」 |

> `「*よ」`（すず）と `「*よ」`（佐倉先生）のように **複数キャラで同じパターン** が現れてよい。
> 照合は常に「その台詞の話者のパターン集合」に対してのみ行うため、衝突は起きない。

### B.4 下線範囲の決定

正規表現のマッチ全体のうち、**`*` / `〜`（`[^\n]*?`）が消費した範囲を除いた部分**に下線を引く。
語クラス `(体言)`・省略記号 `…`・`?` が消費した部分は**含める**。
実装はキャプチャグループを自動挿入して行う（**下線に含めるアトムの連続**を `(...)` で囲んだ
正規表現を生成する。アトムごとに囲むと `…あの…` が 3 本に割れ、B.3 の 2 行目の期待値にならない）。
