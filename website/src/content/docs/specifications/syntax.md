## 5. ファイル形式（構文仕様）

### 5.0 共通字句規則

すべての novnow テキスト形式（`contents/*.cnov`, `plots/*.cnov`, `*.md`）に共通。

#### 5.0.1 行指向の原則（MUST）

**複数行にまたがるトークンは存在しない。** 1 行は常に単独で字句解析できる。
これはインクリメンタル再解析（編集行のみ再解析）と LSP 化の前提であり、v0.1.0 でも維持する。

#### 5.0.2 シジル（記号）一覧

| 記号 | 名称 | 意味 | 出現場所 |
|---|---|---|---|
| `@` | StructureSigil | 行頭: 構造見出し / 行末: 話者注釈 / 範囲式 | 全形式 |
| `'` | RefSigil | 辞書参照（キャラ・用語・資料） | 全形式の本文部 |
| `'{ }` | 明示参照 | 区切りが曖昧なときの参照（§6.2.3） | 同上 |
| `:` | Modifier | `'` トークンの修飾子（モード ID / 資料タイトル） | `'` トークン直後 |
| `+` | ModeJoin | モードの併用（最大 2、§6.4.4） | モード修飾子内 |
| `;` | SectionBreak | 節区切り・ブロック終わり（行全体が `;` のときのみ） | A / B / C 形式（`.cnov`） |
| `//` | LineComment | 行頭: その行全体がコメント / 行内: 以降行末までコメント（**`://` は除く**） | 全形式 |
| `# ` | LineComment | **行頭のみ**。その行全体がコメント（§5.0.8） | A / B / C 形式（`.cnov` のみ） |
| `/* */` | InlineComment | 行内コメント（**単一行内で閉じること**） | 全形式 |
| `「」` | Dialogue | 会話。`『』` は入れ子の引用として同様に扱う | C 形式 |
| `^` | Citation | 行末の資料引用注釈（`^M0137`、§5.2.4） | C 形式 |
| `! ` | IllustrationMemo | **行頭のみ**。挿絵メモ（§5.2.5） | C 形式 |
| `..` | RangeOp | 範囲式の区切り | 範囲式 |
| `key:` | Field | 行頭フィールド（§5.0.5） | A/B 形式, `*.md` |
| `\` | Escape | 直後 1 文字をリテラル化 | 全形式 |

**行頭シジルの優先順位（固定）**: `@` → `;` → `# ` → `! ` → `//` → フィールド行 → 通常テキスト。
`# ` と `! ` は **直後に半角または全角の空白が必要**（`#1 位` や `!?` を誤認しないため、MUST）。

**`://` は行内コメントにしない（MUST）**: 行内の `//` の**直前が `:`** のときは、URL の scheme
区切り（`https://example.com`、フィールド値の `source:https://…`）なのでコメントの始めにしない。
直前が `:` でなければ、その `//` から行末までがコメント。回避にはエスケープ `\/`（§5.0.3）も使える。
この判定は行内で完結する（§5.0.1）。

#### 5.0.3 エスケープ

`\@` `\'` `\;` `\/` `\「` `\」` `\\` `\#` `\!` `\^` のみ有効。それ以外の `\x` は `\x` の 2 文字としてそのまま扱う（診断なし）。
エクスポート時にエスケープは解除される（§17.1）。

#### 5.0.4 改行・符号化・正規化

- 読み込み: UTF-8。BOM があれば剥がして読み、保存時は付けない（MUST）。改行 LF / CRLF / CR を受理し、内部表現は LF。
- 保存: `project.toml` の `newline` に従う。既定 LF、BOM なし。
- 行末の半角/全角空白は保存時に削除（MUST）。ただし行頭のインデントは保持する。
- ファイル末尾は必ず改行 1 個で終える（MUST）。
- Unicode 正規化は行わない（作家の入力を変えないため）。ただし **辞書照合時のみ** NFKC 相当の比較を行う（§6.1.3）。

#### 5.0.5 フィールド行

```ebnf
field_line   = ws? field_key ws? (":" | "：") field_value ;
field_value  = ws value | ws | ε ;   (* ε は行末。手順 4・5 の場合は ws 無しでもよい *)
field_key    = ascii_key | ja_alias ;
ascii_key    = /[a-z][a-z0-9-]{0,23}/ ;
```

判定は**行内で完結する**（§5.0.1）。次の手順で決める。

1. 行頭のインデントが **2 文字以上の空白（半角・全角）または 1 文字以上のタブ**なら継続行であり、フィールド行ではない（下の「継続行」参照）。
2. 最初のコロン（半角 `:` または全角 `：`）の直前までを `key` 候補とし、末尾の空白を除く。
   コロンが無ければフィールド行ではない。**コロンが複数あれば最初のもので切る**（値にコロンが残ってよい）。
3. `key` 候補が `field_key`（`ascii_key` の形、または §5.0.6 の表にある日本語別名）でなければ
   フィールド行ではない。§5.0.6 の表に無い日本語（`注：これは本文` のような散文）はここで通常テキストになる。
4. コロンが**全角 `：`** なら、直後の空白を問わず**フィールド行**（日本語の自然な書き方
   `要約：あらすじ` を受けるため）。
5. コロンが**半角 `:`** のとき:
   - 直後に空白（半角・全角・タブ）があるか、行末なら**フィールド行**。
   - 直後に空白がなくても、`key` が §5.0.6 の**表にあるキー**（正準形または別名）なら**フィールド行**
     （`summary:一行` `mode:B` `source:https://example.com` を救う）。
   - それ以外は**通常テキスト**。
6. 値は前後の空白を除いて保持する。`key:` / `key：` だけの行は**空の値**のフィールド行
   （§5.0.4 が行末の空白を削除する MUST と両立させるため、`ws` は行末でも満たされると読む）。
7. §5.0.6 の表に無い `ascii_key` でフィールド行になったものは **W011**（未知のキー）とし、値は改変せず保持する。

**URL 判定は除外リストを持たない（MUST）**: 手順 5 が「表に無い ascii キーは空白なしではフィールド行に
しない」ため、`http://example.com`・`https://…`・`mailto:foo@example.com`・`doi:10.1000/xyz`・
`isbn:978-…`・`tel:090-…`・`file:///tmp/x`・`C:\Users\x`・`10:30` は**自動的に本文のまま残る**
（`http` `doi` `10` などは §5.0.6 の表に無いので手順 3・5 で落ちる）。逆に、表にあるキーの値に URL を
書くのは正当（`source:https://example.com`）なので、値の中身は検査しない。

**不変条件（MUST）**: §5.0.6 の `ascii_key` は **URL scheme および本文中に書かれがちな接頭辞と
衝突してはならない**（`http` `https` `ftp` `file` `mailto` `data` `tel` `urn` `ssh` `git` `svn`
`s3` `news` `doi` `isbn` `arxiv` `pmid` `javascript` `about` `blob` 等）。表に scheme と同名のキーを足してはならず、キー表と URI スキーム列挙の非交差を維持する（MUST）。

- `ascii_key` が正準形。日本語別名は §5.0.6 の表にある語のみ受理し、**保存時に正準形へ正規化しない**（作家の表記を保つ）。
- 値は 1 行。複数行が必要な場合は継続行として **2 文字以上の空白（半角・全角）または 1 文字以上のタブによるインデント** を用いる。
  継続行の先頭インデント（先頭がタブなら 1 文字、それ以外の空白なら 2 文字）は値から剥がす。

```
summary: 一行目
  二行目（継続行）
```

#### 5.0.7 コメントと「アノテーション」の定義

エクスポート（§17）で除去される「アノテーション」とは、次の 9 種を指す（固定）。

1. 構造見出し行（`@A-B-C[-D] ...`）
2. 行末話者注釈（`@キャラ名[:モード]`）
3. 参照シジル `'` と修飾子（`:モード` / `:タイトル`）。**表示名そのものは残す**
4. 節区切り `;`
5. 行コメント `//...`、行内コメント `/* ... */`
6. **行頭コメント行 `# ...`**（§5.0.8）
7. **行末の資料引用注釈 `^M0137`**（§5.2.4）
8. **挿絵メモ行 `! ...`**（§5.2.5）
9. フィールド行（A/B 形式のみ。本文には現れない）

#### 5.0.8 `# ` 行コメント

```ebnf
hash_comment = ws? , "#" , (" " | "　") , any* , eol ;
```

- **`.cnov`（A / B / C 形式）でのみ有効**。`.md` ファイル（`characters.md` 等）では `#` は従来どおり見出しであり、コメントにならない（MUST）。
- 行頭のみ。行の途中の `#` はただの文字。
- 複数行コメントは存在しない（1 行 1 コメント、MUST）。
- `//` との使い分けは利用者の自由。novnow はどちらも同じ `comment` トークンとして扱い、相互変換もしない。
- 用途の想定: 執筆中の自分宛てメモ（「ここは後で直す。リリアの心情が不自然」）。

```
# ここは後で直す。リリアの心情が不自然。
「……付き合ってあげるわよ」@リリア:B
```

#### 5.0.9 文書として認識する範囲

novnow が文書として読み、解析し、書き戻すのは、置き場所と拡張子の組が仕様の定義に一致するファイルだけである。

- `contents/<章>-<話>.cnov` は本文（C 形式）、`plots/all.cnov` と `plots/<章>.cnov` はアウトライン（A 形式）、`plots/<章>-<話>.cnov` は話プロット（B 形式）。形式は拡張子単体では決まらず、置き場所とファイル名の形との組で決まる。
- 名前がこの形に一致しないファイルは文書として認識しない。`contents/` にあっても拡張子が `.cnov` でないファイルや、章・話の番号の形に合わない `.cnov` がそうである。認識しないファイルは解析も書き戻しもせず、§4.3 のとおり未知のファイルとして触れない。
- `.cnov` は A / B / C の 3 形式で使う novnow 専用の拡張子であり、中身は通常の UTF-8 テキストである。

### 5.1 SceneId と範囲式

```ebnf
scene_id      = num , "-" , num , "-" , num , [ "-" , num ] ;
partial_id    = num , [ "-" , num , [ "-" , num , [ "-" , num ] ] ] ;
num           = /\d{1,4}/ ;                   (* 表示は project.toml の桁数でゼロ詰め *)
range_expr    = range_term , { "," , ws , range_term } ;
range_term    = ( "@" partial_id , ws? , ".." , ws? , [ "@" partial_id ] )
              | ( ".." , ws? , "@" partial_id )
              | ( "@" partial_id ) ;
```

意味論:

- `@01-04-02-03` は節、`@01-04-02` は場面全体（`section = 0` を「場面全体」の意味で用いる。v0 と同じ）。
- `@01-04 .. @02-01` は **閉区間**。比較は `(chapter, episode, scene, section)` の辞書式順序。
  左辺の省略階層は最小値（0）、右辺の省略階層は最大値（9999）に展開される。
  例: `@01 .. @02` ⇒ `01-00-00-00 .. 02-9999-9999-9999`。
- `@03-01 ..` は上端開放、`.. @01-03` は下端開放。
- カンマ区切りで複数区間の和集合。
- **境界検査**: 区間の左端 > 右端 のときは **E016**。

表示（`SceneId::display`）: `section == 0` のときは 3 階層表示、それ以外は 4 階層。いずれも `project.toml` の `structure.*_digits` でゼロ詰め。

#### 5.1.1 階層ごとの役割（再掲）

`A` 章 / `B` 話 / `C` 場面 / `D` 節。

#### 5.1.2 予約番号 `00`（v0.1.0 追加仕様 17・22）

`00` は階層ごとに固有の意味を持つ。**番号としては正当な値であり、パースを拒否しない**（MUST）。

| 位置 | 意味 | ファイル | 備考 |
|---|---|---|---|
| `A = 00` | **未配属ストック章** | `contents/00-01.cnov`, `plots/00.cnov`, `plots/00-01.cnov` | 章番号を決めていない話の仮置き場。UI 表示名は「未分類ストック」。`structure.allow_chapter_zero = false` にすると **E022** で拒否 |
| `B = 00` | **章あらすじ** | `contents/01-00.cnov`, `plots/01.cnov` 内の `@01-00` ブロック | 読者向けの短いあらすじ。`blurb:` フィールドを持つ（§5.3.2） |
| `C = 00` | 予約（未使用） | — | v0.1.0 では書いてはならない（**E022**） |
| `D = 00` | 場面全体 | — | 既存仕様（見出しで `D` を省略した状態） |

- 予約番号を拒否する診断は **E022**。
- `@00-01-02-03` は正当な SceneId（ストック章の 1 話 2 場面 3 節）。
- `@01-00` は正当な PartialSceneId（1 章のあらすじ）。`@01-00-01-01` のように下位を付けることもできる（あらすじを節に分けて書く場合）。
- 範囲式での扱いは通常の番号と同じ（`@00 .. @01` は「ストック章と 1 章」を意味する）。
- ソート順は数値順のため、ストック章（`00`）は常に先頭、章あらすじ（`B=00`）は章の先頭に来る。

**ストックから正式な章への移動**（§10.3.3）は、ファイル名のリネームと本文・プロット内の SceneId 一括置換を
**1 つの操作として原子的に** 行う（途中失敗時は全て巻き戻す、MUST）。

### 5.2 本文形式（C 形式）— `contents/AA-BB.cnov`

#### 5.2.1 文法

```ebnf
content_file  = { line } ;
line          = scene_header | section_break | comment_line | illust_line | blank | text_line ;

scene_header  = ws? , "@" , scene_id , [ ws , title_text ] , [ comment ] , eol ;
section_break = ws? , ";" , [ comment ] , eol ;
comment_line  = ws? , ( "//" | "#" ws1 ) , any* , eol ;
illust_line   = ws? , "!" , ws1 , any* , eol ;
blank         = ws? , eol ;
text_line     = inline+ , [ citation* ] , [ speaker_annot ] , [ comment ] , eol ;

inline        = dialogue | ref | ruby | escaped | plain ;
dialogue      = "「" , inline* , "」" | "『" , inline* , "』" ;
ref           = "'" , ( ref_name | "{" , ref_name , "}" ) , [ ":" , modifier ] ;
ruby          = "｜" , base , "《" , reading , "》" | kanji_run , "《" , reading , "》" ;
citation      = ws* , "^" , material_id ;                            (* 行末側 *)
speaker_annot = ws* , "@" , char_name , [ ":" , mode_expr ] , ws* ;   (* 行末のみ *)
mode_expr     = mode_id , [ "+" , mode_id ] ;
ws1           = " " | "　" ;
```

#### 5.2.2 節の確定規則（MUST）

- 場面見出し `@A-B-C` の直後から最初の `;` までが節 `D=1`。以降 `;` ごとに `D` が 1 ずつ増える。
- 見出しに `D` が明示されている（`@01-04-02-03`）場合、その見出し直後の節番号を `D` から開始する（部分ファイル・差し込み用）。
- 節の末尾の空行は節の内容に含めない。
- `;` が連続した場合、空の節が生成される（診断 W012「空の節」）。

#### 5.2.3 例

```
@01-04-02 図書室の攻防
「やっぱり'アルス、ここにいたのね」@リリア:A

呆れたような声とともに、'リリアが隣の椅子を引き寄せた。
;
「旧校舎の地下遺跡に眠っているっていう'『星屑の時計』の設計図だ」@アルス

'リリアは溜め息をついたが、図面の精巧な書き込みに目を奪われた。
;
「……付き合ってあげるわよ」@リリア:B    // ここでモードが切り替わる
```

#### 5.2.4 資料引用注釈 `^`

本文の行が、どの資料に基づいて書かれたかを示す。

```ebnf
citation = "^" , ( "M" | "S" ) , /\d{4}/ ;
```

| 規則 | 内容 |
|---|---|
| 位置 | 行末側。`speaker_annot` より **前**。複数並べられる（`^M0137 ^M0021`） |
| スコープ | **その 1 行**。段落や節には掛からない |
| 表示 | 本文中ではごく薄い灰色の上付き。参照ペインの「資料」節に、現在の節で引用されている資料を列挙する |
| 妥当性 | `materials/index.json` に存在しない ID は **E012**（未知の資料参照） |
| エクスポート | 完全に除去される（§17.1、§5.0.7-7） |
| 文字数 | `^M0137` は本文文字数に数えない |
| 逆引き | 資料詳細（§10.5）に「この資料を引用している節」の一覧を出す |

```
世界樹の樹皮は、剥がすと七日で再生するという。^M0137
```

**目的の明示**: この機能は「資料を集めたが使っていない」状態を可視化するためにある。
調査済みの資料のうち、どの節からも引用されていないものは **I054** で通知する（§7.2）。
引用は義務ではない（付けなくても診断は出ない、MUST）。

#### 5.2.5 挿絵メモ `! `

```ebnf
illust_line = ws? , "!" , ws1 , memo_text , eol ;
```

| 規則 | 内容 |
|---|---|
| 位置 | 行頭のみ。**単独行**（本文と混ぜられない） |
| 意味 | 「ここに挿絵が入る」という作者のメモ。novnow は画像を生成も表示もしない |
| 所属 | 直前の節に属する。節の先頭に書けばその節の冒頭扱い |
| 表示 | 本文中は細い罫線 1 本＋メモ文（本文と明確に異なる地味な見た目）。参照ペインに「挿絵」節として列挙 |
| エクスポート | 行ごと除去（§17.1）。ただし `--keep-illustration-memo` 付きのときは `［挿絵: …］` として残す |
| 一覧 | §10.9 に「挿絵メモ一覧」を出し、ID 順に並べる（商業出版時のイラストレーター向け指示書の素地） |
| 文字数 | 本文文字数に数えない |

```

```

`! ` は **構造を持たない**（番号も属性も付けない）。構造化した挿絵指示が要るなら
B 形式の `illustration:` フィールド（§5.4.2）を使う。両者は独立して併存できる。

#### 5.2.8 会話閉じ括弧直後の `@` による話者予測補完〔状態: 実装完了〕

- 会話スパンの閉じ鉤括弧（`」` または `』`）の直後（空白を挟む場合を含む）に `@` を入力したときは、行末話者注釈の入力開始とみなし、登録済みの登場人物名および `@キャラ:モード` の予測補完候補を即座に提示する。

### 5.3 アウトライン形式（A 形式）— `plots/all.cnov`, `plots/AA.cnov`

**全体プロットと章プロットは同一形式**。違いは「見出しが指す階層」だけである。

| ファイル | 見出しの階層 | 記述対象 |
|---|---|---|
| `plots/all.cnov` | `@A`（章） | 物語全体の構成。章の要約・目的・転換・伏線 |
| `plots/01.cnov` | `@A-B`（話） | 1 章の構成。話の要約・目的・転換・配役モードの推移 |

#### 5.3.1 文法

```ebnf
outline_file = [ preamble ] , { block } ;
preamble     = { field_line | comment_line | blank } ;      (* ファイル全体のメタ *)

note_line    = inline+ , eol ;        (* フィールドに当てはまらない自由記述 *)
```

| キー | 必須 | 回数 | 値 | 意味 |
|---|---|---|---|---|
| `summary` | **必須** | 1 | 1 行 ≤ 120 字 | この単位の一行要約。**上位 LLM コンテキストに必ず入る唯一の行**（§15.4） |

| `turn` | 任意 | 0..n | 自由文 | 転換点 |
| `pov` | 任意 | 0..1 | `'キャラ名` | 視点人物 |
| `cast` | 任意 | 0..1 | `'名前[:モード[+モード]]` の空白区切り | 登場人物と既定モード |
| `seed` | 任意 | 0..n | `F<id> 説明 -> @範囲` | 伏線の設置 |
| `payoff` | 任意 | 0..n | `F<id> -> @範囲` | 伏線の回収 |
| `material` | 任意 | 0..n | `'M0137 [補足]` | 参照資料 |

#### 5.3.5 作中日時式 `when:`

現実の暦ではなく **作中世界の時間** を書くためのフィールド。異世界の独自暦を許すため、
**novnow は暦を解釈しない**。解釈するのは「順序」だけである（MUST）。

```ebnf
when_value   = timepoint , [ ws? , ".." , ws? , timepoint ] , [ ws , free_text ] ;
timepoint    = ordinal_key , [ ws , clock ] ;
ordinal_key  = /[-+]?\d+(\.\d+)?/ , [ unit_label ]      (* 例: 0, 12, 405.5, -3 *)
             | "?" ;                                     (* 時系列不明 *)
unit_label   = /[^\s:]{1,12}/ ;                          (* 日 / 年 / 刻 / Day など *)
clock        = /\d{1,2}:\d{2}/ ;
```

| 規則 | 内容 |
|---|---|
| 正本 | **`ordinal_key` の数値だけが順序を決める**。`unit_label` と `free_text` は人間向けの表示 |
| 単位 | プロジェクト全体で 1 つの単位系を暗黙に使う。novnow は単位名を検査しない（`日` と `年` が混在しても無視） |
| 時刻 | `clock` は `ordinal_key` 内の副順序。`12 08:30` は `12 09:00` より前 |
| 範囲 | `12 .. 14` は「12 から 14 にかけて」。順序比較には **開始値** を使う |
| 不明 | `?` はタイムラインで「順序未定」の帯に置く。矛盾検出の対象外 |
| 継承 | 下位階層が `when` を持たないとき、上位の `when` を継承する（章 → 話 → 場面 → 節） |
| 相対 | 先頭が `+` のとき、直前の同階層ブロックの値への加算（`+1` = 翌日）。`-` も同様 |

```
when: 405.0 春分  09:15        … 405 日目の 9 時 15 分、表示は「405 春分 09:15」
when: +1 翌朝                   … 直前のブロック +1
when: 12 .. 14 三日間の合宿
when: ? 回想（時期不明）
```

**時系列矛盾の検出**: 本文の節順（SceneId 昇順）に対し `when` が巻き戻る箇所を **W080** で通知する（§7.2）。
ただし **回想は正当な技法** なので、次のいずれかがあれば警告しない（MUST）。

- `when` の `free_text` に `回想` / `過去` / `flashback` のいずれかを含む
- 同ブロックに `note: 回想` がある
- `when: ?`

#### 5.3.6 空間設計メモ `space:`

部屋の間取り・建物の位置関係・座席配置など「文章では書かないが、書く側が把握していないと矛盾する」情報。

```
space-mode: ascii
space:
  ┌─────────┬─────┐
  │  書架A   │ 窓  │
  ├─────────┤     │
  │  机（アルス）  │     │
  │  机（リリア）  │     │
  └─────────┴─────┘
  入口は左下。リリアは窓を背にして座る。
```

| 規則 | 内容 |
|---|---|
| 値の形 | 継続行（2 スペース以上インデント、§5.0.5）で複数行を書ける |
| 外部ファイル | 値が `./` または `assets/` で始まる相対パスのとき、そのテキストファイルを読み込んで表示する。プロジェクト外のパスは **E062** |
| `space-mode: ascii` | **等幅フォント・折り返しなし・整形なし** で表示（MUST）。横スクロールを許す |
| `space-mode: text` | 通常の本文フォントで折り返して表示（既定） |
| 継承 | `when` と同じく上位から継承。場面が独自の `space` を持てば上書き |
| 検査 | novnow は **内容を一切解釈しない**。図形の妥当性も位置矛盾も検出しない（MUST） |
| 表示 | 参照ペインの「空間」節（§9.5.3）。長い場合は既定で折りたたむ |

**非目標**: 間取りエディタ・ドラッグ操作・画像化は v0.1.0 では作らない（付録 E F8 参照）。

#### 5.3.7 あらすじ `blurb:`

**読者に見せる文章** を、本文とは別に章単位で持つ。

| 書き方 | 用途 |
|---|---|
| `plots/01.cnov` の `@01-00` ブロックに `blurb:` | 1 章のあらすじ（短い。数行） |
| `plots/all.cnov` の前文に `blurb:` | 作品全体のあらすじ（投稿サイトの紹介文） |
| `contents/01-00.cnov` | あらすじを本文として書く場合（長いとき） |

```
@01-00 あらすじ
summary: 1 章のあらすじ。
blurb: 古代錬金術に憑かれた少年アルスは、学院の地下に眠る魔導具「星屑の時計」の
  設計図を手に入れる。幼馴染のリリアは呆れながらも、その図面の美しさに惹かれていく。
;
```

- `blurb` は **本文文字数に含めない**（MUST）。進捗・統計の対象外。
- エクスポートでは `export.include_blurb = true` のときのみ各章の冒頭に挿入する（§17.2）。
- 診断: 本文が 1 文字以上ある章に `blurb` が無くても警告しない（任意機能、MUST）。
- 読者モード（§17.3）では、章の表紙ページに `blurb` を表示する。

### 5.4 話プロット形式（B 形式）— `plots/AA-BB.cnov`

本文（C 形式）と **1:1 で節が対応** する形式。A 形式とは別物。

#### 5.4.1 文法

```ebnf
episode_plot = [ preamble ] , { scene_block } ;

section_field= field_line ;             (* ";" のあとに書いたものはその節に適用 *)
```

#### 5.4.2 フィールド（B 形式）

| キー | 適用 | 値 | 意味 |
|---|---|---|---|
| `mode` | 場面 / 節 | `'名前:モード[+モード]` の空白区切り | **モード割り当て（指示 6 の中核）** |
| `cast` | 場面 | `'名前 ...` | この場面に居る人物（モード未指定可） |
| `pov` | 場面 / 節 | `'名前` | 視点 |
| `material` | 場面 / 節 | `'M0137[:タイトル]` | 参照資料（§6.6） |
| `check` | 節 | 自由文 | 「この節で絶対に外せないこと」。文体/論理チェックエージェントの判定材料 |
| `length` | 節 | 整数 | 目標字数（既定 `project.toml` の `writing.section_target_chars`） |
| `state` | 節 | `draft`\|`review`\|`fixed` | 確定度 |
| `seed` / `payoff` | 節 | A 形式と同じ | 伏線 |
| `when` | 場面 / 節 | 作中日時式（§5.3.5） | 作中日時（追加仕様 3） |
| `space` / `space-mode` | 場面 / 節 | §5.3.6 | 空間設計メモ（追加仕様 21） |
| `senses` | 場面 / 節 | 五感キーの空白区切り（§5.4.4） | **この節で描写するつもりの感覚**（追加仕様 7） |

| `material` | 場面 / 節 | `'M0137` / `'S0042` | 参照資料。本文側の `^M0137`（§5.2.4）と対になる |
| `note` | 任意 | 自由文 | メモ |

**制約**

- 1 節の `mode` に同じキャラを 2 回書くのは **E005**。1 キャラに 3 つ以上のモード（`A+B+C`）も **E005**。
- `mode` で指定したモードがそのキャラに存在しなければ **E003**、範囲外なら **E004**（§6.4）。
- 節数が対応する本文の節数と食い違う場合は **W030**（プロットのみ先行して書くのは正常なので警告に留める）。

#### 5.4.4 五感キー `senses:`

```ebnf
senses_value = sense_key , { ws , sense_key } ;
sense_key    = "sight" | "hearing" | "smell" | "taste" | "touch"
             | "視覚" | "聴覚" | "嗅覚" | "味覚" | "触覚" ;
```

| 規則 | 内容 |
|---|---|
| 意味 | 「この節で描写する **つもり** の感覚」。宣言であって、実際の描写の検出ではない |
| 既定 | 書かない場合、その節は五感チェックの対象外（**診断を出さない**、MUST） |
| 英日 | 5 種のみ。どちらの表記でも同じ値。表示は UI 言語に合わせる |
| 集計 | §10.9.3 の文体タブで、章ごとに「宣言された感覚」の出現比率を帯グラフで出す |
| 診断 | 連続 5 節以上にわたって `sight` 系のみが宣言されていれば **W083**（§7.2） |
| 参照ペイン | §9.5.2 の「五感」節に、現在の節の宣言を常時表示。宣言が無ければ節ごと非表示 |

**重要な非目標（MUST）**: novnow は本文を解析して「実際に嗅覚描写があるか」を判定しない。
形態素解析や意味解析は v0.1.0 では行わない（付録 D.2 U-5 を参照）。この機能は
**作者自身のチェックリスト** であり、自動採点ではない。

```

;
```

#### 5.4.5 構造化挿絵指示 `illustration:`

`! ` 行（§5.2.5）が本文中の素早いメモなのに対し、`illustration:` は **プロット側の正式な発注情報**。

```
@01-04-02 図書室の攻防
;
illustration: 見開き / リリアが階段を見上げる / 逆光 / 制服は夏服
note: 口絵候補
;
```

- 値は自由文。novnow は `/` 区切り等を解釈しない。
- §10.9 の「挿絵メモ一覧」に `! ` 行と統合して SceneId 順に並べる（出典欄で区別する）。
- エクスポートでは B 形式そのものが出力対象外なので、何もしなくても消える。

### 5.5 `characters.md`

#### 5.5.1 設計方針

- 人間が直接書く情報は MD（読み書きしやすい）。機械が採番・管理する情報は JSON（`materials/index.json` のみ）。
- **曖昧さのない MD** とするため、意味を持つのは次の 4 種類の行だけに限定する:
  1. `# 見出し`（H1 = キャラ、H2 = セクション、H3 = モード）
  2. フィールド行 `key: value`（§5.0.5）
  3. 箇条書き `- ...`
  4. 鉤括弧行 `「...」`（役割語パターン、§5.5.5）
  それ以外の行は、直前のフィールド／セクションに属する自由記述（`note` 相当）として保持される。
- MD ビューアで読めること（GitHub 上で読めること）を MUST とする。

#### 5.5.2 文法

```ebnf
characters_md = [ file_preamble ] , { character } ;
character     = "# " , char_name , eol , { field_line | section } ;
section       = "## " , section_key , eol , section_body ;
section_key   = "modes" | "attributes" | "tone" | "relations" | "notes"
              | "性格" ... (§5.0.6 の別名表に準拠) ;
section_body  = { field_line | bullet | pattern_line | free_line | blank | comment_line } ;
mode_def      = "### " , mode_id , [ ws , mode_label ] , eol , { field_line | pattern_line | free_line } ;
mode_id       = /[A-Za-z][A-Za-z0-9_]{0,15}/ ;
pattern_line  = ws? , "「" , pattern , "」" , { ws? , "「" , pattern , "」" } , eol ;
```

#### 5.5.3 キャラクタ直下のフィールド

| キー | 必須 | 値 | 意味 |
|---|---|---|---|
| `alias` | 任意 | カンマ区切り | 別名。すべて辞書に登録される |
| `reading` | 任意 | 読み | 補完の並べ替えと検索に使う |
| `role` | 推奨 | 自由文 | 物語上の役回り（モード別に上書き可） |
| `default-mode` | 任意 | `mode_expr`（§5.1、最大 2 つ） | 明示が無い節での既定モード（§6.4.3）。3 つ以上は **E005**（§6.4.4）で `mode_id` 1 つから広げた |
| `color` | 任意 | `#RRGGBB` | 参照ペイン・話者注釈の識別色（任意） |
| `tags` | 任意 | カンマ区切り | 検索用 |
| `icon` | 任意 | `assets/` 配下の相対パス | **キャラアイコン**（追加仕様 24、下記） |

**`icon:` の規則**

| 項目 | 規則 |
|---|---|
| 値 | `assets/icons/megumi.png` のような **プロジェクトルートからの相対パス**。絶対パス・`../` は **E062** |
| 形式 | PNG / JPEG のみ。他は W068 を出して無視 |
| 寸法 | 長辺 256px 以下を推奨。超える場合は読み込み時に縮小し **W069** |
| ファイルサイズ | 1 ファイル 256KB 超は読み込まず **W069** |
| 表示箇所 | 参照ペインの配役見出しの左に 16×16、キャラ一覧（§10.4）に 32×32。**本文エディタ内には出さない**（MUST） |
| Web 版 | `assets/` は IndexedDB に入るため動作する。ただし Zip 入出力（§13.4）に含める |
| 欠損 | ファイルが無くてもエラーにしない。アイコン無しで表示し **W070** |
| 非目標 | アイコンの編集・切り抜き・生成はしない（MUST） |

**設計上の位置づけ**: これは「顔を思い出すための備忘」であり、装飾ではない。
P3（ノイズを増やさない）に反しないよう、**表示は常に小さく、文字情報より目立ってはならない**（MUST）。
`icon` を 1 件も定義していないプロジェクトでは、アイコン用の余白を取ってはならない。

#### 5.5.4 `## modes`

- `### <mode_id> <表示名>` ごとに 1 モード。
- モード内フィールド: `range`, `personality`, `emotion`, `role`, `note`、および役割語パターン行。
- **同一 `mode_id` を複数回定義してよい。ただし `range` が重ならないこと**（重なれば **E017**）。
  これにより「章が進むにつれモードの性格が少しずつ変化する」を表現できる。
- `range` 省略時は全範囲（`@00 ..`）。

#### 5.5.5 役割語パターン行

- 1 行に複数パターンを並べてよい。1 パターン = `「` と `」` に囲まれた文字列。
- `## tone` 直下に置けばキャラ共通、`### <mode>` 直下に置けばそのモード専用。
- モード専用パターンがある場合、そのモードが有効な節では **モード専用 ∪ キャラ共通** を使う。
- パターン言語の意味論は §6.5 / 付録 B。

#### 5.5.6 `## relations` と呼称 `address:`

```
## relations
'葵あおい: 魂のパートナー。あおい無しでは他者と円滑に開発できない。
'瀬戸晴香: 技術の師弟関係。「絶対失敗しない設計哲学」を学ぶ。
```
左辺は `'` 参照（解決できなければ **E013**）。

**呼称マトリクス `address:`**

「誰が誰をどう呼ぶか」を定義する。`## relations` の中、または `### <mode>` の中に書く。

```ebnf
address_line = "address:" , ws , target_ref , ws? , ("=>"|"→") , ws? , appellation
               , { ws? , "," , ws? , appellation } , [ ws , "#" , ws , note ] ;
target_ref   = "'" , char_name | "*" ;        (* "*" = 上記以外のすべての相手 *)
appellation  = /[^,#\n]+/ ;                    (* 「あおいちゃん」など。'' は不要 *)
```

```md
## relations
'葵あおい: 魂のパートナー。
address: '葵あおい => あおいちゃん
address: '瀬戸晴香 => 瀬戸先輩, 先輩
address: * => さん付け

### D あおい依存・感傷
address: '葵あおい => あおい, あおいちゃん     # 感情が昂ると呼び捨てになる
```

| 規則 | 内容 |
|---|---|
| 向き | **話者 → 相手**。`# 恩田恵` の下に書いた `address: '葵あおい => あおいちゃん` は「恵があおいを呼ぶとき」 |
| 複数 | カンマ区切りで複数の正当な呼び方を列挙できる。先頭が代表値 |
| モード別 | `### <mode>` 直下に書けばそのモード専用。モード専用があればキャラ共通を **上書き**（和集合ではない、MUST） |
| ワイルドカード | `* =>` は個別指定の無い相手すべてに適用する既定。値が `さん付け` のように説明的な場合は検査の対象外（下記） |
| 解決 | `target_ref` が辞書に無ければ **E013** |
| 範囲 | `range:` を併記すれば期間限定にできる（`### <mode>` の `range` と同じ構文）。関係の変化（他人行儀 → 親しい）を表現する |

**検査規則（W084、§7.2）**

ある台詞行に話者注釈 `@恵` があり、その行の `「…」` の中に **別のキャラの名前または別名が文字列として出現** し、
かつその文字列が `address:` で許可された呼称のいずれにも一致しないとき、**W084** を出す。

- 許可集合 = 「そのキャラのその相手への `address` の値」∪「相手の `# 見出し名` ？いいえ、含めない」。
  **本名をそのまま呼ぶことも、明示的に `address` に列挙されていなければ違反**とする（これが本機能の価値）。
- `address` が 1 件も定義されていないキャラの台詞は **検査しない**（MUST）。段階的導入のため。
- `* =>` の値が既知の接尾辞パターン（`さん付け` / `呼び捨て` / `君付け` / `ちゃん付け`）のときだけ機械的に検査し、
  それ以外の自由文は **説明とみなして検査しない**（MUST）。
- 地の文は検査しない（視点人物の心中表現は呼称と無関係に揺れるため）。

**修正支援**: W084 のクイックフィックスは「正しい呼称に置換」（代表値 1 件）＋「この呼称を `address:` に追加」の 2 択。

#### 5.8.2 `materials/index.json`（スキーマ v1）

```json
{
  "schema_version": 1,
  "next_id": 138,
  "items": [
    {
      "id": "M0137",
      "title": "科学の甲子園 本戦の運営と実技課題",
      "path": "materials/docs/M0137-kagaku-koshien.md",
      "source": { "kind": "url", "url": "https://example.org/report/2026", "accessed_at": "2026-10-01T09:12:00+09:00" },
      "category": "取材",
      "conditions": [
        { "kind": "scope", "value": "@02-03 .. @02-08" },
        { "kind": "ref",   "value": "'科学の甲子園" },
        { "kind": "text",  "value": "大会運営の手順を描写するとき" }
      ],
      "saved_at": "2026-10-01T09:20:33+09:00",
      "updated_at": "2026-10-02T22:10:00+09:00",
      "tags": ["大会", "高校", "運営"],
      "status": "approved",
      "added_by": "human",
      "summary": "本戦の 1 日のタイムテーブルと実技課題の採点基準。",
      "checksum": "sha256:9f2c..."
    }
  ]
}
```

| フィールド | 必須 | 規則 |
|---|---|---|
| `id` | ✔ | `M` または `S` + 4 桁以上のゼロ詰め連番。**単調増加・再利用禁止**（MUST）。接頭辞は下表 |
| `title` | ✔ | 1〜80 字。参照の照合対象（§6.6） |
| `path` | ✔ | プロジェクトルートからの相対パス。`materials/` 配下に限る（外は **E024**） |
| `source` | ✔ | `{"kind":"url","url":...}` / `{"kind":"custom","text":...}` / `{"kind":"search", ...}`（§16.3.1） |
| `category` | ✔ | 自由文字列。既定候補: `取材` `文献` `Web` `画像` `体験` `一次資料` `二次資料` `検索結果` |
| `conditions` | ✔(空配列可) | 「必要になる条件」。`scope`/`ref`/`tag`/`text` の 4 種（§16.4） |
| `saved_at` | ✔ | RFC 3339、タイムゾーン付き |
| `status` | ✔ | `approved` \| `proposed` \| `rejected` |
| `added_by` | ✔ | `human` または `agent:<role>` |
| `summary` | 任意 | ≤ 120 字。参照ペインとコンテキストに入る短文 |
| `checksum` | 任意 | MD 本文の SHA-256。外部編集の検出に使う |

**ID 接頭辞**

| 接頭辞 | 意味 | 作られ方 |
|---|---|---|
| `M` | 通常の資料 | 人間が追加、またはエージェントの提案を承認 |
| `S` | **検索結果の保存**（§16.3.1） | プロジェクト内検索の結果を「資料化」したもの |

- **`M` と `S` は同一の連番空間を共有する**（MUST）。`next_id` は 1 つだけ存在し、
  `M0137` の次に検索結果を作れば `S0138` になる。ID の衝突と、接頭辞変更時の参照切れを避けるため。
- 本文からの引用注釈（§5.2.4）・`material:` フィールド・`'` 参照は、どちらの接頭辞も同じに扱う。
- `S` を `M` に「昇格」させる操作は提供しない（ID は不変、MUST）。種別を変えたいときは `category` を変える。

**ID 採番**: `next_id` を読み、`M%04d` または `S%04d` を発行し、`next_id` をインクリメントして同一トランザクションで保存する（MUST）。
`rejected` にしても ID は回収しない。

**ファイルが JSON としてパースできない**ときは **E025**（§4.3-4・§7）。診断を出したうえで
**空の索引の既定値で続行**し、原文は 1 バイトも書き換えない（MUST）。`path` の **E024** と
`id` の重複の **E008** はパースできた場合の検査で、E025 が出たときは報告しない。

### 5.9 `prompts/*.md`

#### 5.9.1 共通文法

```md
# writer
model-hint: balanced          # fast | balanced | careful（MCP サーバ選択のヒント）
max-chars: 12000              # ContextPacket の上限（§15.4）
temperature: 0.7

## system
あなたは novnow プロジェクトの本文執筆担当です。…

## task
次の節の本文だけを書いてください。
対象: {{scene_id}}
プロット: {{plot_section}}

## output
- 出力は本文のみ。見出し・解説・前置きを書かない。
- 役割語は {{role_language}} に従う。
```

- セクションは `## system` / `## task` / `## output` / `## examples` / `## refuse` の 5 種（固定）。
- `{{variable}}` は **閉じた集合**（§15.5.3）。未知変数は **E031**（保存は可能、実行は不可）。
- プロンプトは **プロジェクト間で共有しない**。`prompts/` はプロジェクト内のみを参照し、ユーザーのホーム等から読み込んではならない（MUST、§13.1）。
- 既定プロンプトは novnow バイナリに埋め込み、`prompts/` 欠落時にファイルとして書き出す（§4.2）。以後の更新は **上書きしない**（ユーザーの編集が正）。
  埋め込み既定からの復元手段は §15.5.4（U-7）。

#### 5.9.2 カスタムロール `prompts/custom/*.md`

既定の 6 役割（+ integrator）に加え、**ユーザーが独自の役割を定義できる**。

```
prompts/custom/weapon-advisor.md
prompts/custom/military-check.md
```

```md
# weapon-advisor
label: 武器考証                     # UI 表示名（省略時はファイル名）
model-hint: careful
max-chars: 8000
context: project outline target materials constraints    # 送るブロックを選ぶ（§15.4）

## system
あなたは近世ヨーロッパの武具に詳しい考証担当です。

## task
次の節の武器・防具の描写に、時代考証上の誤りがないか指摘してください。
対象: {{scene_id}}
本文: {{text_current}}

## output
- 指摘は箇条書き。各項目に「該当箇所の引用」「問題」「代案」を書く。
- 問題がなければ「問題なし」とだけ書く。
```

| 規則 | 内容 |
|---|---|
| ロール名 | ファイル名（拡張子なし）。`/^[a-z][a-z0-9-]{0,31}$/`。違反は **E032** |
| 名前の衝突 | 既定 7 役割と同名は **E033**（上書きは `prompts/<role>.md` 側で行う） |
| 登録 | `project.toml` の `agents.custom_roles` に列挙されたものだけが UI に出る。ファイルがあっても未登録なら **I056** で「登録しますか」と案内 |
| `context:` | §15.4 の 9 ブロックから **部分集合を選ぶ**。省略時は全 9 ブロック。`constraints` と `project` は常に含まれる（外せない、MUST） |
| 出力 | 既定ロールと同じく **委譲レベルに従う**（§15.1.1、原則 A2）。既定 `propose` では必ず `agents/proposals/` に書く。ユーザーが `apply` / `autonomous` を設定すれば本文へ自動適用される |
| 上限 | 1 プロジェクトあたり 16 ロール。超過は **E034** |
| MCP | 既定ロールと同じ MCP 経路を使う（原則 A5、MUST）。カスタムロールのための独自接続は作らない |

**設計意図（README の思想との接続）**: カスタムロールは **役割を増やす** 機能である。
増やした役割に何をどこまで任せるかは、他の役割と同じく **ユーザーが委譲レベルで決める**（P5、§15.1.1）。
既定のうちはどの役割も提案しかしないが、ユーザーが望めばカスタムロールも自律させられる。
`context:` でコンテキストを絞れることは変わらず本質であり、「何を渡さないか」を決める装置としても提供する。

#### 5.9.5 参考例展開変数 `{{examples}}`〔状態: 実装完了〕

- 閉じた変数集合に `{{examples}}` を追加する。タスク起票時に参考例（お手本）として指定された章・話・場面・節の本文またはプロットがここに展開される。未指定時は空文字列に展開される。

### 5.10 `agents/` のファイル形式

#### 5.10.1 タスク `agents/tasks/T0042.md`

```md
# T0042
role: writer
scope: @01-04-02-03
intent: 初稿生成
status: ready          # draft | ready | running | review | accepted | rejected | canceled | applied（自動適用済み）
initiator: human       # human | agent（委譲レベル autonomous で自動起動された場合、§15.1.1）
delegation: propose    # 実行時点の委譲レベル（監査用、§15.1.1）
prompt: prompts/writer.md
created_at: 2026-10-09T12:00:00+09:00
updated_at: 2026-10-09T12:03:11+09:00
context-hash: sha256:1a2b...
result: agents/results/T0042.md
server: llm-main
human-comment: リリアの心変わりを台詞で説明しないこと
exclude: materials, history
```

`exclude:` は人間が外したブロック（§15.7.2 のトグル。ブロック名を `,` 区切り。`project` と `constraints` は
外せないので書いても無視する）。値の無いフィールドは書かない。§5.10.1 に無いキーは削除せずに残す。

#### 5.10.2 結果 `agents/results/T0042.md`

```md
# T0042 result
finished_at: 2026-10-09T12:03:40+09:00
model: <MCP サーバが返したモデル識別子>
input_chars: 7412
output_chars: 612
duration_ms: 4210

## output
（LLM の出力そのまま。加工禁止）

## proposal
agents/proposals/P0003.md
```

`## output` は最後の `## proposal`（次の行が `agents/proposals/` のもの）の前まで。20,000 字で切ったときは
`truncated: true` を足す（§15.9）。提案を作らなかったときは `## proposal` を書かない。

#### 5.10.3 提案 `agents/proposals/P0003.md`

```md
# P0003
kind: section-text       # section-text | plot-field | material | word | character | idea | note
target: contents/01-04.cnov @01-04-02-03
origin: T0042
status: open             # open | accepted | rejected | superseded | applied（適用済み）
created_at: ...

## before
（現在のテキスト。空なら空）

## after
（提案テキスト）
```
`note` は stylist / logician / integrator の指摘と、本体が空（質問だけ）の出力で、ファイルには適用しない（読むだけ。
採用は「読んだ」の記録になる）。状態を変えたときは `updated_at:`、却下・差し戻しの理由は `comment:`（必須）、
`novnow.section.propose` の添え書きは `note:`、一部採用なら `partial: true` を足す（`after` は提案のまま残す）。
`## before` は最初の `## after` まで、`## after` はファイルの終わりまで（本文に `## ` の行があってもよい）。
MCP のツールから作られた提案の `origin` は `mcp`（`novnow.section.write` / `novnow.plot.write` は `mcp:<role>`）。
採用時は `after` を対象ファイルへ適用し、`status: accepted` に書き換える。委譲レベル `apply` / `autonomous` で
自動適用された場合は `status: applied` に書き換える（§15.1.1）。`applied` の提案はレビュー画面から **差し戻せる**（§15.7.3）。
**提案ファイルは削除しない**（監査証跡、MUST）。

#### 5.10.4 スレッド `agents/threads/TH0007.md`（エージェント間通信）

```md
# TH0007 旧校舎の間取り
scope: @01-04-02
status: open

## msg 001
from: writer
to: researcher
kind: request            # request | deliver | question | reject | note
created_at: ...
approved_by: human | auto  # 人間が中継を承認したか、自律レベルの自動受け渡しか（必須、§15.6）。未承認は pending
body:
  旧校舎 2 階の窓の形式が分かる資料が欲しい。時代設定は 1930 年代相当。

## msg 002
from: researcher
to: writer
kind: deliver
created_at: ...
approved_by: human
refs: 'M0141
body:
  上下げ窓が主流。M0141 に要点を保存した。
```

#### 5.10.5 監査ログ `agents/log/YYYY-MM-DD.jsonl`

1 行 1 イベントの JSON。`{"ts","event","task","role","server","input_chars","output_chars","duration_ms","result_path","error"}`
（値の無いキーは `null`）。提案に関わるイベントには `"proposal"`、`delegation_changed`（`writer: propose -> apply`）・
`chain_hop`（`T0042 -> T0043`）・`limit_stop`（上限のキー）・差し戻しの `reject`（`revert`）には `"detail"` を足す
（値があるときだけ）。日付はイベントの `ts` の日付。
イベント種別（固定）: `run` / `accept` / `reject` / `auto_applied` / `direct_write` / `fixed_overwrite` /
`delegation_changed` / `chain_hop` / `limit_stop`。
**プロンプト本文・出力本文はログに書かない**（結果ファイルを参照する）。API キーや環境変数値は決して書かない（MUST）。

#### 5.10.6 タスクの参考例指定フィールド（`examples:`）〔状態: 実装完了〕

- `agents/tasks/T####.md` のフィールド行に `examples: <範囲式> [<種別>]`（複数指定可。種別は `contents` / `plot` / `both`、省略時は `both`）を追加する。指定された話・節の本文またはプロットが「例」としてコンテキストに組み込まれる。

### 5.11 `agents/mcp.json`

```json
{
  "schema_version": 1,
  "servers": {
    "llm-main": {
      "transport": "stdio",
      "command": "my-llm-mcp",
      "args": ["--profile", "balanced"],
      "env": { "API_KEY": "${NOVNOW_LLM_KEY}" },
      "capabilities": ["sampling"],
      "roles": ["writer", "plotter", "ideator", "stylist", "logician", "integrator"],
      "timeout_ms": 60000
    },
    "web-research": {
      "transport": "stdio",
      "command": "search-mcp",
      "capabilities": ["tools"],
      "allow_tools": ["search", "fetch"],
      "roles": ["researcher"]
    }
  }
}
```

**規則（MUST）**

- `env` の値は `${ENV_NAME}` 形式の参照のみ許可。**リテラルの秘密情報を書くことを novnow 自身は決して行わない**。ユーザーが直書きした場合は W033 で警告する。
- 環境変数が未解決のサーバは無効化し、UI に E030 を出す。
- `transport` は v0.1.0 では `stdio` のみ必須。`http`/`sse` は MAY（v0.1.0 の本体は `stdio` だけを使う）。
- `servers` は**書かれた順**に読む（§15.8.1 の「定義順」）。`roles` の `*` はどの役割にも一致する。
- `capabilities` に `sampling` が無く `tools` があるサーバには、`allow_tools` の先頭のツールを
  `{"system","prompt","role","scope"}` の引数で呼ぶ。
- novnow は LLM プロバイダの SDK を直接組み込まない（MUST）。モデル呼び出しは必ず MCP サーバ経由。

#### 5.11.3 アプリ内 `mcp.json` 編集モーダル〔状態: 実装完了〕

- コマンドパレットおよび `agent` ワークスペースから、`agents/mcp.json` をアプリ内で直接編集・構文検証・保存できる編集モーダルを開くことができる。JSON 構文エラーや未知のトランスポート指定がある場合はモーダル内で即座にエラー箇所を通知する。

### 5.12 フォーマッタ（正規化）仕様

フォーマッタは以下だけを行う（それ以外の整形は禁止、MUST）。

1. 行末の空白削除
2. 改行コードを `project.toml` の `newline` に統一
3. ファイル末尾に改行 1 個
4. 3 行以上連続する空行を 2 行に圧縮
5. `;` 行の前後の空白除去（`  ;  ` → `;`）
6. フィールド行の `key` と `:` の間の空白を除去し、`: ` の後は空白 1 個に統一
7. 全角空白のみの行は空行に変換

**本文の文字（句読点・記号・改行位置）には一切触れない。** 自動整形は保存時ではなく明示操作（コマンドパレット `format`）でのみ実行する。
