本書は公開 Web サイトのページ構成と利用者向け表示の要件を定める。製品本体の仕様は各仕様書を正本とする。

## 21. Web サイト

### 21.1 トップページとコミュニティ導線

- サイトは日本語 (`/ja/`) と英語 (`/en/`) の同等ページを提供する。
- トップページは製品の概要、開始手順、機能一覧、仕様・参照先、コミュニティへの入口を案内する。
- 機能・トラブルシューティングは一覧性を優先したリファレンス形式とし、説明のためだけのカード群にはしない。
- 診断コードから、当該コードの説明ページへ直接遷移できる。実装の全診断コードに対応する。
- 仕様、ガイド、診断説明の正本はリポジトリ内の `docs/` とカタログデータとし、サイト内に独立した重複原稿を作らない。

### 21.2 検証

- トップページには、コントリビュートとスポンサーの案内を掲載する。
- コントリビュート案内は GitHub の課題報告・提案入口へリンクする。
- スポンサー案内はプロジェクトのスポンサー窓口へリンクする。
- 日本語・英語で同じ目的と入口を提供し、画面幅が狭い場合もリンクを操作可能な状態にする。
- 受け入れ条件、開発手順等の詳細は案内文で再掲せず、該当する GitHub / 開発者文書へ委ねる。

### 21.3 受け入れ基準

- `/ja/` と `/en/` の両方でコミュニティ案内が表示される。
- 各リンクが正しい外部窓口へ遷移し、見出し・リンク名は支援技術から識別できる。
- サイトビルドとリンク検証が成功する。
